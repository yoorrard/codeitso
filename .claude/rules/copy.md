# 문장 규칙 (화면 문구·자료 문장·문서)

코드잇소(v5)는 바이브코딩 재료 쇼핑몰이다. 쓰는 사람은 앱을 만들려는 사람이고, 코딩을 몰라도 읽히게 쓴다. 정본은 `docs/review/v5/brief.md`와 `docs/CONCEPT.md`.

## 말투 (v5.1 D119, `scripts/lib/words.ts`가 지킨다)

- **화면 문구는 해요체**('~해요', 토스·카카오처럼): 설명·도움말·상태·알림·오류·빈 상태 ("장바구니가 비었어요.", "복사했어요."). 다체 끝맺음('~다.')은 `npm run words`가 막는다.
- **법 문서(이용약관·개인정보 처리방침·이용 안내)는 합니다체.**
- **상품 설명·용어 풀이(`data/catalog-ko`, `data/glossary.json`)는 사전 글이라 다체.**
- 버튼은 짧은 동사형·명사형: "담기", "빼기", "검색", "복사", "키트 담기", "프롬프트 뽑기".
- 이용자가 자기 AI에게 하는 말(뽑은 프롬프트)은 반말 '~해 줘'.
- 소개 한 줄: "폰트·API·MCP·템플릿까지, 앱 만들 재료를 담아 내 AI에게 건네요."

## 쓰는 말

- **쇼핑몰 말**: 재료·상품·카테고리(대분류)·소분류·장바구니·담기·메모·프롬프트 뽑기·스타터 키트·기획전·인기순·이름순·최근 갱신순. (영수증·계산은 v5.1에서 없앴다)
- **표준 용어·외래어는 그대로**: API, API 키, MCP, 폰트, 템플릿, 프롬프트, 라이선스, 다운로드, 스타, 깃허브, 다크 모드. 어려운 말은 `data/glossary.json`에 풀이가 있으면 드래그 풀이와 `/terms`가 맡는다.
- 상품 이름·설명은 출처 원문 그대로 둔다(번역하거나 다듬지 않는다). 한국어 한 줄이 있으면 그것을 먼저 보인다.
- **쓰지 않는 말**: 버린 v1~v4 세계의 말(기사·목적지·설계도·꾸러미·단계 이름·막힌 곳·교통 비유)은 `scripts/lib/words.ts`가 막는다.

## 쉬운 말

- 한 문장에 한 가지 뜻. 40자를 넘으면 나눌 수 있는지 본다.
- 숫자는 단위와 함께: "상품 131,370개", "1–60번째". 큰 수는 만·억으로 짧게(`formatCount`).
- 번역투를 쓰지 않는다: ~를 통해 → ~로, ~에 대해 → ~을, ~하는 것이 가능하다 → ~할 수 있다, ~되어지다 → ~되다.
- 과장(완벽한, 최고의)·겁주기·탓하기를 쓰지 않는다. 느낌표는 아낀다.

## 자리 표시와 조사

- 이름 뒤 조사는 받침을 따져 고르는 도우미(`src/lib/josa.ts`)를 쓰거나, 조사가 필요 없는 문장으로 쓴다.
- 문구의 자리 표시는 `{{이름}}` 꼴이고 `fill()`(`src/lib/text.ts`)로 채운다.

## 접근성 문장

- 그림 대체 텍스트는 "무엇이 무엇을 하는 그림"으로 한 문장. 장식 그림은 `alt=""`.
- `aria-live` 알림은 화면 글과 같은 말을 짧게: "담았어요: Roboto", "복사했어요."
- 색만으로 뜻을 전하지 않는다.

## 확인

화면 고정 문구는 `src/copy/ko.ts` 한 곳. 코드에 문장을 박지 않는다(품질 바닥선이 막는다). 문구를 바꾸면 `npm run words`.
