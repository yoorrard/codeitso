# 문장 규칙 (화면 문구·자료 문장·문서)

코드쇼퍼를 쓰는 사람은 코딩을 모르는 성인이다. 처음 읽어도 바로 알아듣게 쓴다.

## 말투

- 화면 안내는 기사가 손님을 모시는 **해요체**: "어떤 도구로 만들까요?", "이제 도구를 고를 수 있어요.", "영수증 챙겨 가세요". 합쇼체는 슬로건 두 줄("코드는 몰라도 됩니다. 목적지만 말하세요.", "도착했습니다. 요금은 0원입니다.")과 사이트 슬로건 "어디로 모실까요? 요금은 0원입니다."(홈 <title>·영수증 끝 줄)에만 쓴다 (D64).
- 기사 메시지(모자 배지 원 32와 글만, `docs/CONCEPT.md` 4절)도 해요체. 한 번에 두 문장 이하, 한 문장 40자 안쪽. 느낌표는 쓰지 않는다 (확인 문제 정답만 예외). 기사 메시지는 사건 때만 낸다(막힌 곳이 다 풀림, 도착, 풀이 처음 안내). 단계에 처음 올 때의 안내는 H1 아래 한 줄이 맡는다.
- 버튼은 짧은 동사로 끝낸다: "고르기", "빼기", "다음", "설계도 받으러 출발하기", "도구 고르러 가기", "복사". "~하기 버튼을 클릭하세요" 같은 설명형은 쓰지 않는다.
- 자료 파일의 문장 체는 자리마다 정해져 있다 (`docs/DATA.md`):
  - 안전 지시(`safety.line`, `safetyDefaults`), 설계도 목록(11·12번): "-ㄴ다"체 ("비밀 키는 코드에 넣지 않는다.")
  - 막히기 쉬운 곳(`stuck`), 화면 설명: "-요"체 ("발표 시각이 정해져 있어요.")
  - 설계도 지시문(9·10번 머리, `promptFragment`), AI에게 할 말, `askAI`: 이용자가 자기 AI에게 하는 반말 "~해 줘"체

## 세계관 말과 쉬운 말 (D56·D64)

- **장소·진행·보상은 세계관 말로, 결정·돈·안전·AI에게 넘길 것은 쉬운 말로.** 세계관은 낱말보다 지도·선·색·움직임으로 전한다.
- 세계관 낱말은 이것만 쓴다: 목적지(홈 소개 문장·지도의 빈 터 이름표·영수증 줄에만) · 출발하기(버튼 안) · 도착 · 요금 · 영수증 · 막힌 곳 · 막힘/서행/원활 · 교통 정보 · 통행 불가 · 지름길 · 더 쉬운 길 · 이어서 가기 · 미리 짠 코스 · 모시다.
- 단계 이름은 할 일을 말하는 쉬운 말이다(D64): 내 AI 써 보기(연습, 선택) · 1 만들 앱 정하기 · 2 도구 고르기 · 3 도구끼리 맞춰 보기 · 4 설계도 받기. 단계 줄·상태 한 줄 머리·다음 버튼의 동사·<title>에 같게 쓰고, '-하기' 이름을 조사 붙은 문장에 넣지 않는다("이제 도구를 고를 수 있어요."). 옛 이름(시운전·경유지·점검·들르는 곳·길 찾는 중)과 호출 앱 말(호출·배차·탑승)은 쓰지 않는다. 기능 하나하나는 '고를 것'(필수는 '꼭 고를 것', 선택은 '있으면 좋은 것')과 기능 이름(화면, 저장, 로그인…)으로 부른다.
- '요금'은 코드쇼퍼 이용료(늘 0원)에만 쓴다. 도구에 드는 돈은 '비용'이다.
- 화면 말과 설계도 말은 1:1로 맞춘다: 만들 앱(영수증의 '목적지' 줄) = 만들 것 (목적지), 알아볼 것 = 9. 만들기 전에 알아볼 것, 나중에 붙일 것 = 나중에 붙일 것, 만들면서 볼 용어 = 이 단계에서 볼 용어.
- 쓰지 않는 말(옛 비유: 정류장·첫 수업·인터뷰·장보기·재확인·계산대·장바구니·진열대·레시피·꾸러미·도장·주행 거리·기사님 등)은 `npm run words`(scripts/guard/check-words.ts)가 막는다. 전체 목록과 새 말은 CONCEPT 3절.

## 쉬운 말

- 한 문장에 한 가지 뜻. 40자를 넘으면 나눌 수 있는지 본다.
- 숫자는 단위와 함께: "약 2시간", "하루 10만 건", "10분이면 돼요".
- 굳어진 용어는 그대로 쓴다: API, API 키, 환경 변수, 배포(사전 표제어와 기존 칸 이름·문장에만. 새 v3 화면 문장은 '공개하기', D83·CONCEPT 3.10절), 저장소, 터미널, JSON, CORS. 처음 나오면 한 줄 풀이나 사전 링크를 붙인다.
- 영어를 섞어 말하지 않는다: 체크 → 확인, 클릭 → 누르기, 세팅 → 설정, 리스트 → 목록, 유저 → 이용자, 스텝 → 단계, 오픈 → 열기, 컨펌 → 확인받기.

## 번역투 금지 (고쳐 쓰기 예)

| 쓰지 않는 말 | 고쳐 쓴 말 |
|---|---|
| ~를 통해 | ~로, ~에서 |
| ~에 대해 / ~에 대한 | ~을, ~의 (빼도 되면 뺀다) |
| ~하는 것이 가능합니다 | ~할 수 있어요 |
| ~를 진행합니다 | ~합니다 (무엇을 하는지 바로 말한다) |
| ~되어집니다, ~되어지다 | ~돼요, ~됩니다 |
| ~에 있어서 | ~에서 |
| ~을 가지고 있다 | ~이 있다 |
| 그것은 ~이다 (대명사 주어) | 주어를 이름으로, 또는 빼기 |
| 성공적으로 완료되었습니다 | 다 됐어요 |
| ~하시기 바랍니다 | ~하세요 |

## 쓰지 않는 말

- 과장: 완벽한, 혁신적인, 최고의, 놀라운, 손쉽게(실제로 쉬운지 모를 때).
- 겁주기: 큰일 납니다, 절대 안 됩니다(안전 지시의 '절대 넣지 마' 같은 꼭 필요한 금지는 예외), 위험합니다!!
- 탓하기: "잘못 입력하셨습니다" → "이 칸은 숫자만 넣을 수 있어요".
- 느낌표는 화면 전체에서 아껴 쓴다 (축하 장면 한두 곳).

## 자리 표시와 조사

- `{{project}}` 바로 뒤에 조사를 붙이지 않는다 (받침에 따라 틀린다). `내가 만들려는 것: {{project}}.`처럼 쓴다.
- 화면 문구에서 이름 뒤 조사는 받침을 따져 고르는 도우미(`src/lib/josa.ts`)를 쓰거나, 조사가 필요 없는 문장으로 쓴다.

## 접근성 문장

- 그림 대체 텍스트는 "무엇이 무엇을 하는 그림"으로 한 문장. "이미지", "그림입니다"로 시작하지 않는다. 장식 그림은 `alt=""`.
- `aria-live` 알림은 화면 글과 같은 말을 짧게: "복사했어요.", "급식 API로 정했어요. 1개만 더 고르면 돼요."
- 색만으로 뜻을 전하지 않는다: 막힌 곳은 색 + 그림 + 글 (막힘·서행·원활).

## 확인

- 화면 고정 문구는 `src/copy/ko.ts` 한 곳, 엔진 문장은 `data/templates.json`. 코드에 문장을 박지 않는다.
- 문구를 많이 바꾸면 `ko-copy-editor` 에이전트에게 검토를 맡긴다.
