# /next-task — 작업 하나를 끝까지 (v5, 간소화 2026-10-20)

인자: `$ARGUMENTS`. 비우면 `CLAUDE.md` '지금 상태'의 '다음'과 `docs/TASKS.md` 맨 아래 줄을 본다.

## 1. 계획 (짧게)

- `docs/review/v5/brief.md`의 해당 절과 소유자 요청 원문을 읽는다. 무엇을 할지 3~5줄로 적는다.
- **빠뜨리지 않기:** 같은 갈래의 변형이 있으면 모두 넣는다(예: 학교급마다 따로인 API는 초·중·고·특수 모두). 소유자가 든 예는 예일 뿐이다(brief 7절).

## 2. 구현

- 진열대 계산은 `src/lib/catalog/core.ts`(순수 함수, 시험 먼저), 문구는 `src/copy/ko.ts`(해요체), 색·크기·모션은 `src/styles/tokens.css` 변수만.
- 진열대 자료(`data/catalog/**`)는 손으로 고치지 않는다. 가져오기 스크립트를 고친다.
- 가장 단순한 방법부터. 요청받지 않은 리팩터링·기능을 더하지 않는다.

## 3. 검사 (모두 통과해야 커밋)

1. `npm run check` (토큰·글꼴·바닥선·말·하네스·타입·단위 시험).
2. `npm run build`.
3. 바꾼 흐름의 e2e만: `npx playwright test tests/e2e/<바뀐 흐름>.spec.ts`. 레이아웃·공통 부품을 바꿨으면 전체 `npm run e2e`.
4. 화면을 바꿨으면 390×844·1440×900 스크린샷을 찍어 **직접 본다**(Read). 키보드로 한 번 끝까지 가 본다.
5. 실패하면 원인을 찾아 고친다(`systematic-debugging`). "아마 괜찮다"로 넘기지 않는다.

검토 에이전트는 기본으로 부르지 않는다. 화면을 크게 바꿨을 때만 `a11y-perf-auditor` 하나를 부를 수 있다.

## 4. 기록·커밋·푸시

- 정한 것은 `docs/DECISIONS.md`에 (결정 — 이유 — 틀렸을 때 비용), 사람 몫은 `docs/HUMAN.md`, 진행은 `docs/TASKS.md` 맨 아래 한 줄.
- 커밋 메시지는 한국어, 작업 이름으로 시작. 푸시 전에 `git pull --rebase`로 원격을 받는다. 푸시마다 배포되므로 검사가 통과한 것만 푸시한다.
