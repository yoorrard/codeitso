# /next-task — 작업 하나를 끝까지

인자: `$ARGUMENTS` (작업 번호. 비우면 아래 규칙으로 고른다)

## 0. 고르기

- `docs/TASKS.md`를 읽고, `먼저:`에 적힌 작업이 모두 `[x]`인 것 중 **첫 번째 `[ ]` T 작업**을 고른다.
- T 작업이 사람 일(H)에 막혀 있으면 건너뛰고 다음 T를 고른다. 막힌 이유는 `docs/HUMAN.md`에 이미 있는지 확인하고 없으면 더한다.
- C 작업(자료 채우기)은 T 작업이 막혔거나 모두 끝났을 때 초안까지 한다 (사람 확인 표를 `docs/HUMAN.md`에 남김).

## 1. 이해하고 계획하기

0. 시작 커밋을 적어 둔다: `git rev-parse HEAD` (검토 에이전트에게 `git diff <시작 커밋>..HEAD` 범위로 넘긴다).
1. 작업의 `요구`(R-xx)와 `읽을 것` 문서를 읽는다. 관련 규칙(`.claude/rules/*`)은 파일을 열면 자동으로 붙는다.
2. 무엇을 할지 3~5줄로 적는다 (진행 기록에 그대로 쓸 수 있게). 화면 작업이면 `docs/CONCEPT.md`의 해당 화면(6절)과 대표 장면(7절)을 함께 본다.
3. 화면·모션 설계가 문서에 없으면 `game-ux-designer` 에이전트에게 짧은 연출 명세를 받는다 (예산·동작 줄이기 대응 포함).

## 2. 구현하기

- 엔진 계산은 엔진에서만. 화면은 `evaluate()` 결과를 보여 주기만 한다.
- 색·크기·모션 길이는 `src/styles/tokens.css` 변수만. 문구는 `src/copy/ko.ts`.
- 새 의존성은 꼭 필요할 때만, 이유를 `docs/DECISIONS.md`에.
- 엔진·스크립트는 시험을 먼저 쓰고 구현한다 (`test-driven-development` 스킬).
- 그림(SVG)이 여러 개 필요하면 `svg-illustrator` 에이전트에게 맡기고, 그동안 화면 코드를 짠다.

## 3. 검사하기 (모두 통과해야 다음 단계)

1. `npm run check` → (있으면) `npm test` → `npm run build`.
2. 화면을 바꿨으면 `/visual-qa`: 360·768·1280px 스크린샷, 키보드만으로 흐름, 동작 줄이기, axe. 스크린샷을 직접 열어 본다(Read 도구로 이미지 확인).
3. 실패하면 `systematic-debugging` 스킬 방식으로 원인을 찾고 고친다. "아마 괜찮다"로 넘기지 않는다.

## 4. 전문가 검토 (바뀐 것에 맞는 에이전트만, 한 메시지에서 동시에 부른다)

| 바뀐 것 | 검토 에이전트 |
|---|---|
| `src/lib/engine/`, `data/`, `schemas/`, `data/golden/` | `engine-guardian` |
| 화면 문구, 자료 문장, 문서 | `ko-copy-editor` |
| 화면·컴포넌트·스타일 | `a11y-perf-auditor` |
| 모션·지도 장면·효과음·3D 렌더 | `game-ux-designer` (검토 모드) |
| 꾸러미 문장 틀·상품 지시·개념 카드 (`docs/examples/`가 바뀜) | `reader-tester` (바뀐 예시 파일 하나와 페르소나를 넘긴다) |

검토자에게는 시작 커밋, 작업 번호, 바뀐 라우트를 함께 준다. 받은 지적은 고치기 전에 맞는지 직접 확인한다 (검토자도 틀릴 수 있다). 맞는 것은 고치고, 동의하지 않는 것은 이유를 진행 기록에 한 줄 남긴다. UI 작업은 끝에 `polish` 스킬로 마감 점검을 한 번 한다. 고친 뒤 3을 다시 돈다.

## 5. 기록하고 올리기

1. `docs/TASKS.md`: `[ ]` → `[x]`, 맨 아래 진행 기록에 `YYYY-MM-DD T번호 한 줄 요약 (커밋 해시는 다음 커밋에서 채워도 된다)`.
2. 정한 것은 `docs/DECISIONS.md`에 번호를 이어 적는다. 스스로 정한 것은 제목 끝에 `(자동 결정)`을 붙이고, 본문은 "결정 — 이유 — 틀렸을 때 비용" 세 줄로 쓴다. 사람이 나중에 훑어볼 수 있게.
3. 사람만 할 수 있는 일(계정·돈·법·상표·상품 사실 최종 확인)은 `docs/HUMAN.md`에 더하고 **기다리지 않고** 계속한다.
4. 커밋: 한국어, 작업 번호로 시작. 예: `T08 인터뷰: 질문 섬과 좁혀지는 중 미리 보기`. 작은 커밋 여러 개도 좋다.
5. `git push -u origin <지금 브랜치>` (네트워크 오류면 2·4·8·16초 간격으로 4번까지 다시).

## 결정 원칙 (멈추지 않기)

- **되돌릴 수 있는 결정**(라이브러리 선택, 화면 배치, 문구, 연출, 파일 구조): 문서와 원칙에 가장 맞는 쪽을 스스로 고르고 `(자동 결정)`으로 기록한 뒤 계속한다.
- **문서끼리 어긋날 때**: PRD > UX/ARCHITECTURE/ENGINE > TASKS 순으로 따르고, 어긋난 곳을 고친 뒤 결정 기록을 남긴다.
- **멈추는 경우는 셋뿐**: (1) 돈이 들거나 계정이 필요한 일, (2) 법·약관 판단, (3) 사실을 원문으로 확인할 수 없는데 그 사실 없이는 진행할 수 없는 일. 이때도 `docs/HUMAN.md`에 적고 다른 작업으로 넘어간다.
- 골든 기대값은 이유를 한 줄로 쓸 수 있을 때만 손으로 고친다.
