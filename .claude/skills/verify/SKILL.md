# /verify — 모든 검사 돌리고 정리하기

고치지 않는다. 결과만 정확히 보고한다.

## 순서

1. 있는 명령만 차례로 돌린다 (`package.json`의 scripts를 먼저 읽는다). 앞이 실패해도 뒤를 계속 돌려 전체 그림을 본다.
   1. `npm run check` (자료 검사 + 골든 + 타입 + 토큰 대비)
   2. `npm test` (T03 이후)
   3. `npm run build` (T01 이후)
   4. `npm run e2e` (T20 이후. 오래 걸리면 `--reporter=line`)
   5. `npm run qa:budget` (성능 예산, 있으면)
   6. `npm run validate:release` (정보용. 진열 상품 사람 확인이 남아 있으면 실패하는 것이 정상)
2. 결과를 아래 형식으로 정리한다.

```text
검사 결과 (YYYY-MM-DD HH:mm)
- 통과: …
- 실패: 명령 — 무엇이 왜 실패했는지 한 줄 — 고칠 곳(파일:줄)
- 경고: …
- 참고: 한 번도 켜지지 않은 규칙, 사람 확인이 남은 상품 수 등
다음 할 일: (실패가 있으면 고칠 순서, 없으면 "커밋해도 됩니다")
```

## 지킬 것

- 실패를 "아마 괜찮다"로 넘기지 않는다. 실패는 실패로 적는다.
- 오래 걸리는 명령은 시간 제한을 넉넉히 준다 (빌드·e2e 10분).
- 출력이 길면 실패 부분만 인용한다.
