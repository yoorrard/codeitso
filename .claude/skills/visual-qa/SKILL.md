# /visual-qa — 화면을 눈으로 확인하기

사람이 "360px에서 직접 확인"하던 일을 대신한다. 스크린샷은 저장소에 올리지 않고 `.qa/`에 둔다.

## 순서

1. `npm run build` (실패하면 여기서 멈추고 고친다).
2. `npm run qa:shots -- $ARGUMENTS`
   - `dist/`를 로컬 서버로 띄우고, 라우트마다 360×800, 768×1024, 1280×800 화면과 `prefers-reduced-motion: reduce` 화면을 찍어 `.qa/shots/`에 저장한다.
   - 화면마다 axe 검사 결과(심각·치명 개수)를 `.qa/axe.json`에 남긴다.
   - 가로 스크롤 생김, 44px보다 작은 누르는 곳, 외부 주소 요청, 콘솔 에러를 찾아 `.qa/report.md`에 적는다.
3. `.qa/report.md`를 읽고, **바꾼 화면의 스크린샷은 Read 도구로 직접 열어 본다.** 볼 것:
   - 글자가 잘리거나 겹치지 않는가, 360px에서 한눈에 무엇을 할지 보이는가
   - 주 버튼이 엄지 자리(아래)에 있고 44px 이상인가
   - 지도·렌더·아이콘 그림이 깨지지 않았는가, 색이 토큰과 맞는가
   - 동작 줄이기 화면에서 결과 상태가 바로 보이는가 (중간 상태로 멈춰 있지 않은가)
4. `npm run qa:budget`: 첫 화면 JS 100KB(gzip) 이하, 페이지별 그림·애니메이션 300KB 이하.
5. 키보드 흐름은 e2e(`tests/e2e/keyboard.spec.ts`, T20 이후)로 확인하고, 그 전에는 `qa:shots`가 남기는 탭 순서 목록을 읽는다.
