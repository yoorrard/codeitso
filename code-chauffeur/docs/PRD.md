# 코드쇼퍼 제품 요구사항 (PRD)

이 문서는 사람이 쓴 기획서 「코드쇼퍼 기획서 (완성본)」를 구현 기준으로 옮긴 것이다. 요구사항마다 번호(R-xx)를 붙였고, `docs/TASKS.md`의 작업이 이 번호를 가리킨다. 기획서와 이 문서가 다르면 이 문서를 따르고, 다른 점은 `docs/DECISIONS.md`에 적는다.

## 1. 한 줄 정의

코드쇼퍼(Code Chauffeur)는 바이브코딩 초심자가 질문에 답하고 필요한 재료를 골라 담으면, 자기 AI에 넘길 **설계 꾸러미**와 **대화 카드**, 먼저 알아 둘 **공부할 것**, 직접 확인할 **조사할 것**을 영수증처럼 받아 가는 무료 웹 서비스다.

- 슬로건: "어디로 모실까요? 요금은 0원입니다."
- 소개 한 줄: "코드는 몰라도 됩니다. 목적지만 말하세요."
- 이름 뜻: 코드를 대신 운전해 주는 기사(chauffeur). 한국어 '쇼퍼'는 장 보는 사람(shopper)으로도 읽혀 장보기 흐름과 맞는다.
- 영수증 도장: "코드쇼퍼 · 요금 0원"

## 2. 대상과 성공 기준

- 대상: AI 채팅은 써 봤지만 앱 만들기는 막막한 성인 (교사·직장인·대학생). 학생은 교사 지도 아래 쓴다.
- 성공 기준: 영수증을 받은 사람이 첫 결과물을 실제로 만든다. 1단계는 교사 5명 관찰 시험과, 처음 써 본 10명의 첫 결과물로 확인한다.

## 3. 원칙 (어기면 안 되는 것)

| 번호 | 원칙 |
|---|---|
| R-01 | 사이트는 AI를 부르지 않는다. 판단은 `data/`의 공개된 데이터와 규칙으로만 한다. 이용자만의 아이디어 해석, 개별 에러 해석, 사실 조사는 이용자의 AI에게 넘긴다. |
| R-02 | 운영비는 월 0원으로 시작한다. 정적 사이트 + Cloudflare Workers 무료 플랜 + GitHub Actions. |
| R-03 | 회원가입, 쿠키, 광고, 제휴 링크가 없다. 추천 순위를 돈으로 바꾸지 않는다. |
| R-04 | 진행 상태는 이용자 브라우저에만 둔다. 우리 서버로 보내는 것은 익명 이벤트 횟수뿐이다 (R-60). 방문 통계는 쿠키 없는 Cloudflare Web Analytics만 쓰고(R-61), 공유 상태가 주소에 있는 영수증 화면에는 싣지 않는다. |
| R-05 | 꾸러미에는 사람이 검수한 문장만 넣는다. 색인의 외부 설명문은 넣지 않고 이름·링크·정해진 항목만 담는다 (프롬프트 주입 방지). |
| R-06 | MCP 서버와 비공식 패키지는 추천하지 않는다. 색인에만 두고 주의 표시를 단다. |
| R-07 | 점수 공식과 가중치를 사이트에 공개한다. 가중치는 운영자가 바꾸고, 회귀 검사(골든 사례)를 통과해야 반영한다. |
| R-08 | 화면은 게임처럼 움직이지만, 모션은 지금 위치와 바뀐 것을 알려 주는 데 쓴다. 모션 하나는 1초 안쪽, 공들인 장면도 3초 이하, 모두 건너뛸 수 있고 '동작 줄이기'를 따른다. |
| R-09 | 휴대폰 화면(폭 360px)이 기준이다. 접근성은 WCAG 2.2 AA를 목표로 한다. |
| R-10 | 쉬운 한국어로 쓴다. 번역투를 쓰지 않고, 굳어진 용어(API, API 키, 환경 변수, 배포 등)는 그대로 쓴다. |

하지 않는 것: 코드 생성, 대신 구현, 회원가입, 유료 강의·광고·제휴 링크.

## 4. 이용 흐름

첫 수업(선택) → 인터뷰 → 장보기 → 재확인 → 계산대. 사전은 어느 단계에서든 옆에 띄운다. 첫 화면에는 "만들러 왔어요"(인터뷰)와 "구경하러 왔어요"(진열대) 두 입구가 있다.

### 4.0 첫 수업 (선택)

| 번호 | 요구 |
|---|---|
| R-11 | 설치 없이 AI 채팅에서 웹페이지 한 장을 만들어 보는 10분 체험. 복사할 문장 3개(만들기 → 고치기 → 저장해서 열기)를 차례로 보여 준다. |
| R-12 | '저장해서 열기' 단계에 "PC 권장"을 표시한다. 끝나면 "방금 한 게 바이브코딩"이라는 정리와 함께 인터뷰로 넘어간다. 언제든 건너뛸 수 있다. |

### 4.1 인터뷰

| 번호 | 요구 |
|---|---|
| R-13 | 앞 3문항은 그림 보기로 고정한다: 무엇을 만드나("어디로 모실까요?") → 누가 쓰나 → 어떤 AI로 만드나. |
| R-14 | 나머지는 규칙 분기: 앞의 답에 따라 필요한 질문만 이어진다. 질문과 분기는 `data/questions.json`에 있다. |
| R-15 | 예·아니요 질문의 답은 '네 / 아니요 / 아마도 / 모르겠어요'. '모르겠어요'는 무난한 기본값으로 넘어간다 (개인정보처럼 조심할 것은 '있다'로 본다). |
| R-16 | 진행 중에 '좁혀지는 중' 미리 보기를 보여 준다: 답한 내용 칩, 지금까지 생긴 칸, 어긋나지 않는 레시피. |
| R-17 | 진행 표시("n번째 질문")와 "일단 구경만 할게요" 출구를 둔다. 보통 10~12문항에서 끝난다. |
| R-18 | 마지막 질문은 "만들고 싶은 걸 한 줄로" 자유 입력(선택, 80자). 이름·학교명 같은 개인정보를 쓰지 말라는 안내를 붙이고, 공유 링크에는 넣지 않는다. |
| R-19 | 그림 보기마다 대체 텍스트를 단다. 키보드만으로 답할 수 있다. 앞 질문으로 돌아가 답을 바꿀 수 있다. |

### 4.2 장보기 (맞춤 진열대)

| 번호 | 요구 |
|---|---|
| R-20 | 인터뷰 답으로 정해진 칸(화면, 저장, 로그인, 외부 데이터, 알림, 배포·공유)을 하나씩 채운다. 칸은 규칙이 만든다. |
| R-21 | 칸마다 후보를 점수 순으로 보여 준다. 진열 상품(쉬운 설명 있음)과 색인 상품(원문 정보만)을 나눠 보여 준다. |
| R-22 | 추천 표시는 칸마다 하나만, 기준 점수 이상인 진열 상품에만 붙인다. 추천 옆에 이유를 짧게 보여 주고(예: "분야 일치 · 주제 일치 · 무료"), 2위와의 차이를 한 줄로 비교한다. |
| R-23 | 조건 배지(무료, 초보 추천, 공식, 실시간·자주 갱신)는 추천과 따로 모든 상품에 붙인다. 추천 제외 상품에는 "주의: 직접 확인 필요"를 붙인다. |
| R-24 | 상품 카드는 다섯 가지(이름·한 줄 설명, 이럴 때 써요, 비용, 난이도, 추천 이유)만 먼저 보이고 나머지는 펼쳐서 본다. |
| R-25 | 한 상품이 여러 칸을 맡을 수 있다 (예: 구글 시트 + 앱스 스크립트 = 저장 + 배포·공유). 맡은 칸은 함께 채워진 것으로 보여 준다. |
| R-26 | 칸에 맞는 상품이 없으면 그렇다고 말하고, 재확인에서 "그대로 두고 조사할 것에 추가"를 고를 수 있게 한다. |
| R-27 | "도움이 됐나요" 응답은 집계만 한다 (2단계). |

### 4.3 재확인

| 번호 | 요구 |
|---|---|
| R-28 | 영수증 전에 "이렇게 이해했어요" 요약과 담은 상품을 보여 준다. |
| R-29 | 충돌을 규칙으로 검사한다: 로그인이 필요한데 로그인 상품 없음, 0원인데 유료 상품, 실시간인데 실시간이 아닌 데이터, 개인정보인데 해외 서버에 저장하는 상품, 여럿이 쓰는 앱에 개인정보를 받는데 로그인 없음, 키를 숨길 중간 서버 없음, 필수 칸 빔. 화면 칸은 비워 둔 채 발행할 수 없다. |
| R-30 | 충돌마다 "바꾸기"(장보기로 돌아감)나 "그대로 두고 조사할 것에 추가" 중 하나를 고른다. 모든 충돌을 고치거나 그대로 두어야 영수증을 뽑을 수 있다. |
| R-31 | 1차 난이도 합이 기준(6)을 넘으면 "오늘 가능한 1차 / 나중에 붙일 2차" 나누기를 제안한다. 미룰 수 있는 칸(로그인, 알림)과 같은 칸의 더 쉬운 상품을 엔진이 함께 알려 준다. |
| R-32 | 고른 유형에 코딩 없이 되는 방법이 있으면 한 줄로 알려 준다 (예: 신청서 → 구글 설문지로 충분할 수 있음). |

### 4.4 계산대 (발행)

| 번호 | 요구 |
|---|---|
| R-33 | 네 가지를 발행한다: 텍스트 영수증, 설계 꾸러미(.md), 공부할 것, 대화 카드. 형식은 `docs/RECEIPT.md`. |
| R-34 | 영수증: 품목, 비용 합계(0원), 예상 시간, 난이도, 준비물·공부할 것·조사할 것 개수, 공유 링크, "코드쇼퍼 · 요금 0원" 도장. |
| R-35 | 설계 꾸러미: 12개 항목. 복사 버튼과 .md 내려받기. 코딩 에이전트용 파일 이름(CLAUDE.md, AGENTS.md)으로 저장하는 법을 한 줄로 안내한다. |
| R-36 | 공부할 것: 영수증을 받은 다음에 본다. 시작 전 필수 3개 이하(10분 안쪽) + 단계별 개념. |
| R-37 | 대화 카드 5장(첫 마디, 다음 단계, 확인이 안 될 때, 막혔을 때, 고칠 때)을 카드별로 복사한다. |
| R-38 | 공유 링크로 영수증을 다시 열어 고쳐 발행할 수 있다. 휴대폰에서 받은 영수증을 PC로 보내는 버튼을 둔다. |
| R-39 | 준비물(가입할 계정, 발급할 키)은 승인이 오래 걸리는 것부터, 예상 막힘은 고른 조합에 맞춰 보여 준다. |

### 4.5 공부할 것

| 번호 | 요구 |
|---|---|
| R-40 | 개념 카드: 3분 설명, 그림, 확인 문제 2~3개, "내 AI에게 배우기" 문장(복사). 자주 막히는 개념에는 직접 해 보기 모형을 둔다 (1단계 5개: 환경 변수 입력, API 키 위치, JSON 읽기, 터미널 연습, 배포 따라가기). |
| R-41 | 진행 기록(읽음, 문제 정답)은 브라우저에 저장한다. 건너뛰기는 언제든 된다. |
| R-42 | 개념 카드는 사전과 같은 자료를 쓰고, 검색에 걸리도록 정적 페이지(`/concepts/아이디`)로 만든다. |

### 4.6 사전 (상시 백과사전)

| 번호 | 요구 |
|---|---|
| R-43 | 어느 화면에서든 사전 버튼으로 옆 창(휴대폰은 아래에서 올라오는 창)을 띄운다. |
| R-44 | 검색창 하나로 용어(개념 카드), 에러 안내, 예상 막힘, 상품을 찾는다. 한글은 두 글자 단위로도 찾게 한다. |
| R-45 | 에러 문장을 붙여 넣으면 맞는 에러 안내를 보여 준다. 못 찾으면 "내 AI에게 이렇게 물어보세요" 질문 틀을 준다. 1단계 목표 20개. |

## 7. 지표와 집계

| 번호 | 요구 |
|---|---|
| R-60 | 세는 이벤트는 다섯 개뿐: 인터뷰 시작, 영수증 발행(걸린 시간 구간), 대화 카드 복사(카드 종류), 필수 개념 완료, 확인 문제 응답(정답·오답). 쿠키·IP·기기 정보는 저장하지 않고 날짜별 횟수만 센다. |
| R-61 | 방문 통계는 쿠키 없는 Cloudflare Web Analytics만 쓴다. |

3개월 목표: 영수증 발행률 50% 이상, 영수증까지 중앙값 10분 이하, 첫 마디 카드 복사율 60% 이상, 필수 개념 완료율 40%·정답률 70% 이상.

## 9. 1단계 범위 (문 열기)

첫 수업, 인터뷰(그림 3문항 + 분기), 장보기·재확인, 계산대(텍스트 영수증·설계 꾸러미·공부할 것·대화 카드), 사전(에러 20개), 핵심 모션 4개와 '동작 줄이기' 대응, 분야 분류표 10개, 진열 상품 60~80개(교육 분야 중심), 개념 카드 20장(해 보기 모형 5개), 레시피 5개, 색인 출처 1곳(공공데이터포털), 회귀 검사 20개, 익명 집계.

지금 저장소의 씨앗 자료(상품 19개, 개념 카드 10장, 레시피 5개, 에러 안내 6개, 골든 사례 15개)는 엔진과 화면을 만들기 위한 최소 분량이다. 목표 분량은 `docs/TASKS.md`의 C 작업으로 채운다.

다음 단계로 넘어가는 기준: 교사 5명 관찰 시험을 거친 뒤, 처음 써 본 10명이 영수증으로 첫 결과물을 실제로 만든다.
