## 엔진 (T04 시험 중 찾은 것, 동작은 바꾸지 않았다)

- 중간 서버 기능만 있는 상품(capabilities가 ['proxy']뿐)의 필요 개념이 읽어 둘 용어에는 들어가지만 어떤 진행 단계에도 붙지 않는다 (`checkout.ts` buildSteps). 지금 자료에는 그런 상품이 없다. 생기면 `step.proxy`에 붙이도록 고치고 골든을 더한다.
- ['host','proxy'] 상품(Workers)의 stepHint 없는 개념은 중간 서버 단계가 아니라 배포 칸 단계에 붙는다. 의도인지 정한다.
- 영수증 개수 줄(준비물·읽어 둘 용어·알아볼 것)이 셋 다 두 자리면 36칸을 넘는다 (T24에서 이름이 바뀌어 다시 잰다). 칸 이름 대체 글('로그인 외 1칸')이 11칸을 넘으면 '(나중)' 표시가 잘린다.
- `oneLine`이 자른 끝에 빈칸이 남을 수 있다 (설계도 제목 끝 빈칸).
- `displayWidth`는 그림 문자를 1칸으로 센다. 한 줄 입력에 그림 문자가 들어가면 영수증 줄이 넘칠 수 있다.
- `normalizeSession`은 cart가 배열이 아닐 때를 막지 않는다 (지금은 saved.ts·fromShareState가 먼저 거른다).
- shared 항목은 order가 같은 앞 칸을 '앞선 칸'으로 보지 않는다 (명세와 같음, 지금 자료에는 order가 같은 칸이 없다).
- 나중으로 미룬 칸의 stepHint 개념이 먼저 만들 것의 단계로 옮겨 붙는다 (case-04에서 로그인을 미루면 로그인 개념이 저장 단계로).
- 영수증·코스 카드의 난이도는 합계 점수와 말('5 보통')이라 몇 점 만점인지 알 수 없다 (문장 검토, T14). 도구 줄은 난이도 막대 세 칸 기준이다 (CONCEPT 3.2절). 바꾸려면 `receipt.ts`의 `difficultyText`와 templates.json, ENGINE.md, `npm run examples`를 함께 고친다.
- 이름 순으로 갈리는 동점이 남아 있다 (D55, 고른 도구 없이 답 조합 55,593개를 훑은 2026-10-12 기준). 배포 칸 Cloudflare Workers > Firebase Hosting 18,531개, GitHub Pages > 앱스 스크립트 6,390개, 데이터 칸 국어사전(krdict > opendict) 2,349개, 나이스 급식 > 학사일정·공공데이터포털 > 서울 열린데이터·문화 행사 > 공공데이터포털·공공데이터포털 > 특일 각 1,566개. 배포 칸은 '무엇을 올리나'(정적 화면만 / 키를 숨길 중간 서버도)로 가르는 점수나 질문이 필요하고, 데이터 칸은 교육 주제 '모르겠어요'에 기본 태그가 없는 것(의도)과 교통·공공·문화 분야 안 주제가 없는 것이 원인이다. 무엇이 맞는지 정하고 골든을 더한다. 훑는 스크립트는 `.qa/golden-draft/scan.ts` 모양으로 다시 만들 수 있다.
