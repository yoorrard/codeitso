# 결정 기록

정한 것과 이유를 짧게 남긴다. 새 결정은 아래에 번호를 이어 붙인다. 바뀐 결정은 지우지 말고 "바뀜: Dxx"로 적는다.

## D01 이름은 코드쇼퍼 (Code Chauffeur)
코드를 대신 운전해 주는 기사라는 뜻이고, '쇼퍼'가 장 보는 사람으로도 읽혀 장보기 흐름과 맞는다. '코더'를 넣으면 이용자가 이미 코딩하는 사람처럼 들려 뺐다. 상표·도메인 확인은 H03.

## D02 사이트에는 AI가 없다
운영비 0원과 예측 가능한 추천을 위해 판단은 공개된 데이터와 규칙으로만 한다. 이용자만의 해석과 사실 조사는 이용자의 AI에게 넘긴다 (조사할 것, 대화 카드). 설명문 초안에 AI를 쓸지는 H06.

## D03 Astro 정적 사이트 + Preact 섬
대부분이 콘텐츠 페이지이고, 상태가 있는 화면은 몇 개뿐이다. 서버가 필요 없고, 개념·상품 페이지가 검색에 걸린다. React 대신 Preact를 써서 자바스크립트를 줄인다.

## D04 배포는 Cloudflare Workers 정적 파일 (Pages가 아님, Vercel Pro 팀도 아님)
- 기획서는 Cloudflare Pages였지만, Cloudflare 공식 문서가 새 프로젝트는 Workers로 시작하라고 안내한다 (2026-10 확인). Workers 정적 파일 요청은 무료·무제한이고, 집계용 함수와 D1을 한 프로젝트에 둘 수 있다.
- 기존 Vercel Pro 팀에 올리면 기존 프로젝트와 사용량을 나눠 쓰고, 지출 한도에 자동 정지를 걸면 팀 프로젝트가 함께 멈출 수 있다. Cloudflare는 별도 계정이라 무슨 일이 생겨도 기존 서비스에 영향이 없다.
- 확인한 한도: 정적 파일 요청 무료·무제한, Worker 요청 하루 10만 건, 요청당 CPU 10ms, 버전당 파일 2만 개, 파일당 25MiB, D1 무료 쓰기 하루 10만 행·읽기 500만 행·저장 5GB.
- 출처: developers.cloudflare.com의 Pages 안내, Workers static assets billing and limitations, Workers limits, D1 pricing (2026-10).

## D05 엔진은 Node가 바로 실행하는 TypeScript
`src/lib/engine/`은 지울 수 있는 타입 문법만 쓴다 (enum, namespace 금지, `import type`, `.ts` 확장자 import). 그래서 Node 22.18 이상에서 빌드 없이 `node scripts/*.ts`로 검사가 돌고, 같은 파일을 Astro(Vite)가 그대로 쓴다. 화면을 만들기 전에 엔진·자료·골든 사례를 먼저 완성해 두었다.

## D06 자료는 JSON + 스키마 + 교차 검사 + 골든 사례
판단을 전부 데이터에 맡기므로, 잘못된 자료가 배포되지 않게 막는 것이 품질 관리의 중심이다. 누구나 PR로 고칠 수 있고 이력이 남는다.

## D07 공유 링크는 주소의 # 뒤에, 자유 입력은 넣지 않는다
`#` 뒤는 서버로 가지 않는다. 이용자가 쓴 한 줄에는 개인정보가 섞일 수 있어 링크에서 뺀다.

## D08 집계는 날짜별 이벤트 횟수만
이벤트 다섯 개의 날짜별 횟수만 D1에 쌓는다. IP·쿠키·기기 정보는 저장하지 않는다. 걸린 시간은 구간으로만 보낸다.

## D09 MCP 서버·비공식 패키지·색인 상품은 추천하지 않는다
MCP 서버와 비공식 패키지는 이용자 컴퓨터에서 남의 코드를 실행하게 만들고, 색인 상품은 사람이 검수한 설명이 없다. 그래서 추천하지 않고 주의 배지를 단다.

## D10 추천 기준과 가중치
기준 점수 3, 가중치는 `data/scoring.json`. 정한 이유:
- 분야·주제 일치(+3)가 가장 크다. 목적에 맞는 데이터가 먼저다.
- 고른 주제와 다른 주제의 상품은 −3 (교육과정이 필요한데 급식 API를 추천하지 않게).
- 여럿이 쓰는 앱에 내 기기에 저장하는 상품은 −6 (같이 볼 수 없어 사실상 쓸 수 없음).
- 이미 담은 상품이 앞 칸을 맡고 있고 이 칸도 맡을 수 있으면 +2 (초심자에게 도구 수를 줄이는 쪽을 권함). 담은 그 칸에서는 더하지 않는다. 더하면 담은 상품이 스스로 추천 이유가 되기 때문이다.
- 무료 상품 +2, 0원만 쓰는데 유료 −4.
- 계좌·사업자가 필요한 상품은 −4. 채팅 AI로 만드는 초심자에게 증권사 API가 추천되지 않게 한다 (코딩 에이전트 이용자에게는 실시간이 꼭 필요할 때 기준을 넘는다).
골든 사례 15개로 결과를 고정했다. 바꿀 때는 `docs/ENGINE.md` 8절 절차를 따른다.

## D11 글꼴은 Pretendard + D2Coding, 직접 싣기
둘 다 OFL. 외부 글꼴 서버를 부르지 않아 개인정보와 속도에 좋다.

## D12 1단계 모션은 CSS와 Web Animations API로만
기획서는 영수증 출력처럼 공들일 장면을 Lottie로 만든다고 했지만, 애니메이션 파일을 만들 디자이너가 아직 없고 lottie-web은 무겁다. 1단계는 CSS로 만들고, 컴포넌트 경계를 두어 나중에 Lottie 파일로 바꿔 끼울 수 있게 한다 (BACKLOG).

## D13 인터뷰의 '모르겠어요'는 대체로 더 단순한 쪽, 조심할 것은 '있다'로
저장·로그인·알림·외부 데이터를 모르면 빼고 시작한다 (나중에 붙이기 쉬움). 개인정보는 모르면 받는다고 보고 조사할 것과 안전 지시를 붙인다. 결제는 모르면 없는 것으로 본다 (처음 만드는 앱에서 결제는 드묾).

## D14 키 노출 충돌은 '나만 쓰는 앱'에서는 띄우지 않는다
배포하지 않고 혼자 쓰면 화면 코드의 키가 남에게 드러나지 않는다. 대신 '내 컴퓨터에서만 쓰고, 키는 .env에 두고, 나누기 전에 중간 서버로 옮긴다'는 안전 지시(`safety.local-key`)를 붙인다. 상품의 프롬프트 조각에는 키를 둘 곳을 적지 않고, 상황에 맞는 안전 지시가 붙인다.

## D15 키를 숨길 중간 서버가 있으면 데이터 단계 앞에 '중간 서버 준비' 단계를 넣는다
칸 순서대로만 단계를 만들면 '외부 데이터 붙이기'가 '배포·공유'(중간 서버가 들어 있는 칸)보다 앞에 와서, 한 단계씩 따라 하는 초심자가 키를 화면에 넣게 된다. 그래서 키 노출 위험 상품이 처음 나오는 단계 바로 앞에 `step.proxy` 단계를 넣고, 환경 변수 개념도 그 단계에 붙인다.

## D16 신청서는 응답을 앱 화면에 다시 보여 주지 않는다
로그인 없이 응답 목록 화면을 만들면 주소를 아는 사람 모두가 응답(학생 정보 포함)을 보게 된다. 신청서 유형에서 '모아 보기' 화면을 빼고, 응답은 만든 사람이 저장 공간(예: 구글 시트)에서 직접 본다. 여럿이 쓰는 기록장처럼 화면에 기록을 보여 주는 유형은 개인정보를 받으면서 로그인이 없으면 충돌(`conflict.shared-without-login`)로 알린다.

## D17 공유 상태는 주소에서 바로 지우고, 영수증 화면에는 방문 통계를 싣지 않는다
공유 링크의 `#` 뒤는 서버로 가지 않지만, 화면에서 도는 제3자 스크립트는 주소 전체를 읽을 수 있다. 읽자마자 `history.replaceState`로 지우고, `/receipt`에는 Web Analytics를 싣지 않는다. 영수증 발행 수는 우리 집계(`receipt_issued`)로 센다.

## D18 확인 문제의 정답 위치를 섞어 둔다
화면에서 보기 순서를 섞지 않는다 (채점과 기록이 자료 순서를 쓰므로). 대신 자료에서 정답 위치를 섞고, 한 자리에 60% 넘게 몰리면 자료 검사가 경고한다.

## D19 인터뷰 보기는 버튼으로 만든다
보기를 고르면 바로 다음 질문으로 넘어가는 흐름이라, 라디오 버튼을 쓰면 화살표 키로 보기를 훑기만 해도 화면이 바뀐다 (WCAG 3.2.2 위반). 보기 하나하나를 버튼으로 만들고 누를 때만 넘어간다.

## D20 미리 보기 배포와 정식 배포를 나눈다
사람 확인(C01)이 끝나기 전에도 화면을 실제 주소에서 시험할 수 있게, 개발용 검사만 통과하면 "검토 중인 시험판" 띠와 `noindex`를 붙여 배포한다. 정식 배포는 `npm run validate:release`가 통과해야 한다.

## D21 화면 칸은 비워 둔 채 발행할 수 없다
화면이 없는 꾸러미는 쓸모가 없다. 화면 칸 규칙에 `mustFill: true`를 두어, 그 칸이 빈 충돌은 '그대로 두기'를 고를 수 없게 했다.

## D22 저장소를 루트로 옮기고 자율 개발 하네스를 둔다 (2026-10-12)
- 웹 업로드로 모든 파일이 `code-chauffeur/` 하위 폴더에 들어가 CI·배포·Claude Code 작업 폴더가 맞지 않았다. 내용은 그대로 두고 위치만 루트로 옮겼다.
- 업로드에서 점(.)으로 시작하는 폴더가 빠져 `.claude/rules`와 스킬 세 개(`/next-task`, `/add-product`, `/verify`)가 없었다. 문서에 적힌 내용대로 다시 만들었다.
- 소유자가 개입을 최소로 원해서 `.claude/`에 스킬·전문가 에이전트·훅을, `scripts/guard`·`scripts/qa`에 기계 검사를 두었다. 구성은 `CLAUDE.md`의 '하네스 지도'.

## D23 묻고 기다리지 않고, 정하고 기록하고 계속한다 (2026-10-12, 바뀜: CLAUDE.md '작업 방식')
- 처음 규칙은 "문서끼리 어긋나거나 결정이 필요하면 멈춰서 묻는다"였다. 소유자 요구(개입 최소)와 맞지 않아 바꿨다.
- 되돌릴 수 있는 결정은 스스로 정하고 이 파일에 `(자동 결정)`과 "결정 — 이유 — 틀렸을 때 비용"으로 적는다. 사람만 할 수 있는 일은 `docs/HUMAN.md`에 쌓고 다른 작업을 계속한다.
- 골든 기대값은 여전히 손으로만 고치되, 이유를 한 줄로 쓸 수 있을 때만 고치고 커밋 메시지에 `골든:`을 적는다 (훅이 확인).

## D24 게임 같은 경험을 1단계에 넣는다: 기사님, 도장, 주행 거리, M5~M8, 효과음 (2026-10-12, 바뀜: PRD R-53, UX 5절, BACKLOG)
- 소유자가 "게임을 경험하는 듯한 UX"를 요구하고 기사님 그림을 주었다. 2단계로 미뤘던 마스코트·도장판·효과음·M5~M7을 1단계로 당기고, 홈의 출발 장면(M8)을 더했다.
- 지킬 선은 그대로다: 모션 하나 1초 안쪽, 장면 3초 이하, 누르면 끝, 동작 줄이기 대응, 순위표·벌점·시간 압박 없음. 재미는 진행을 돕는 데만 쓴다.
- 주행 거리와 도장은 저장된 상태에서 계산한다 (D32). 다른 사람과 비교하는 화면은 만들지 않는다.

## D25 모션 기술: CSS·WAAPI·SVG가 기본, 라이브러리는 색종이 하나 (2026-10-12, 바뀜: D12)
- 크기를 직접 재 보고 정했다 (esbuild 최소화 + gzip -9, 2026-10). GSAP 코어 27.6KB(오픈소스 라이선스 아님), Motion 전체 20.4KB, lottie-web 48.8~78.6KB(전체판에 eval), dotLottie WASM 496KB, Rive WASM 315KB, three.js 최소 장면 132KB. 첫 화면 JS 100KB·페이지 그림 300KB 예산에 맞지 않거나 얻는 것이 적다.
- 층: L0 CSS 전환·키프레임·`@starting-style`·`linear()` 스프링·`offset-path`·CSS 3D·문서 간 View Transitions(0KB) → L1 직접 쓴 `src/lib/motion.ts`·`sfx.ts`(약 2KB) → L2 `canvas-confetti`(ISC, 4.3KB, 계산대에서만 지연 로드) → L3 꼭 필요하면 `motion/mini`(3.4KB)나 animejs WAAPI(4.8KB), 이 파일에 기록한 뒤.
- 페이지 전환은 Astro `<ClientRouter />`(약 6KB, 섬 다시 초기화 필요) 대신 `@view-transition { navigation: auto }`. 지원하지 않는 브라우저(2026-10 기준 Firefox)는 그냥 이동한다.
- D12의 "Lottie로 바꿔 끼울 수 있게"는 Lottie를 쓰지 않기로 하면서 없앤다.

## D26 3D는 CSS 3D와 3D 그림 문자로, WebGL은 선택 시험만 (2026-10-12)
- 진짜 3D(three.js 132KB+, react-three-fiber는 Preact와 맞지 않음)는 예산을 넘는다. 원근 도로(M8), 카드 뒤집기(M5), 차 문(M2), 영수증 종이 말림을 CSS 3D로 만들고(0KB), 아이콘은 Fluent Emoji 3D 그림(D27)으로 입체감을 낸다.
- 홈에 진짜 WebGL 장면을 넣는 것은 선택 과제 T16b에서만, `ogl`(Unlicense, 최소 장면 14KB)로 시험한다. 정지 그림이 먼저 보이고, 유휴 시간 뒤 지연 로드하며, 동작 줄이기·데이터 절약·WebGL 없음이면 띄우지 않는다. 예산과 시각 검토를 통과하지 못하면 넣지 않는다.

## D27 아이콘과 그림: Fluent Emoji 3D(MIT) + Phosphor(MIT) + 직접 그린 SVG (2026-10-12)
- 정류장·칸·보상에는 microsoft/fluentui-emoji의 3D PNG(MIT)를 고정 커밋에서 받아 128px webp로 줄여 직접 싣는다 (한 장 약 3~4KB). UI 아이콘은 Phosphor(MIT) SVG를 빌드 때 인라인한다.
- 거른 것: Tossface(형식 변환도 수정본으로 보아 승인 없이 못 씀, 글꼴 조각 하나 0.7~1.4MB), game-icons.net(CC BY 작가별 표기 부담, RPG 느낌), Twemoji(평면, CC BY 표기).
- 기사님 그림은 소유자가 준 것만 쓴다. 벡터로 따기(imagetracerjs 32색 1.1MB, 흰 장갑·금색 손실)와 Rive(플레이어 315KB gzip)는 시험해 보고 버렸다. 추가 자세는 소유자에게 요청했다 (`docs/HUMAN.md` M02).

## D28 효과음: 기본 꺼짐, 소리 파일 없이 합성 (2026-10-12)
- 켜면 그때 합성기(ZzFX MIT 1.2KB 또는 직접 쓴 WebAudio)를 동적 import한다. 소리 파일은 싣지 않는다 (0KB). `AudioContext`는 사용자가 누른 뒤 하나만 만든다.
- 소리만으로 뜻을 전하지 않는다. 설정은 `cc:prefs:v1.sound`에 둔다 (이미 자리가 있었다).

## D29 글꼴 싣는 법: Pretendard 동적 하위 집합, 영수증은 D2Coding에서 고른 글자만 (2026-10-12, D11 보충)

## D36 나만 쓰는 앱이라도 중간 서버 없이 공개 주소에 올리면 충돌로 알린다, 꾸러미를 읽기 시험으로 다듬는다 (2026-10-12, 바뀜: D14 일부)

## D37 글꼴 실제 구성: Pretendard 정적 3굵기 조각, 영수증 글꼴은 고정 문구 글자만 (2026-10-12, 자동 결정, D29 보충)
- 결정: Pretendard는 가변 글꼴 대신 굵기별 정적 동적 하위 집합 400·700·800(조각 276개, 조각 평균 12.3KB)을 싣는다. 영수증 글꼴 `CC Receipt`는 D2Coding Regular·Bold에서 출력 가능한 ASCII·기호와 영수증·칸 이름·전광판의 고정 글자(지금 178자)만 골라 각각 17~18KB로 만든다. 이름이 바뀐 글꼴 이름 표(name)를 스크립트가 직접 다시 쓴다 (OFL 예약 이름 D2Coding을 쓰지 않음). 원본은 태그 VER1.4.0, SHA-256을 스크립트에 고정했다.
- 이유: 가변 글꼴 조각은 평균 31.4KB라, 본문(400)은 많고 제목(800)·버튼(700)은 글자가 적은 우리 화면에서는 정적 조각이 덜 내려받는다. 상품 이름·한 줄 입력처럼 바뀌는 글자는 영수증 글꼴에 없어서 Pretendard로 보이므로, 영수증 화면은 고정 문구·숫자에만 영수증 글꼴을 쓴다 (글자마다 글꼴이 섞이지 않게).
- 틀렸을 때 비용: 낮음. 전광판·영수증 고정 문구를 바꾸면 `npm run check`의 글꼴 글자 검사가 알려 주고, `npm run fonts`로 다시 만든다.

## D38 Pretendard를 가변 글꼴 조각으로, CSS 예산, 그림 자산 실제 구성 (2026-10-12, 자동 결정, 바뀜: D37 Pretendard 부분)
- 결정: Pretendard는 가변 글꼴 동적 하위 집합(`Pretendard Variable`, 굵기 45~920, 조각 92개)을 싣는다. 성능 예산에 '처음 불러오는 CSS gzip 30KB 이하'를 더하고, `<picture>`는 첫 번째 형식(avif)의 가장 큰 후보 하나만 센다. 기사님 그림은 `Mascot` 컴포넌트가 보이는 폭의 1배·2배 avif·webp만 만들고 대체 형식도 webp로 둔다(PNG를 싣지 않음). UI 아이콘은 Phosphor 2.1.1 duotone 한 가지 모양으로 맞추고 `src/lib/icons.ts`에 등록한 것만 빌드 때 넣는다. 3D 그림 문자는 fluentui-emoji 고정 커밋 1ffb34c에서 30개(평균 3.6KB)를 받았다.
- 이유: D37의 정적 3굵기는 글꼴 조각 바이트가 적지만, `@font-face` 276개짜리 글꼴 CSS가 gzip 40KB라 첫 화면 그리기를 막는다. 가변 글꼴은 CSS가 13KB이고 요청 수도 1/3이다. 조각 바이트는 늘지만 `font-display: swap`이라 글자를 먼저 보여 주고 나중에 바뀐다. 처음 오는 이용자(교사가 보낸 링크로 한 번 들어오는 사람)가 대부분이라 첫 방문의 그리기 시작이 더 중요하다.
- 틀렸을 때 비용: 낮음. `scripts/fonts/build-fonts.ts`의 Pretendard 부분만 바꾸면 되돌아간다. 실제 기기 측정(T20)에서 글꼴 바뀜이 거슬리면 대체 글꼴 크기 맞춤(`size-adjust`)을 더한다.

## D40 상태 저장·공유 링크·진행 계산의 실제 구성 (2026-10-12, 자동 결정)
- 결정: 저장은 nanostores 1.5.4 + @nanostores/persistent 1.3.5(합쳐 gzip 약 1.3KB, 섬에서 쓸 @nanostores/preact 1.1.0), 공유 링크 압축은 lz-string 1.5.0(gzip 약 1.7KB)으로 한다. 최신판(nanostores 1.5.5, @nanostores/preact 1.1.1)은 나온 지 일주일이 안 돼 한 판 아래로 고정했다. `store.ts`는 저장만, `saved.ts`는 읽은 값 고르기(부작용 없음), `result.ts`는 `$result`·`commitSession`(자료 전체를 싣는다)으로 나눈다. localStorage에 실제로 써 보고 실패하면 메모리 엔진으로 바꾸고 `$storageOk`를 false로 둔다. 처음 값과 같아지면 키를 지운다 ('기록 지우기'가 진행 기록 키를 실제로 지움. 설정은 남긴다, D41 검토 반영).
- 도장에 필요한 '첫 수업을 끝까지 봄'과 '영수증을 한 번 이상 뽑음'은 Session에도 공부 기록에도 없어 `cc:meta:v1`에 `lessonDone`, `issued`로 둔다. 계산대 도장은 `issued`이면서 지금도 `canIssue`일 때만 (D32: 지금 상태에서 계산).
- 주행 거리 공식: 첫 수업 5, 답한 질문마다 2, 채운 칸마다 5, 재확인 통과 10, 영수증 10, 읽은 개념마다 3, 맞힌 문제마다 1 (km). 칸 하나를 채우는 일이 질문 하나에 답하는 일보다 무겁다는 정도만 반영한 값이다.
- 순서: T05(기본 틀)의 설정 메뉴·전광판·계기판이 저장소와 진행 계산에 기대므로 T06을 먼저 끝냈다.
- 틀렸을 때 비용: 낮음. 공식은 `KM` 한 곳, 저장 모양은 `saved.ts` 한 곳이다. 키 모양을 바꾸면 `v1`을 올린다.

## D41 기본 틀: 머리말은 붙박이가 아니다, 머리말 섬 하나, popover·dialog (2026-10-12, 자동 결정)
- 결정: 머리말(노선 띠 + 전광판 + 계기판 + 설정)은 스크롤하면 올라가고, 아래 막대(주 버튼 + 사전)만 붙박이로 둔다 (화면 높이 480px 이하에서는 아래 막대도 푼다). 머리말은 Preact 섬 하나(`Masthead`, client:load)로 만들고, 빌드 때는 처음 온 사람 기준(빈 진행)으로 그린 뒤 붙고 나서 저장된 진행으로 바꾼다 (`useHydrated`). 설정 메뉴는 HTML `popover`(바깥 누르기·Esc 닫힘), 기록 지우기 확인과 내 여행 기록은 `<dialog>`(showModal: 초점 가두기·Esc), 닫으면 설정 버튼으로 초점을 돌린다. 잠긴 정류장은 `aria-disabled` 버튼으로 두고 누르면 이유를 띠 아래에 보이고 읽어 준다. 사이트 설정의 동작 줄이기는 첫 그림 전에 `<head>`의 작은 인라인 스크립트가 `cc:prefs:v1`을 읽어 붙인다 (읽기만, 저장은 store.ts). 전광판 옆 기사님 얼굴은 정리본에서 머리만 잘라 낸 그림(`chauffeur-face.png`)이다.
- 이유: 360px 휴대폰에서 머리말(약 140px)과 아래 막대를 둘 다 붙이면 화면의 3분의 1을 가리고, 글자를 키우면 내용이 거의 안 보인다 (WCAG 1.4.10). 붙지 않는 머리말은 초점을 가리지 않는다(2.4.11). popover·dialog는 브라우저가 초점·Esc·바깥 누르기를 처리해 직접 짠 코드보다 덜 틀린다.
- 비용: 머리말 섬이 계기판·자물쇠 계산에 자료와 엔진을 함께 실어 모든 페이지가 처음에 약 46KB(gzip)를 받는다 (홈 합계 50.8KB/100KB). 소개·법 페이지까지 이 값을 내는 것이 아까우면 T17에서 머리말을 정적 HTML + 작은 진행 섬으로 나눈다.
- 틀렸을 때 비용: 낮음. 붙박이 여부는 `frame.css` 한 곳이다.
- 검토 반영 (a11y-perf-auditor, P1 4·P2 6·P3 5): 대화 창 안 초점 테두리를 밝은 바탕 색으로, 전광판은 자르지 않고 줄바꿈, 노선 띠 칸을 줄어들 수 있게(글자 200%에서 가로 스크롤 없앰), 아래 막대 높이 토큰을 rem으로(글자를 키우면 함께 커져 초점을 가리지 않음, 풀기 조건도 `max-height: 30em`), 잠긴 정류장 안내는 알림 한 곳으로, 섬이 붙을 때 초점 칸을 되돌림, 설정 창 낮은 화면 스크롤, 머리말은 페이지 전환 때 자리 이동 없음, 마친 정류장에 작은 도장 표시, 머리말 섬은 `client:idle` + 빌드 때 계산한 처음 상태를 넘겨 브라우저 계산 한 번 줄임, 동작 줄이기에서 올림·누름 없음, 여행 기록 창은 제목에 초점, 아래 막대를 이름 붙은 영역으로, 기록 지우기는 설정을 남기고 화면에도 안내, 계기판 이름을 '지나온 정류장'으로.

## D47 검색 색인은 Astro 정적 끝점으로, 사전은 옆 창 섬으로 (2026-10-12, 자동 결정)
- 결정: MiniSearch 7.2.0(MIT)으로 개념·에러·상품·예상 막힘 81개 문서를 색인한다. 색인 파일은 별도 빌드 스크립트 대신 Astro 정적 끝점 `src/pages/search-index.json.ts`가 빌드 때 만든다 (자료와 늘 같이 바뀌고, 저장소에 만들어진 파일을 두지 않는다). `scripts/build-search.ts`는 문서 수·크기·예시 질문 결과를 출력하는 점검용이다. 낱말 나누기(`src/lib/search-tokenize.ts`)는 ARCHITECTURE 7절 그대로이고 색인과 찾기가 같은 함수를 쓴다. 색인(원본 94KB, gzip 21KB)은 사전을 처음 열 때만 불러온다. 사전은 아래 막대 '사전' 링크를 가로채 `<dialog>`로 연다(휴대폰 아래 창, 1024px 이상 오른쪽 창, Esc로 닫고 링크로 초점). 자바스크립트가 없거나 새 탭이면 `/dictionary`. 에러 문장은 검색과 따로 엔진의 `matchErrors`로 맨 위에, 없으면 에러처럼 보일 때만 질문 틀.
- 이유: T15 완성 확인 질문 네 개가 모두 맞는 항목을 맨 위에 올리고(시험으로 고정), 첫 화면 JS를 늘리지 않는다.
- 틀렸을 때 비용: 낮음. 색인 설정은 `SEARCH_OPTIONS` 한 곳이다.
- 더함 (T15 마무리): 진열대 검색창도 같은 색인을 쓴다. 불러오기는 `src/lib/search-client.ts` 한 곳에서 한 번만 하고(사전과 함께 씀), 상품 문서와 상품에 달린 예상 막힘 문서가 맞으면 그 상품을 남긴다. 검색 결과는 분야·기능 거르기와 함께(그리고) 적용한다.

## D48 진열대·상품 상세·레시피 화면 (2026-10-12, 자동 결정)
- 결정: (1) 진열대 코너는 상품의 첫 기능(대표 기능)으로 한 번만 묶는다. 한 상품이 여러 코너에 겹쳐 나오지 않는다. (2) 거르기 섬은 정적 목록을 다시 그리지 않고 `hidden`만 바꾼다. 자바스크립트가 없으면 목록이 모두 보인다. (3) 색인 상품은 맨 아래 '색인에서 찾은 것'에 주의 배지·제공·원문 링크만 두고 상세 페이지를 만들지 않는다. (4) 레시피 카드의 난이도·예상 시간은 빌드 때 레시피 세션으로 `evaluate` → `receiptModel`을 돌린 값이라 영수증과 같다. - 이유: UX 3.8·3.9, 화면은 엔진 결과를 보여 주기만 한다는 원칙, 첫 화면 JS를 늘리지 않는다.

## D49 노선도 차 이동은 새 페이지의 CSS 애니메이션으로, 건너뛰기는 화면 전체에서 (2026-10-12, 자동 결정)
- 결정: (1) M1은 문서 간 View Transitions에 싣지 않는다. 첫 그림 전 스크립트가 같은 사이트에서 링크로 온 경우(`navigation.type`이 `navigate`)만 앞 정류장 번호를 `--from`(홈이면 -1)으로 붙이고, CSS가 차를 `(--here - --from) × 20cqi`만큼 뒤에서 출발시켜 이번 정류장까지 달리게 한다(`--dur-move`). 지나온 길은 막대 하나를 깔고 `clip-path`로 잘라 같은 길이로 칠한다. 뒤로 가기·새로 고침에서는 달리지 않는다. 앞 정류장은 `document.referrer`로만 알아내고 저장하지 않는다. (2) M7(정류장 열림 핀, 마친 정류장 작은 도장, 주행 거리 굴리기)은 머리말 섬이 붙은 뒤 그 화면 안에서 바뀐 것만 연출한다. 처음 읽은 저장 상태는 기준으로만 삼는다. 정류장이 열리면 '○○ 정류장이 열렸어요.'를 알리고 효과음 '딩동'(켠 경우). (3) 모든 장면 건너뛰기: 기본 틀 스크립트가 화면 어디든 누르기 시작(pointerdown, capture)이나 Esc에서 `document.getAnimations()`를 끝 상태로 보낸다. 누른 버튼은 그대로 눌린다. (4) 알림 자리가 하나라 같은 순간의 알림이 덮이던 것을 고쳐, 120ms 안의 알림은 이어 붙여 한 번에 읽힌다(`GATHER_MS`, 시험 있음). (5) 효과음 '드르륵'(영수증 출력)은 아직 쓰지 않는다. 출력 장면은 페이지를 연 직후라 브라우저가 소리를 막는다(사용자 동작 없음).
- 이유: 전환 중에는 화면을 누를 수 없어서 800ms 이동을 전환에 실으면 다음 행동을 기다리게 된다(R-08). 새 페이지의 CSS 애니메이션은 화면이 바로 눌리고, 자바스크립트가 붙기 전에도 돌며, 줄이기 토큰이 0이면 바로 끝 상태다. 기기·사이트 동작 줄이기 두 경우 모두 첫 수업부터 영수증까지 150ms 넘는 애니메이션 없이 흐름이 끝까지 됨을 확인했다(`.qa/reduce-flow.ts`).
- 틀렸을 때 비용: 낮음. 차 이동은 `frame.css`의 '노선 띠의 차 이동' 블록과 기본 틀 스크립트 몇 줄이다.
- 검토 반영 (game-ux-designer, 꼭 2·권함 6): 저장된 진행이 있으면(`html[data-saved]`) 머리말 섬이 붙기 전의 '처음 온 사람' 값(0km·자물쇠·출발 전)을 감췄다가 붙으면 `--dur-fade`로 보인다. 지금 정류장은 늘 링크로 그려 붙기 전후 같은 요소다(도착 핀이 다시 돌지 않음). 핀 톡은 위로 들지 않고 크기만(0.88→1.03→1, `--ease-spring`). 마친 정류장의 작은 도장은 기울지 않는 `mark-in`. 지금 정류장의 작은 도장은 연출하지 않는다(무대의 큰 도장이 먼저). 숫자 굴리기·색종이는 기본 틀이 쏘는 `cc:skip` 신호로 바로 끝난다. '건너뛰기' 버튼 위의 누르기는 버튼이 직접 처리한다(제목으로 초점). 세 칸 이상이면 `--dur-drive`(900ms). 홈·레시피·진열대에서 출발하면 출발점(-1)부터 달린다. 차 기울기는 새 토큰 `--juice-tilt`(3deg, 줄이기 0deg, 토큰 검사가 각도도 본다). 효과음은 150ms 안에 하나만, 더 중요한 소리가 이긴다(`shouldPlay`, 시험 있음). 담기 비행은 새 토큰 `--dur-fly`(550ms) 뒤 칸이 한 번 통통.
- 게임 순간이 없던 화면 (같은 검토): 진열대는 거르기로 새로 진열된 카드 앞 여섯 장이 차례로 뒤집힘(30도, `--dur-fast`/4 간격), 사전은 붙여 넣은 에러 문장에 맞는 안내가 뒤집혀 나오고 '에러 안내를 찾았어요.'를 알림, 공부는 개념 카드에서 다 읽고 돌아오면 그 줄의 '읽음' 표가 뒤집힘(들어온 주소만 읽고 저장하지 않음). 레시피는 출발 뒤 재확인 도착의 M1로 충분하다(화면 안에 더하면 다음 행동을 기다리게 된다).

## D50 익명 집계: wrangler 4.141.0, 이벤트 약속 한 곳, 끝 빗금 없는 주소 (2026-10-12, 자동 결정)
- 결정: (1) `wrangler` 4.141.0(2026-09-25, MIT/Apache-2.0)을 개발 의존성으로 정확히 고정한다. 배포 화면에 들어가지 않으므로 첫 화면 JS·그림 예산과 상관없다 (설치 크기는 workerd 바이너리 포함 약 200MB, 개발 기계에만). `npm audit`의 높음 4건은 모두 개발 도구(wrangler 안의 undici, astro 안의 sharp) 쪽이고 배포물(`--omit=dev`)은 0건이다. (2) 이벤트 다섯 개와 구간·본문 검사·걸린 시간 구간을 `src/lib/event-spec.ts` 하나에 두고 화면과 Worker가 같이 쓴다. T05의 임시 이름(`interview_done`, `pack_copy`, `pack_download`, `share_open`, `receipt_issue`)은 R-60에 없어서 지웠다. - 틀렸을 때 비용: 낮음. 이벤트를 더하려면 PRD R-60과 `event-spec.ts`를 함께 고친다.
