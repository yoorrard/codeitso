# 결정 기록

정한 것과 이유를 짧게 남긴다. 새 결정은 아래에 번호를 이어 붙인다. 바뀐 결정은 지우지 말고 "바뀜: Dxx"로 적는다.

## D01 이름은 코드쇼퍼 (Code Chauffeur)
코드를 대신 운전해 주는 기사라는 뜻이고, '쇼퍼'가 장 보는 사람으로도 읽혀 장보기 흐름과 맞는다. '코더'를 넣으면 이용자가 이미 코딩하는 사람처럼 들려 뺐다. 상표·도메인 확인은 H03.

## D02 사이트에는 AI가 없다
운영비 0원과 예측 가능한 추천을 위해 판단은 공개된 데이터와 규칙으로만 한다. 이용자만의 해석과 사실 조사는 이용자의 AI에게 넘긴다 (조사할 것, 대화 카드). 설명문 초안에 AI를 쓸지는 H06.

## D03 Astro 정적 사이트 + Preact 섬
대부분이 콘텐츠 페이지이고, 상태가 있는 화면은 몇 개뿐이다. 서버가 필요 없고, 개념·상품 페이지가 검색에 걸린다. React 대신 Preact를 써서 자바스크립트를 줄인다.

## D04 배포는 Cloudflare Workers 정적 파일 (Pages가 아님, Vercel Pro 팀도 아님)
- 기획서는 Cloudflare Pages였지만, Cloudflare 공식 문서가 새 프로젝트는 Workers로 시작하라고 안내한다 (2026-10 확인). Workers 정적 파일 요청은 무료·무제한이고, 집계용 함수와 D1을 한 프로젝트에 둘 수 있다.
- 기존 Vercel Pro 팀에 올리면 기존 프로젝트와 사용량을 나눠 쓰고, 지출 한도에 자동 정지를 걸면 팀 프로젝트가 함께 멈출 수 있다. Cloudflare는 별도 계정이라 무슨 일이 생겨도 기존 서비스에 영향이 없다.
- 확인한 한도: 정적 파일 요청 무료·무제한, Worker 요청 하루 10만 건, 요청당 CPU 10ms, 버전당 파일 2만 개, 파일당 25MiB, D1 무료 쓰기 하루 10만 행·읽기 500만 행·저장 5GB.
- 출처: developers.cloudflare.com의 Pages 안내, Workers static assets billing and limitations, Workers limits, D1 pricing (2026-10).

## D05 엔진은 Node가 바로 실행하는 TypeScript
`src/lib/engine/`은 지울 수 있는 타입 문법만 쓴다 (enum, namespace 금지, `import type`, `.ts` 확장자 import). 그래서 Node 22.18 이상에서 빌드 없이 `node scripts/*.ts`로 검사가 돌고, 같은 파일을 Astro(Vite)가 그대로 쓴다. 화면을 만들기 전에 엔진·자료·골든 사례를 먼저 완성해 두었다.

## D06 자료는 JSON + 스키마 + 교차 검사 + 골든 사례
판단을 전부 데이터에 맡기므로, 잘못된 자료가 배포되지 않게 막는 것이 품질 관리의 중심이다. 누구나 PR로 고칠 수 있고 이력이 남는다.

## D07 공유 링크는 주소의 # 뒤에, 자유 입력은 넣지 않는다
`#` 뒤는 서버로 가지 않는다. 이용자가 쓴 한 줄에는 개인정보가 섞일 수 있어 링크에서 뺀다.

## D08 집계는 날짜별 이벤트 횟수만
이벤트 다섯 개의 날짜별 횟수만 D1에 쌓는다. IP·쿠키·기기 정보는 저장하지 않는다. 걸린 시간은 구간으로만 보낸다.

## D09 MCP 서버·비공식 패키지·색인 상품은 추천하지 않는다
MCP 서버와 비공식 패키지는 이용자 컴퓨터에서 남의 코드를 실행하게 만들고, 색인 상품은 사람이 검수한 설명이 없다. 그래서 추천하지 않고 주의 배지를 단다.

## D10 추천 기준과 가중치
기준 점수 3, 가중치는 `data/scoring.json`. 정한 이유:
- 분야·주제 일치(+3)가 가장 크다. 목적에 맞는 데이터가 먼저다.
- 고른 주제와 다른 주제의 상품은 −3 (교육과정이 필요한데 급식 API를 추천하지 않게).
- 여럿이 쓰는 앱에 내 기기에 저장하는 상품은 −6 (같이 볼 수 없어 사실상 쓸 수 없음).
- 이미 담은 상품이 앞 칸을 맡고 있고 이 칸도 맡을 수 있으면 +2 (초심자에게 도구 수를 줄이는 쪽을 권함). 담은 그 칸에서는 더하지 않는다. 더하면 담은 상품이 스스로 추천 이유가 되기 때문이다.
- 무료 상품 +2, 0원만 쓰는데 유료 −4.
- 계좌·사업자가 필요한 상품은 −4. 채팅 AI로 만드는 초심자에게 증권사 API가 추천되지 않게 한다 (코딩 에이전트 이용자에게는 실시간이 꼭 필요할 때 기준을 넘는다).
골든 사례 15개로 결과를 고정했다. 바꿀 때는 `docs/ENGINE.md` 8절 절차를 따른다.

## D11 글꼴은 Pretendard + D2Coding, 직접 싣기
둘 다 OFL. 외부 글꼴 서버를 부르지 않아 개인정보와 속도에 좋다.

## D12 1단계 모션은 CSS와 Web Animations API로만
기획서는 영수증 출력처럼 공들일 장면을 Lottie로 만든다고 했지만, 애니메이션 파일을 만들 디자이너가 아직 없고 lottie-web은 무겁다. 1단계는 CSS로 만들고, 컴포넌트 경계를 두어 나중에 Lottie 파일로 바꿔 끼울 수 있게 한다 (BACKLOG).

## D13 인터뷰의 '모르겠어요'는 대체로 더 단순한 쪽, 조심할 것은 '있다'로
저장·로그인·알림·외부 데이터를 모르면 빼고 시작한다 (나중에 붙이기 쉬움). 개인정보는 모르면 받는다고 보고 조사할 것과 안전 지시를 붙인다. 결제는 모르면 없는 것으로 본다 (처음 만드는 앱에서 결제는 드묾).

## D14 키 노출 충돌은 '나만 쓰는 앱'에서는 띄우지 않는다
배포하지 않고 혼자 쓰면 화면 코드의 키가 남에게 드러나지 않는다. 대신 '내 컴퓨터에서만 쓰고, 키는 .env에 두고, 나누기 전에 중간 서버로 옮긴다'는 안전 지시(`safety.local-key`)를 붙인다. 상품의 프롬프트 조각에는 키를 둘 곳을 적지 않고, 상황에 맞는 안전 지시가 붙인다.

## D15 키를 숨길 중간 서버가 있으면 데이터 단계 앞에 '중간 서버 준비' 단계를 넣는다
칸 순서대로만 단계를 만들면 '외부 데이터 붙이기'가 '배포·공유'(중간 서버가 들어 있는 칸)보다 앞에 와서, 한 단계씩 따라 하는 초심자가 키를 화면에 넣게 된다. 그래서 키 노출 위험 상품이 처음 나오는 단계 바로 앞에 `step.proxy` 단계를 넣고, 환경 변수 개념도 그 단계에 붙인다.

## D16 신청서는 응답을 앱 화면에 다시 보여 주지 않는다
로그인 없이 응답 목록 화면을 만들면 주소를 아는 사람 모두가 응답(학생 정보 포함)을 보게 된다. 신청서 유형에서 '모아 보기' 화면을 빼고, 응답은 만든 사람이 저장 공간(예: 구글 시트)에서 직접 본다. 여럿이 쓰는 기록장처럼 화면에 기록을 보여 주는 유형은 개인정보를 받으면서 로그인이 없으면 충돌(`conflict.shared-without-login`)로 알린다.

## D17 공유 상태는 주소에서 바로 지우고, 영수증 화면에는 방문 통계를 싣지 않는다
공유 링크의 `#` 뒤는 서버로 가지 않지만, 화면에서 도는 제3자 스크립트는 주소 전체를 읽을 수 있다. 읽자마자 `history.replaceState`로 지우고, `/receipt`에는 Web Analytics를 싣지 않는다. 영수증 발행 수는 우리 집계(`receipt_issued`)로 센다.

## D18 확인 문제의 정답 위치를 섞어 둔다
화면에서 보기 순서를 섞지 않는다 (채점과 기록이 자료 순서를 쓰므로). 대신 자료에서 정답 위치를 섞고, 한 자리에 60% 넘게 몰리면 자료 검사가 경고한다.

## D19 인터뷰 보기는 버튼으로 만든다
보기를 고르면 바로 다음 질문으로 넘어가는 흐름이라, 라디오 버튼을 쓰면 화살표 키로 보기를 훑기만 해도 화면이 바뀐다 (WCAG 3.2.2 위반). 보기 하나하나를 버튼으로 만들고 누를 때만 넘어간다.

## D20 미리 보기 배포와 정식 배포를 나눈다
사람 확인(C01)이 끝나기 전에도 화면을 실제 주소에서 시험할 수 있게, 개발용 검사만 통과하면 "검토 중인 시험판" 띠와 `noindex`를 붙여 배포한다. 정식 배포는 `npm run validate:release`가 통과해야 한다.

## D21 화면 칸은 비워 둔 채 발행할 수 없다
화면이 없는 꾸러미는 쓸모가 없다. 화면 칸 규칙에 `mustFill: true`를 두어, 그 칸이 빈 충돌은 '그대로 두기'를 고를 수 없게 했다.

## D22 저장소를 루트로 옮기고 자율 개발 하네스를 둔다 (2026-10-12)
- 웹 업로드로 모든 파일이 `code-chauffeur/` 하위 폴더에 들어가 CI·배포·Claude Code 작업 폴더가 맞지 않았다. 내용은 그대로 두고 위치만 루트로 옮겼다.
- 업로드에서 점(.)으로 시작하는 폴더가 빠져 `.claude/rules`와 스킬 세 개(`/next-task`, `/add-product`, `/verify`)가 없었다. 문서에 적힌 내용대로 다시 만들었다.
- 소유자가 개입을 최소로 원해서 `.claude/`에 스킬·전문가 에이전트·훅을, `scripts/guard`·`scripts/qa`에 기계 검사를 두었다. 구성은 `CLAUDE.md`의 '하네스 지도'.

## D23 묻고 기다리지 않고, 정하고 기록하고 계속한다 (2026-10-12, 바뀜: CLAUDE.md '작업 방식')
- 처음 규칙은 "문서끼리 어긋나거나 결정이 필요하면 멈춰서 묻는다"였다. 소유자 요구(개입 최소)와 맞지 않아 바꿨다.
- 되돌릴 수 있는 결정은 스스로 정하고 이 파일에 `(자동 결정)`과 "결정 — 이유 — 틀렸을 때 비용"으로 적는다. 사람만 할 수 있는 일은 `docs/HUMAN.md`에 쌓고 다른 작업을 계속한다.
- 골든 기대값은 여전히 손으로만 고치되, 이유를 한 줄로 쓸 수 있을 때만 고치고 커밋 메시지에 `골든:`을 적는다 (훅이 확인).

## D24 게임 같은 경험을 1단계에 넣는다: 기사님, 도장, 주행 거리, M5~M8, 효과음 (2026-10-12, 바뀜: PRD R-53, UX 5절, BACKLOG)
- 소유자가 "게임을 경험하는 듯한 UX"를 요구하고 기사님 그림을 주었다. 2단계로 미뤘던 마스코트·도장판·효과음·M5~M7을 1단계로 당기고, 홈의 출발 장면(M8)을 더했다.
- 지킬 선은 그대로다: 모션 하나 1초 안쪽, 장면 3초 이하, 누르면 끝, 동작 줄이기 대응, 순위표·벌점·시간 압박 없음. 재미는 진행을 돕는 데만 쓴다.
- 주행 거리와 도장은 저장된 상태에서 계산한다 (D32). 다른 사람과 비교하는 화면은 만들지 않는다.

## D25 모션 기술: CSS·WAAPI·SVG가 기본, 라이브러리는 색종이 하나 (2026-10-12, 바뀜: D12)
- 크기를 직접 재 보고 정했다 (esbuild 최소화 + gzip -9, 2026-10). GSAP 코어 27.6KB(오픈소스 라이선스 아님), Motion 전체 20.4KB, lottie-web 48.8~78.6KB(전체판에 eval), dotLottie WASM 496KB, Rive WASM 315KB, three.js 최소 장면 132KB. 첫 화면 JS 100KB·페이지 그림 300KB 예산에 맞지 않거나 얻는 것이 적다.
- 층: L0 CSS 전환·키프레임·`@starting-style`·`linear()` 스프링·`offset-path`·CSS 3D·문서 간 View Transitions(0KB) → L1 직접 쓴 `src/lib/motion.ts`·`sfx.ts`(약 2KB) → L2 `canvas-confetti`(ISC, 4.3KB, 계산대에서만 지연 로드) → L3 꼭 필요하면 `motion/mini`(3.4KB)나 animejs WAAPI(4.8KB), 이 파일에 기록한 뒤.
- 페이지 전환은 Astro `<ClientRouter />`(약 6KB, 섬 다시 초기화 필요) 대신 `@view-transition { navigation: auto }`. 지원하지 않는 브라우저(2026-10 기준 Firefox)는 그냥 이동한다.
- D12의 "Lottie로 바꿔 끼울 수 있게"는 Lottie를 쓰지 않기로 하면서 없앤다.

## D26 3D는 CSS 3D와 3D 그림 문자로, WebGL은 선택 시험만 (2026-10-12)
- 진짜 3D(three.js 132KB+, react-three-fiber는 Preact와 맞지 않음)는 예산을 넘는다. 원근 도로(M8), 카드 뒤집기(M5), 차 문(M2), 영수증 종이 말림을 CSS 3D로 만들고(0KB), 아이콘은 Fluent Emoji 3D 그림(D27)으로 입체감을 낸다.
- 홈에 진짜 WebGL 장면을 넣는 것은 선택 과제 T16b에서만, `ogl`(Unlicense, 최소 장면 14KB)로 시험한다. 정지 그림이 먼저 보이고, 유휴 시간 뒤 지연 로드하며, 동작 줄이기·데이터 절약·WebGL 없음이면 띄우지 않는다. 예산과 시각 검토를 통과하지 못하면 넣지 않는다.

## D27 아이콘과 그림: Fluent Emoji 3D(MIT) + Phosphor(MIT) + 직접 그린 SVG (2026-10-12)
- 정류장·칸·보상에는 microsoft/fluentui-emoji의 3D PNG(MIT)를 고정 커밋에서 받아 128px webp로 줄여 직접 싣는다 (한 장 약 3~4KB). UI 아이콘은 Phosphor(MIT) SVG를 빌드 때 인라인한다.
- 거른 것: Tossface(형식 변환도 수정본으로 보아 승인 없이 못 씀, 글꼴 조각 하나 0.7~1.4MB), game-icons.net(CC BY 작가별 표기 부담, RPG 느낌), Twemoji(평면, CC BY 표기).
- 기사님 그림은 소유자가 준 것만 쓴다. 벡터로 따기(imagetracerjs 32색 1.1MB, 흰 장갑·금색 손실)와 Rive(플레이어 315KB gzip)는 시험해 보고 버렸다. 추가 자세는 소유자에게 요청했다 (`docs/HUMAN.md` M02).

## D28 효과음: 기본 꺼짐, 소리 파일 없이 합성 (2026-10-12)
- 켜면 그때 합성기(ZzFX MIT 1.2KB 또는 직접 쓴 WebAudio)를 동적 import한다. 소리 파일은 싣지 않는다 (0KB). `AudioContext`는 사용자가 누른 뒤 하나만 만든다.
- 소리만으로 뜻을 전하지 않는다. 설정은 `cc:prefs:v1.sound`에 둔다 (이미 자리가 있었다).

## D29 글꼴 싣는 법: Pretendard 동적 하위 집합, 영수증은 D2Coding에서 고른 글자만 (2026-10-12, D11 보충)
- Pretendard(npm `pretendard`, OFL)의 굵기별 동적 하위 집합(unicode-range 조각 92개, 평균 12.6KB)을 직접 싣는다. 브라우저는 그 페이지에 나온 글자의 조각만 받는다.
- D2Coding 전체 woff2는 1.49MB라 그대로 싣지 않는다. 필요한 글자만 골라 조각으로 나누고, OFL의 예약 이름 때문에 이름을 `CC Receipt`로 바꾼다 (OFL 원문 동봉). 영수증 화면은 엔진의 `receiptModel`로 그리므로 칸 맞춤은 CSS 그리드가 맡고, 고정폭 글꼴은 숫자·기호·고정 글자의 분위기를 낸다.

## D30 동작 줄이기는 "움직임 없음, 짧은 페이드는 남김" (2026-10-12)
- 처음 토큰은 동작 줄이기에서 모든 길이를 0으로 했다. 그러면 바뀐 것을 알려 주는 페이드까지 사라진다. 이동·확대·시차·흔들림·색종이는 없애고, 투명도 전환(`--dur-fade`, 150ms 이하)만 남긴다. 기기 설정과 사이트 설정(`html[data-motion="reduce"]`) 둘 다 같은 규칙.

## D31 색 체계를 기사님 그림에서 가져온다: 남색·금색·지도 종이 (2026-10-12)
- 기사님 제복 남색과 배지 금색을 브랜드 색으로, 바탕은 차가운 지도 종이 색으로 바꾼다 (`docs/DESIGN.md` 3절). 처음 바탕(#fbf8f1 따뜻한 크림)은 생성형 디자인의 흔한 기본값과 겹치고 기사님 그림과도 덜 어울렸다.
- 금색(`--taxi`)은 밝은 바탕에서는 채움으로만, 남색 바탕에서는 글자로도 쓴다 (7.5:1). T02에서 토큰을 바꾸고 대비 검사를 돌린다.

## D32 주행 거리와 도장은 저장된 상태에서 계산한다 (2026-10-12)
- 따로 쌓는 점수로 두면 공유 링크·레시피·지우기와 어긋나고, 같은 일을 되풀이해 늘릴 수 있다. 그래서 `src/lib/progress.ts`가 `Session`·`evaluate` 결과·공부 기록에서 매번 계산한다 (순수 함수, 시험 있음).
- 도장 장면을 처음 한 번만 보이려고 본 도장 목록만 `cc:trip:v1`에 둔다.

## D33 Playwright를 하네스 단계에서 미리 설치하고 1.56.1로 고정한다 (2026-10-12)
- 화면을 사람이 아닌 에이전트가 확인하려면 T07부터 스크린샷·axe가 필요하다 (처음 계획은 T20에서 설치). 컨테이너에 있는 Chromium(빌드 1194)과 맞는 1.56.1로 고정하고, `@axe-core/playwright`가 끌어오는 `playwright-core`도 `overrides`로 같은 판에 묶었다. 브라우저 내려받기 사이트는 컨테이너에서 막혀 있다.

## D34 '나만 쓰는 앱'의 CORS 막힘을 예상 막힘으로 알린다, 상품 지시문에서 키 둘 곳을 뺀다 (2026-10-12)
- 골든 case-15(나만 쓰는 HTML 한 장 + 기상청 API, 중간 서버 없음)는 D14대로 키 노출 충돌이 뜨지 않는다. 하지만 화면에서 바로 부르면 CORS로 막힐 수 있다 (`conflict.key-in-static-page` 문장도 이 점을 말한다). 그래서 같은 조건에 막힘 규칙 `stuck.cors-no-proxy`를 더했다. 충돌이 아니라 막힘이므로 발행은 막지 않는다.
- `safety.local-key`는 ".env 파일"을 말했는데, HTML 한 장과 채팅 AI 이용자에게는 .env가 없다. "코드 한 곳(코딩 에이전트를 쓰면 .env 파일)"으로 넓혔다.
- 구글 앱스 스크립트 지시문이 늘 "데이터는 구글 시트에 저장"이라고 해서, 저장이 없는 급식 페이지 꾸러미가 범위·5번(원본 저장 안 함)과 어긋났다. "저장할 데이터가 있으면"으로 바꿨다. 같은 이유로 앱스 스크립트·Workers 지시문에서 키 둘 곳을 빼고, 상황에 맞는 안전 규칙·막힘 규칙이 붙이게 했다 (DATA.md 4절 원칙). 골든 기대값은 바뀌지 않았고 예시 세 개가 다시 만들어졌다.
