# 코드쇼퍼 제품 요구사항 (PRD)

이 문서는 사람이 쓴 기획서 「코드쇼퍼 기획서 (완성본)」를 구현 기준으로 옮긴 것이다. 요구사항마다 번호(R-xx)를 붙였고, `docs/TASKS.md`의 작업이 이 번호를 가리킨다. 기획서와 이 문서가 다르면 이 문서를 따르고, 다른 점은 `docs/DECISIONS.md`에 적는다.

## 1. 한 줄 정의

코드쇼퍼(Code Chauffeur)는 바이브코딩 초심자가 만들고 싶은 앱(목적지)을 말하고 들르는 곳마다 도구를 고르면, 자기 AI에게 줄 **설계도**, **AI에게 할 말** 다섯 장, 미리 읽어 둘 용어(**읽어 둘 용어**), 직접 확인할 **알아볼 것**을 요금 0원 영수증과 함께 받아 가는 무료 웹 서비스다. 세계관·낱말·화면은 `docs/CONCEPT.md`(D56)를 따른다.

- 슬로건: "어디로 모실까요? 요금은 0원입니다."
- 소개 한 줄: "코드는 몰라도 됩니다. 목적지만 말하세요."
- 이름 뜻: 손님을 모시는 기사(chauffeur). 한국어 '쇼퍼'는 대신 골라 주는 사람(shopper)으로도 읽혀, 경유지마다 도구를 함께 고르는 흐름과 맞는다.
- 영수증 도장: "코드쇼퍼 · 요금 0원"
- 도착 짝 문장: "도착했습니다. 요금은 0원입니다."

## 2. 대상과 성공 기준

- 대상: AI 채팅은 써 봤지만 앱 만들기는 막막한 성인 (교사·직장인·대학생). 학생은 교사 지도 아래 쓴다.
- 성공 기준: 영수증을 받은 사람이 첫 결과물을 실제로 만든다. 1단계는 교사 5명 관찰 시험과, 처음 써 본 10명의 첫 결과물로 확인한다.

## 3. 원칙 (어기면 안 되는 것)

| 번호 | 원칙 |
|---|---|
| R-01 | 사이트는 AI를 부르지 않는다. 판단은 `data/`의 공개된 데이터와 규칙으로만 한다. 이용자만의 아이디어 해석, 개별 에러 해석, 사실 조사는 이용자의 AI에게 넘긴다. |
| R-02 | 운영비는 월 0원으로 시작한다. 정적 사이트 + Cloudflare Workers 무료 플랜 + GitHub Actions. |
| R-03 | 회원가입, 쿠키, 광고, 제휴 링크가 없다. 추천 순위를 돈으로 바꾸지 않는다. |
| R-04 | 진행 상태는 이용자 브라우저에만 둔다. 우리 서버로 보내는 것은 익명 이벤트 횟수뿐이다 (R-60). 방문 통계는 쿠키 없는 Cloudflare Web Analytics만 쓰고(R-61), 영수증 상태가 주소에 있는 도착 화면(`/arrival`)에는 싣지 않는다. |
| R-05 | 설계도에는 사람이 검수한 문장만 넣는다. 색인의 외부 설명문은 넣지 않고 이름·링크·정해진 항목만 담는다 (프롬프트 주입 방지). |
| R-06 | MCP 서버와 비공식 패키지는 추천하지 않는다. 색인에만 두고 주의 표시를 단다. |
| R-07 | 점수 공식과 가중치를 사이트에 공개한다. 가중치는 운영자가 바꾸고, 회귀 검사(골든 사례)를 통과해야 반영한다. |
| R-08 | 화면은 게임처럼 움직이지만, 모션은 지금 위치와 바뀐 것을 알려 주고 진행을 돕는 데 쓴다. 모션 하나는 1초 안쪽, 공들인 장면도 3초 이하, 어느 모션이든 누르면 건너뛰고 '동작 줄이기'(기기·사이트 설정)를 따른다. 재미 때문에 다음 행동을 기다리게 하지 않는다. |
| R-09 | 휴대폰 화면(폭 360px)이 기준이다. 접근성은 WCAG 2.2 AA를 목표로 한다. |
| R-10 | 쉬운 한국어로 쓴다. 번역투를 쓰지 않고, 굳어진 용어(API, API 키, 환경 변수, 배포 등)는 그대로 쓴다. |

하지 않는 것: 코드 생성, 대신 구현, 회원가입, 유료 강의·광고·제휴 링크.

## 4. 이용 흐름

시운전(선택) → 목적지 → 경유지 → 점검 → 도착. 다섯을 묶는 말은 '단계'다 (CONCEPT 2절). 사전은 어느 단계에서든 옆에 띄운다. 첫 화면에는 "목적지 말하기"(목적지)와 "도구 둘러보기"(도구 모음) 두 입구가 있다.

### 4.0 시운전 (선택)

| 번호 | 요구 |
|---|---|
| R-11 | 설치 없이 AI 채팅에서 웹페이지 한 장을 만들어 보는 10분 체험. 복사할 문장 3개(만들기 → 고치기 → 저장해서 열기)를 차례로 보여 준다. |
| R-12 | '저장해서 열기' 연습에 "PC 권장"을 표시한다. 끝나면 "방금 한 게 바이브코딩"이라는 정리와 함께 목적지로 넘어간다. 언제든 건너뛸 수 있다. |

### 4.1 목적지

| 번호 | 요구 |
|---|---|
| R-13 | 앞 3문항은 그림 보기로 고정한다: 무엇을 만드나("어디로 모실까요?") → 누가 쓰나 → 어떤 AI로 만드나. |
| R-14 | 나머지는 규칙 분기: 앞의 답에 따라 필요한 질문만 이어진다. 질문과 분기는 `data/questions.json`에 있다. |
| R-15 | 예·아니요 질문의 답은 '네 / 아니요 / 아마 그럴 거예요 / 모르겠어요'. '아마 그럴 거예요'는 '네'로 본다는 것을 보기 아래 한 줄로 밝힌다. '모르겠어요'는 무난한 기본값으로 넘어간다 (개인정보처럼 조심할 것은 '있다'로 본다). |
| R-16 | 진행 중에 '길 찾는 중' 미리 보기를 보여 준다: 답할 때마다 자라는 지도(답한 내용과 지금까지 생긴 고를 것), 어긋나지 않는 미리 짠 코스. |
| R-17 | 진행 표시("n번째 질문")와 "도구 먼저 둘러볼게요" 출구를 둔다. 보통 10~12문항에서 끝난다. |
| R-18 | 마지막 질문은 "만들고 싶은 걸 한 줄로" 자유 입력(선택, 80자). 이름·학교명 같은 개인정보를 쓰지 말라는 안내를 붙이고, 영수증 링크에는 넣지 않는다. |
| R-19 | 그림 보기마다 대체 텍스트를 단다. 키보드만으로 답할 수 있다. 앞 질문으로 돌아가 답을 바꿀 수 있다. |

### 4.2 경유지 (기능마다 도구 고르기)

| 번호 | 요구 |
|---|---|
| R-20 | 목적지 답으로 정해진 기능(엔진의 칸: 화면, 저장, 로그인, 외부 데이터, 알림, 배포·공유)마다 도구를 하나씩 고른다. 화면에서는 '꼭 고를 것'(필수)과 '있으면 좋은 것'(선택)으로 부른다. 기능은 규칙이 만든다. |
| R-21 | 기능마다 후보 도구를 점수 순으로 보여 준다. 쉬운 설명이 있는 도구(진열 상품, `layer: shelf`)와 원문만 있는 도구(색인 상품, `layer: index`)를 나눠 보여 준다. |
| R-22 | 추천 표시는 기능마다 하나만, 기준 점수 이상인 쉬운 설명이 있는 도구에만 붙인다. 추천 옆에 이유를 짧게 보여 주고(예: "분야 일치 · 주제 일치 · 0원으로 시작"), 다른 후보와의 차이를 한 줄로 비교한다. |
| R-23 | 조건 꼬리표(0원으로 시작, 처음 쓰기 쉬움, 공식, 실시간·자주 갱신)는 추천과 따로 모든 도구에 붙인다. 추천 제외 도구에는 "주의: 직접 확인 필요"를 붙인다. |
| R-24 | 도구 카드는 다섯 가지(이름·한 줄 설명, 이럴 때 써요, 비용, 난이도, 추천 이유)만 먼저 보이고 나머지는 펼쳐서 본다. |
| R-25 | 한 도구가 여러 기능을 맡을 수 있다 (예: 구글 시트 + 앱스 스크립트 = 저장 + 배포·공유). 맡은 기능은 함께 고른 것으로 보여 준다 ("이것도 함께 맡아요"). |
| R-26 | 기능에 맞는 도구가 없으면 그렇다고 말하고, 점검에서 "그대로 가기"('알아볼 것'에 적어 둠)를 고를 수 있게 한다. |
| R-27 | "도움이 됐나요" 응답은 집계만 한다 (2단계). |

### 4.3 점검 (출발 전 점검)

| 번호 | 요구 |
|---|---|
| R-28 | 출발 전에 "이렇게 이해했어요" 요약과 고른 도구를 보여 준다. |
| R-29 | 막힌 곳(엔진의 충돌)을 규칙으로 검사한다: 로그인이 필요한데 로그인 도구 없음, 0원인데 유료 도구, 실시간인데 실시간이 아닌 데이터, 개인정보인데 해외 서버에 저장하는 도구, 여럿이 쓰는 앱에 개인정보를 받는데 로그인 없음, 키를 숨길 중간 서버 없음, 나만 쓰는데 중간 서버 없이 키가 든 화면을 공개 주소에 올림, 꼭 고를 것이 빔. 화면 기능은 비워 둔 채 출발할 수 없다 (통행 불가). 막힌 곳은 교통 정보(막힘·서행·원활)로 보인다. |
| R-30 | 막힌 곳마다 "도구 바꾸기"(경유지로 돌아감)나 "그대로 가기"('알아볼 것'에 적고 서행으로 보임) 중 하나를 고른다. 모든 막힌 곳을 고치거나 그대로 가기로 해야 출발해서 영수증을 받을 수 있다. |
| R-31 | 먼저 만들 것의 난이도 합이 기준(6)을 넘으면 "먼저 만들 것 / 나중에 붙일 것" 나누기를 제안한다. 미룰 수 있는 기능(로그인, 알림)과 같은 기능의 더 쉬운 도구(더 쉬운 길)를 엔진이 함께 알려 준다. |
| R-32 | 고른 앱 종류에 코딩 없이 가는 지름길이 있으면 한 줄로 알려 준다 (예: 신청서 → 구글 설문지로 충분할 수 있음). |

### 4.4 도착 (받아 가는 것)

| 번호 | 요구 |
|---|---|
| R-33 | 네 가지를 건넨다: 텍스트 영수증, 설계도(.md), 읽어 둘 용어, AI에게 할 말. 형식은 `docs/RECEIPT.md`. |
| R-34 | 영수증: 품목, 도구 비용 합계('0원으로 시작' 또는 '유료 포함'), 예상 시간, 난이도, 준비물·읽어 둘 용어·알아볼 것 개수, 영수증 링크, "코드쇼퍼 · 요금 0원" 도장. '요금'은 코드쇼퍼 이용료(늘 0원)에만 쓰고, 도구에 드는 돈은 '비용'이다. |
| R-35 | 설계도: 12개 항목. 복사 버튼과 .md 내려받기(`codechauffeur-plan-YYYYMMDD-HHmm.md`). 코딩 에이전트용 파일 이름(CLAUDE.md, AGENTS.md)으로 저장하는 법을 한 줄로 안내한다. |
| R-36 | 읽어 둘 용어: 영수증을 받은 다음에 본다. 먼저 읽어 둘 용어 3개 이하(10분 안쪽) + 만들면서 볼 용어. |
| R-37 | AI에게 할 말 5장(첫 마디, 다음 단계, 확인이 안 될 때, 막혔을 때, 고칠 때)을 장마다 복사한다. |
| R-38 | 영수증 링크로 영수증을 다시 열어 고쳐 받을 수 있다. 휴대폰에서 받은 영수증을 PC로 보내는 버튼을 둔다. 받은 영수증은 이 브라우저의 '지난 영수증'(`/receipts`, 최대 30장)에서 다시 연다. |
| R-39 | 준비물(가입할 계정, 발급할 키)은 승인이 오래 걸리는 것부터, 막히기 쉬운 곳은 고른 조합에 맞춰 보여 준다. |

### 4.5 읽어 둘 용어 (용어 카드)

| 번호 | 요구 |
|---|---|
| R-40 | 용어 카드: 3분 설명, 그림, 확인 문제 2~3개, "내 AI에게 배우기" 문장(복사). 자주 막히는 용어에는 직접 해 보기 모형을 둔다 (1단계 5개: 환경 변수 입력, API 키 위치, JSON 읽기, 터미널 연습, 배포 따라가기). |
| R-41 | 진행 기록(읽음, 문제 정답)은 브라우저에 저장한다. 건너뛰기는 언제든 된다. |
| R-42 | 용어 카드는 사전과 같은 자료를 쓰고, 검색에 걸리도록 정적 페이지(`/terms/아이디`)로 만든다. 읽어 둘 용어 목록은 `/terms` 맨 위에 둔다. |

### 4.6 사전 (상시 백과사전)

| 번호 | 요구 |
|---|---|
| R-43 | 어느 화면에서든 사전 버튼으로 옆 창(휴대폰은 아래에서 올라오는 창)을 띄운다. |
| R-44 | 검색 칸 하나로 에러 안내('에러가 났을 때'), 용어(용어 카드), 막히기 쉬운 곳, 도구를 찾는다. 한글은 두 글자 단위로도 찾게 한다. |

## 5. 경험 디자인 (게임처럼)

세계관·색·글꼴·그림·화면별 구성·장면은 `docs/CONCEPT.md`(1·5~8절), 피할 것은 `docs/DESIGN.md`, 접근성 확인표와 고정 문구는 `docs/UX.md`, 구현 방법은 `game-motion` 스킬.

| 번호 | 요구 |
|---|---|
| R-50 | 코드쇼퍼 차가 손님을 모시고 다섯 단계(시운전·목적지·경유지·점검·도착)를 가는 '길 지도' 이야기. 답할 때마다 내 앱 지도가 자라고, 경유지에서 도구를 고르면 길이 이어지고, 차가 그 길을 달려 설계도가 놓인 빈 터에 닿는다. 화면 위 단계 줄과 아래 막대의 상태 한 줄이 지금 위치와 남은 일을 보여 준다. 갈 수 있는 단계만 누를 수 있고, 아직 못 가는 단계는 이유를 글로 보인다. |
| R-51 | 1단계 장면 아홉: S1 배차(홈), S2 지도가 자라요, S3 고르면 이어져요, S4 교통 정보, S5 출발 → 도착(대표 장면), S6 영수증 출력과 도장, S7 단계 이동, S8 시운전 한 바퀴, S9 용어 카드 읽음·정답. 깊이는 위에서 본 평면 지도(2.5D)와 미리 구운 3D 렌더로 내고, 실행 중 WebGL은 쓰지 않는다. 자세한 값은 `docs/CONCEPT.md` 7절, 옛 M1~M8과의 짝은 `docs/UX.md` 4절. |
| R-52 | 운전기사가 손님을 모시는 말투 ("어디로 모실까요?", "다음은 경유지예요. 들르는 곳마다 도구를 골라요.", "영수증 챙겨 가세요"). 사람 그림(마스코트)은 쓰지 않는다 (D56). 서비스가 직접 짧은 기사 메시지로 단계에 처음 왔을 때·점검의 막힌 곳이 다 풀렸을 때·도착했을 때 안내한다 (진짜 글이라 화면 낭독기가 읽는다). |
| R-53 | 진행은 단계 줄의 ✓, 자라는 지도, 남은 개수("꼭 고를 것 1개 남음", "막힌 곳 1개")로 보여 준다. 모두 저장된 상태에서 계산하고, 순위표·벌점·시간 압박·다른 사람과 비교는 두지 않는다. 모으는 것은 지난 영수증과 용어 카드 20장(읽음·문제를 다 맞힘)뿐이다. 효과음은 설정에서 켤 수 있고 기본은 꺼짐이며, 소리만으로 뜻을 전하지 않는다. |

## 9. 1단계 범위 (문 열기)

시운전, 목적지(그림 3문항 + 분기), 경유지·점검, 도착(텍스트 영수증·설계도·읽어 둘 용어·AI에게 할 말), 지난 영수증, 사전(에러 20개), 게임 연출(자라는 길 지도·단계 줄·장면 S1~S9·선택 효과음)과 '동작 줄이기' 대응, 낮 지도·밤 지도, 분야 분류표 10개, 진열 상품 60~80개(교육 분야 중심), 용어 카드 20장(해 보기 모형 5개), 미리 짠 코스 5개, 색인 출처 1곳(공공데이터포털), 회귀 검사 20개, 익명 집계. 사람 그림(마스코트)은 쓰지 않는다 (D56). 그림은 평면 SVG 지도, 청사진 선 그림, 미리 구운 렌더(차·빈 터·앱 종류 건물)이고, 렌더를 받기 전에는 청사진 자리 표시로 낸다.

처음 저장소의 씨앗 자료(도구 19개, 용어 카드 10장, 코스 5개, 에러 안내 6개, 골든 사례 15개)는 엔진과 화면을 만들기 위한 최소 분량이었다. 목표 분량은 `docs/TASKS.md`의 C 작업으로 채운다.

다음 단계로 넘어가는 기준: 교사 5명 관찰 시험을 거친 뒤, 처음 써 본 10명이 영수증으로 첫 결과물을 실제로 만든다.

코드쇼퍼 상표(KIPRIS)와 도메인(codechauffeur.com 등) 확인, '학원' 명칭 사용 가능 여부, 운영자(공립학교 교원)의 겸직 신고 필요 여부, 해외 업체(Cloudflare) 서버 이용의 국외 이전 고지 대상 여부, 설명문 초안에 AI를 쓸지, 이미지 생성 AI·Tripo3D로 만든 그림을 공개 사이트에 써도 되는지와 그 그림의 라이선스 (마스코트 그림 항목은 쓰지 않기로 해서 닫음, D56). 모두 `docs/HUMAN.md` 대기열에 있고, 에이전트는 기다리지 않고 다른 작업을 한다.
