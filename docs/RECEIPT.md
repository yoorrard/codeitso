# 4단계(설계도 받기)에서 건네는 것

4단계 설계도 받기(`/arrival`)에서는 네 가지를 건넨다: 영수증, 설계도, 읽어 둘 용어, AI에게 할 말. 모두 엔진(`src/lib/engine/`)이 만들고, 문장은 `data/templates.json`과 상품 카드(화면: 도구)에서 온다. 화면은 엔진 결과를 보여 주고 복사·내려받기만 한다. 알아볼 것은 따로 건네지 않고 설계도 9번과 영수증 개수 줄에 들어 있다.

실제 결과물 예시는 `docs/examples/`에 있다 (`npm run examples`로 다시 만든다). 화면을 만들 때 이 예시와 같은 내용이 나오는지 확인한다. 낱말은 `docs/CONCEPT.md` 3.4절을 따른다. 엔진의 내부 이름(`pack`, `study`, `research`, `conversationCards`)은 그대로다.

| 건네는 것 | 누가 보나 | 함수 | 형식 |
|---|---|---|---|
| 영수증 | 이용자 | `receiptModel` → `renderReceiptText` | 화면: 모델로 그린 종이 / 복사: 고정폭 텍스트 |
| 설계도 (내 AI에게 주는 설계 문서) | 이용자의 AI | `renderPack`, `packFileName` | 마크다운. 복사, `.md` 내려받기 |
| 읽어 둘 용어 | 이용자 | `evaluate().study`, `steps[].concepts` | 설계도 받기의 '용어' 칸과 `/terms` 맨 위 묶음 |
| AI에게 할 말 (대화 카드) | 이용자 → 자기 AI | `conversationCards` | 카드별 복사 |

## 1. 영수증

```text
          코드쇼퍼 영수증
          2026-10-12 14:05
------------------------------------
목적지  우리 학교 급식 안내 페이지
------------------------------------
화면        HTML 파일 한 장      0원
외부 데이터 나이스 급식식단정보  0원
배포·공유   구글 시트 + 앱스 …   0원
------------------------------------
도구 비용 합계          0원으로 시작
예상 시간                   약 2시간
난이도                          보통
준비물                           2개
읽어 둘 용어                     5개
알아볼 것                        0개
------------------------------------
      [ 코드쇼퍼 · 요금 0원 ]
 어디로 모실까요? 요금은 0원입니다.
```

- 폭 36칸(한글 2칸). 화면에서는 `receiptModel`의 값으로 HTML 영수증을 그리고, 복사 버튼은 텍스트를 쓴다.
- 품목: 고른 도구마다 한 줄. 맡은 칸 이름(여럿이면 '화면, 저장', 11칸을 넘으면 '저장 외 1개'), 나중으로 미룬 칸에만 쓰이면 '(나중)'.
- 칸 이름 자리는 기본 12칸이다. '로그인(나중)'처럼 11칸을 넘는 이름이 있으면 그 영수증만 13칸으로 넓히고 도구 이름 자리를 한 칸 줄인다. '(나중)' 표시는 늘 보이게 칸 이름을 먼저 자르고 붙인다.
- 가격: 0원으로 시작할 수 있으면 '0원', 아니면 '유료'.
- **도구 비용 합계**: 모두 0원으로 시작할 수 있으면 '0원으로 시작', 하나라도 유료면 '유료 포함'. '요금'은 코드쇼퍼 이용료(늘 0원)에만 쓴다. 도장 "코드쇼퍼 · 요금 0원"과 맺음말이 그 자리다. 합계를 '요금'이라 부르면 유료 도구를 고른 순간 "요금은 0원입니다"가 거짓이 된다.
- 난이도: 먼저 만들 것의 난이도 합을 말로만 쓴다: 쉬움(3 이하)·보통(6 이하)·어려움. 숫자는 초심자가 읽을 수 없어 찍지 않는다.
- 개수 세 줄: 준비물, 읽어 둘 용어, 알아볼 것. 숫자는 단위와 함께('2개', `receipt.count`). 한 줄에 이으면 36칸을 넘어서 한 줄에 하나씩 둔다.
- 발행 시각은 이용자 기기 시간 `YYYY-MM-DD HH:mm`.
- 화면에서만: 종이 맨 위에 내 길을 찍은 작은 그림, 아래에 [영수증 복사] [영수증 링크 복사] [PC로 보내기]. 복사하는 글에는 그림이 없다.

## 2. 설계도 (.md)

처음 나올 때만 "설계도(내 AI에게 주는 설계 문서)"로 풀어 쓴다. 파일 이름: `codechauffeur-plan-YYYYMMDD-HHmm.md` (`packFileName`, 이용자 기기 시간). 고른 AI에 따라 머리말의 저장 안내가 바뀐다 (채팅 AI: 첨부, 코딩 에이전트: CLAUDE.md 또는 AGENTS.md로 저장).

| 순서 | 제목 | 들어가는 것 | 출처 |
|---|---|---|---|
| 머리말 | {{project}} 설계도 | 만든 방식(AI 없이 규칙과 문장 틀로), 저장 안내, 확인한 때 기준 안내, 발행 시각, 설계도 형식 | `pack.title`, `pack.intro`, `aiTools.*.saveAs` |
| 1 | 만들 것 (목적지) | 한 줄 설명(자유 입력 또는 유형 목표), 종류, 쓰는 사람, 만드는 AI, 고른 답 | `types.*`, `audiences`, `aiTools`, 질문 `chip` |
| 2 | 범위 | 범위 규칙, 먼저 만들 것(유형 기능 + '단계: 도구'. 나중에 붙일 것이 없으면 이름이 '만들 것'), 만들지 않을 것, 나중에 붙일 것 | `pack.scopeRule`, `notBuildRules`, `pack.deferredNote` |
| 3 | 화면 목록 | 유형의 화면과 요소 + 먼저 만들 것의 단계가 더하는 화면(로그인, 알림 설정) | `types.*.screens`, `slotSteps.*.screen` |
| 4 | 기능과 완성 확인 기준 | 기능마다 확인 기준 표 | `types.*.features` |
| 5 | 데이터 구조 초안 | 저장할 것과 항목, 개인정보 최소화, 외부 데이터 다루는 법 | `types.*.dataModel`, `pack.dataLines` |
| 6 | 디자인 지시 | 느낌, 색 코드, 글꼴, 글자 크기, 모서리, 화면 크기, 접근성 | `styles.*`, `devices.*`, `pack.a11yLine` |
| 7 | 쓸 도구 | 표(맡는 일, 도구+링크, 제공, 필요한 자격, 비용, 라이선스, 확인한 때) + 도구별 메모(지시, 막히기 쉬운 곳) + 함께 쓸 때 막히기 쉬운 곳. 나중에만 쓰는 도구에는 '(나중)' | 상품 카드, `stuck` 규칙 |
| 8 | 준비물 | 확인란(`- [ ]`) 목록, 오래 걸리는 것 먼저 | 상품 `prep` |
| 9 | 만들기 전에 알아볼 것 | 알아보기 지시문 + 항목마다 무엇을 확인 / 왜 / 어디서 / 확인됐다고 볼 기준 | 조사 카드, `pack.researchIntro`, `pack.noResearch` |
| 10 | 진행 순서 | 단계 규칙 + 단계마다 쓰는 도구, 완성 확인, 이 단계에서 볼 용어 링크. 키를 숨길 중간 서버가 있으면 데이터 단계 앞에 '중간 서버 준비 (키 숨기기)' | `slotSteps`, `proxyStep`, `pack.stepRule`, `pack.conceptLink` |
| 11 | 안전 기본 지시 | 기본 여섯 줄 + 조건에 맞는 안전 지시 | `safetyDefaults`, `safety` 규칙 |
| 12 | AI 작업 방식 | 한 단계씩, 쉬운 말, 모르면 질문, 확인 방법 알려 주기 | `aiTools.*.workStyle` |
| 맺음 | — | 면책 안내 | `disclaimer` |

화면 말과 설계도 말은 1:1로 맞춘다: 만들 앱(1단계 만들 앱 정하기, 영수증의 '목적지') = 1. 만들 것 (목적지), 알아볼 것 = 9. 만들기 전에 알아볼 것, 나중에 붙일 것 = 2번의 '나중에 붙일 것', 만들면서 볼 용어 = 10번의 '이 단계에서 볼 용어'. '먼저 읽어 둘 용어'(3개 이하)는 화면과 영수증 개수에만 있고 설계도에는 단계마다 나눠 들어간다.

지킬 것:
- 색인 상품(화면: 원문만 있는 도구)은 이름·링크·정해진 항목만 표에 넣고, 메모에는 "9번에서 먼저 알아본다"만 적는다. 외부 설명문을 넣지 않는다 (프롬프트 주입 방지).
- 자유 입력은 한 줄로 정리(줄바꿈 제거)해서 설계도 제목·영수증 목적지(30자)와 1번 한 줄 설명(80자)에 쓴다.
- 용어 링크는 화면의 사이트 첫 주소(`siteRoot()` = `location.origin` + 주소 바탕) + `/terms/아이디`.
- 설계도 문장은 이용자가 자기 AI에게 하는 말이다. 지시문(9, 10번 머리)은 "~해 줘"체, 목록(11, 12번)은 "~한다"체로 쓴다. 머리말과 면책은 "~습니다"체다.

## 3. 읽어 둘 용어

- 먼저 읽어 둘 용어: `study.required` (최대 3개, `level: must`). 화면에 "3개, 10분이면 돼요".
- 만들면서 볼 용어: `steps[].concepts`. 설계도 10번의 같은 단계에 '이 단계에서 볼 용어' 링크로 들어간다.
- 링크는 모두 `/terms/아이디`(용어 카드). `/terms` 맨 위 묶음에도 같은 목록이 나온다.
- 진행 기록(읽음, 맞힌 문제)은 `cc:study:v1`에 저장한다. 먼저 읽어 둘 용어를 모두 읽으면 `required_done` 이벤트를 한 번 보낸다.

## 4. AI에게 할 말 (대화 카드)

| 카드 | 언제 | 문장 |
|---|---|---|
| 첫 마디 | 시작할 때 | {{packRef}}를 읽고 알아볼 것부터 정리해 줘. 구현은 내가 확인한 뒤 1단계부터 시작하자. |
| 다음 단계 | 한 단계를 확인한 뒤 | 방금 단계가 완성 확인 기준대로 됐어. 다음 단계를 진행해 줘. |
| 확인이 안 될 때 | 기준대로 안 될 때 | 완성 확인 기준대로 안 돼. 지금은 (보이는 현상)이야. 무엇이 다른지 같이 찾아 줘. |
| 막혔을 때 | 에러가 날 때 | 이 에러가 났어: (붙여 넣기). 원인을 쉬운 말로 설명하고, 내가 할 일을 순서대로 알려 줘. |
| 고칠 때 | 완성한 뒤 | 설계도의 범위는 지키면서 (바꿀 것)만 고쳐 줘. 다른 부분은 건드리지 마. |

`{{packRef}}`는 채팅 AI면 "첨부한 설계도", 코딩 에이전트면 "폴더에 저장한 설계도(CLAUDE.md 또는 AGENTS.md)". 괄호 안은 이용자가 채운다. 복사하면 `card_copy` 이벤트(카드 id)를 보낸다.

## 5. 영수증 링크와 지난 영수증

- 설계도 받기 주소에 영수증 링크(`/arrival#r=…`)를 붙인다. 링크를 연 사람은 같은 영수증을 보고, "이 영수증으로 이어서 가기"로 3단계(도구끼리 맞춰 보기)부터 다시 할 수 있다. 주소 바탕이 있는 호스트면 링크도 바탕을 품는다(`siteRoot()`, ARCHITECTURE 3.1절). v1 옛 주소 `/receipt#r=…` 넘기기는 공개 배포 전이라 T35에서 지웠다.
- 영수증 링크에는 자유 입력이 없으므로, 링크로 연 설계도의 '한 줄 설명'은 유형 목표가 된다.
- 링크로 연 상태를 저장하기 전에 기존 진행을 덮어쓸지 묻는다.
- 발행 시각은 다시 열 때마다 새로 찍는다 (자료가 바뀌었을 수 있으므로 '확인한 때'는 상품 카드 값 그대로).
- 영수증을 받을 때마다 `cc:receipts:v1`에 한 장 더한다: 영수증 링크 조각(`#r=` 뒤), 앱 종류 id(`q.type`의 답), 받은 날. 최대 30장이고, 넘치면 가장 오래된 것을 빼고 그렇다고 알린다. `/receipts`(지난 영수증)에서 줄을 누르면 `/arrival#r=…`로 다시 연다.
