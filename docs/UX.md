# 화면과 경험 설계

정본은 `docs/CONCEPT.md`(D56)다. 화면별 구성은 CONCEPT 6절, 장면과 모션(S1~S9)은 7절, 배치는 5.8절, 게임 층은 8절이 맡는다. 단계 이름은 D64(CONCEPT 2절)를 따른다: 내 AI 써 보기(연습, 선택) → 1 만들 앱 정하기 → 2 도구 고르기 → 3 도구끼리 맞춰 보기 → 4 설계도 받기. 이 문서는 거기에 없는 것만 둔다: 단계 규칙의 구현 기준, 화면마다 남는 세부(내 AI 써 보기 문장, 해 보기 모형 같은 것), 옛 모션과 새 장면의 짝, 접근성 확인표, 화면 고정 문구. 문서끼리 어긋나면 PRD > CONCEPT > 이 문서 순으로 따른다.

## 1. 이야기와 말투

손님이 만들고 싶은 앱을 정하면 지도에 길이 생기고, 기능마다 도구를 골라 길을 잇는다. 고른 도구끼리 맞춰 보며 막힌 곳을 풀면 코드쇼퍼 차가 그 길을 달려 빈 터에 닿고, 설계도와 요금 0원 영수증을 건넨다. 짓는 일은 손님의 AI가 한다. 세계관은 CONCEPT 1절, 여정은 2절, 목소리는 4절.

- 말하는 이는 코드쇼퍼 자신이다. 사람 그림 없이 화면 글과 짧은 기사 메시지로만 말한다.
- 해요체로 쓴다. 합쇼체는 슬로건 두 줄에만 쓴다. 손님을 모시는 말("모실게요")은 한 화면에 한 번까지. 느낌표는 쓰지 않는다 (확인 문제를 맞힌 순간만 예외).
- 장소·진행·보상은 세계관 말로, 결정·돈·안전·AI에게 넘길 것은 쉬운 말로 쓴다. 세계관 낱말은 CONCEPT 3.8절 목록만 쓰고, 3.9절의 말은 쓰지 않는다.
- 버튼은 하는 일 그대로 짧게 쓴다: "고르기", "빼기", "도구 바꾸기", "그대로 가기", "설계도 받으러 출발하기", "복사". 다음 단계로 가는 버튼은 단계 이름의 동사를 쓴다("도구 고르러 가기").
- 숫자는 단위와 함께: "약 2시간", "3개, 10분이면 돼요".
- 번역투, 영어 섞어 쓰기, 과장, 겁주기는 `.claude/rules/copy.md`를 따른다.

## 2. 모든 화면에 공통

틀과 크기는 CONCEPT 5.8절, 부분마다의 생김새는 6절 머리와 6.1~6.12절이 정본이다. 단계 화면의 뼈대는 **머리줄 → 단계 줄 → 지도 띠 → 시트 → 아래 막대**다.

| 요소 | 내용 |
|---|---|
| 머리줄 | 높이 56. 로고 가로 묶음(그림 52×44 + 8 + 글자 상표 82×20, 링크 높이 44, 숨은 글 '코드쇼퍼'), 오른쪽에 (사전) 알약(보이는 높이 36, 누르는 곳 44)과 (⚙ 설정) 원형 버튼 44px. 붙박이가 아니다 (D41, D65) |
| 단계 줄 | `<nav aria-label="진행 단계">`. 컨테이너 40rem 미만(360px 기본, 글자 200%)이면 "2/4 · 도구 고르기" 버튼 하나 + 4칸 막대로 접히고 누르면 단계 시트가 열린다. 40rem 이상이면 연습 글 링크와 원 넷으로 펼친다. 마침(✓) · 지금(`aria-current="step"`) · 아직 못 가요(이유 글). CONCEPT 5.8절 |
| 지도 띠 | 내 앱 지도. `role="img"`와 요약 글을 단다. 보조 그림이고, 뜻과 조작은 모두 시트가 가진다 |
| 시트 | H1(기사가 묻는 말), H1 아래 한 줄(그 단계에서 할 일), 내용. 화면이 바뀌면 초점이 H1로 간다 |
| 기사 메시지 | 사건 때만 나온다: 도구끼리 맞춰 보기에서 막힌 곳이 다 풀렸을 때, 도착했을 때 (D64). 모자 배지 원 32 + `--fill` 면(모서리 14, 안쪽 12·16, 테두리 없음) + 15/22 글 두 줄: 알림 600, 다음 할 일 400 `--text-2` (D65, brief 6.1). `aria-live="polite"`, 닫기 버튼 44px, 저절로 닫히지 않고 다음 행동을 하면 한 줄로 접힌다 |
| 아래 막대 | 붙박이. `--surface-raised` + 위로 그림자. 위 8 → 상태 한 줄 20("도구 고르기 · 1개만 더 고르면 돼요 · 약 1분", CONCEPT 2.3절) → 사이 8 → 그 화면의 주 버튼 하나 56 → 아래 12 + 안전 영역. 미니 길은 없앴다 (D67) |
| 사전 | 머리줄의 (사전)으로 연다. 휴대폰은 위 모서리 20의 모달 시트(최대 높이 90%), 1024px 이상은 오른쪽 옆 창 400. 손잡이는 그리지 않는다 (D67) |
| 설정 | 머리줄 ⚙ 모달 시트, 줄 56: 동작 줄이기(기기 설정을 따르는 것이 기본) · 효과음(기본 꺼짐) · 조용히 모시기(기본 꺼짐) · 어려운 말 풀이 · 점선 밑줄(둘 다 기본 켜짐) · 지난 영수증 보기 › · 저장한 기록 지우기(위험 글, 확인 대화 상자). 스위치 44×28, 켜짐 `--accent`, `role="switch"` (D67) |
| 바닥글 | 글자 상표(높이 16) → 14/20 `--text-3` 줄 둘(라이선스, 미리 보기 배포의 "시험판이에요. 도구 정보가 바뀔 수 있어요.") → 링크 목록(밑줄 없음, 누르는 곳 44, 사이 12). 모든 화면 맨 위의 시험판 띠는 없앴다 (D67) |
| 저장 안내 | localStorage를 쓸 수 없으면 "이 브라우저에서는 진행 상황이 저장되지 않아요." 한 줄 |

화면 폭 360px 기준, 옆 여백 20px(359px 이하 16px). 768px에서는 시트 내용을 가운데 640px 안쪽에 두고, 1024px 이상에서는 왼쪽 440px 패널과 오른쪽 지도로 나눈다.

### 2.1 단계 규칙

열리는 조건과 못 갈 때의 문장은 CONCEPT 2.1절이 정본이다. 조건은 `evaluate()` 결과로 정하고, 단계 목록과 판단은 `src/lib/stages.ts`(옛 `stations.ts`) 한 곳에 둔다. 조건이 안 맞는 주소로 바로 들어오면 갈 수 있는 단계로 보내고 이유를 한 줄 보여 준다.

| 단계 | id · 주소 | 열리는 조건 | 조건이 안 맞으면 |
|---|---|---|---|
| 내 AI 써 보기 (연습, 선택, 번호 밖) | `test-drive` · `/test-drive` | 늘 | — |
| 1 만들 앱 정하기 | `destination` · `/destination` | 늘 | — |
| 2 도구 고르기 | `waypoints` · `/waypoints` | 만들 앱을 다 정함 (`done`) | 만들 앱 정하기의 다음 질문으로 |
| 3 도구끼리 맞춰 보기 (H1 '고른 도구끼리 잘 맞을까요?') | `check` · `/check` | 만들 앱을 다 정함 (`done`) | 만들 앱 정하기의 다음 질문으로 |
| 4 설계도 받기 | `arrival` · `/arrival` | 막힌 곳이 없음 (`canIssue`) | 도구끼리 맞춰 보기로 |

- 홈의 '이어서 가기' (`continueTarget`, D70): 만들 앱을 다 정하지 않았으면 만들 앱 정하기(n번째 질문), 고른 도구가 없거나 지금 고를 수 있는 꼭 고를 것이 남았으면 도구 고르기, 출발할 수 없으면 도구끼리 맞춰 보기, 아니면 설계도 받기(영수증 다시 보기). 맞는 도구가 없는 꼭 고를 것은 도구끼리 맞춰 보기에서 '그대로 가기'로 넘기므로 남은 수에 넣지 않는다 (상태 한 줄과 같은 progress()).
- 홈의 미리 짠 코스 줄은 `data/recipes.json`의 앞 3개다.
- 코스로 출발하거나 영수증 링크로 연 상태가 지금 저장된 상태와 다르면 덮어쓰기 전에 묻는다. 두 상태가 같은지는 `normalizeSession` 결과의 answers·cart·kept·deferred를 비교해 정한다.

### 3.1 내 AI 써 보기: 연습 문장 셋

10분 연습이다. 설치 없이 AI 채팅에서 웹페이지 한 장을 만든다. 문장마다 [복사] 버튼이 있다.

1. **연습 1 · 만들기**: "버튼을 누르면 응원 문구가 하나씩 바뀌어 나오는 웹페이지를 HTML 파일 하나로 만들어 줘. 문구는 10개를 넣고, 휴대폰에서도 보기 좋게 해 줘. 코드는 한 덩어리로 보여 줘."
2. **연습 2 · 고치기**: "배경색을 연한 노란색으로 바꾸고, 문구 아래에 몇 번째 문구인지 숫자로 보여 줘. 바뀐 코드 전체를 다시 보여 줘."
3. **연습 3 · 저장해서 열기** ('PC 권장' 꼬리표): "이 코드를 내 컴퓨터에서 열고 싶어. 메모장(맥은 텍스트 편집기)에 붙여 넣고 cheer.html로 저장한 뒤 브라우저로 여는 방법을 차례로 알려 줘."

- 연습마다 "잘 안 돼요" 접힘 안내를 둔다 (복사가 안 될 때, AI가 코드를 여러 조각으로 줄 때).
- 끝 한 줄과 [다 했어요] 뒤의 흐름([만들 앱 정하러 가기])은 CONCEPT 6.2절. 연습을 마친 표시(`cc:meta:v1`의 `lessonDone`)가 단계 줄의 ✓가 된다.
- 연습 셋은 세로 번호 단계(번호 원 24 + 2px 잇는 선)이고, 단계마다 붙여 넣을 말 상자('AI에게 보낼 말' + [복사])와 접기 "잘 안 돼요"가 있다. 상자·점선·옅은 파랑 알약은 쓰지 않는다 (D70).

### 3.2 만들 앱 정하기: 질문 규칙

- 한 화면에 질문 하나: H1이 그 질문이고(앞에 숨은 'n번째 질문.'), 풀이(있으면), 보기. 질문 수가 답에 따라 바뀌므로 퍼센트나 막대 대신 아래 막대의 상태 한 줄이 "n번째 질문"을 보인다(돌아가 보는 질문을 따른다). 화면 안의 'n번째 질문' 글과 바깥 카드는 없다 (D70).
- 보기는 하나하나가 버튼이다. 누르거나 Enter·Space를 치면 바로 다음 질문으로 간다. 화살표 키만으로는 넘어가지 않는다 (라디오 버튼을 쓰지 않는 이유, WCAG 3.2.2, D19). 이미 고른 보기는 `aria-pressed="true"`로 표시한다. 질문을 옮기면 제목으로 초점이 가고 화면 맨 위로 올라간다.
- 보기 꼴: 앱 종류·느낌은 2열 타일 156×132(느낌은 내 지도를 네 팔레트로 칠한 견본), 모르겠어요는 아래 전체 폭 줄 56, 짧은 네 보기(네·아니요…)는 2×2 버튼 56, 그 밖은 목록 줄 56 (CONCEPT 6.3).
- 아래 막대 왼쪽 [이전](56×56, 이름 '이전')으로 돌아가 답을 바꿀 수 있다. 시트 맨 아래 접기 '지금까지 정한 것'의 답 줄을 눌러도 그 질문으로 간다.
- 마지막 질문: "만들고 싶은 걸 한 줄로 적어 주세요 (선택)". 안내: "이름, 학교 이름, 연락처는 적지 마세요. 이 글은 영수증 링크에 들어가지 않아요." 80자까지. Enter는 주 버튼으로 초점을 옮긴다.
- 출구 "도구 먼저 둘러볼게요"는 시트 맨 아래 글 버튼이고 `/tools`로 간다. 답은 저장해 둔다. 주 버튼 자리에 두지 않는다.
- 첫 질문은 "어떤 앱을 만들까요?"이고, 그 위에만 단계 한 줄 "몇 가지만 물어볼게요. 답할 때마다 내 앱 지도가 자라요."를 둔다.
- 답이 쌓이면 시트 첫 줄에 칩 "고를 것 n개". 답 하나로 마디가 생기거나 빠지면 "지도에 저장이 생겼어요." / "지도에서 로그인이 빠졌어요."를 낭독한다.
- 마지막 질문에 답하면 "고를 것이 n개 생겼어요. 기능마다 도구를 골라요."(한 줄 쓰기 위 한 줄과 낭독), 상태 한 줄 "만들 앱 정하기 · 다 정했어요", 주 버튼 [도구 고르러 가기] → `/waypoints` (S7). 그 전에는 주 버튼이 없다.

### 3.2.1 도구 고르기: 미리 누름과 이름이 박힌 확정 버튼

- 기능 칩 한 줄(가로로 밀기)로 칸을 연다. 칩은 버튼이고 지금 여는 칩에 `aria-current="true"`, 숨은 글로 '꼭 고를 것/있으면 좋은 것, 골랐어요/아직 안 골랐어요'를 읽는다. 처음 열 칸은 주소의 `?slot=`(도구끼리 맞춰 보기의 '도구 바꾸기') → 고를 수 있는 첫 꼭 고를 것 → 첫 칸.
- 도구 줄은 `<button aria-pressed>`다(D19와 같은 방식). 꼭 고를 것은 추천 줄이 '고를 예정'으로 눌려 있고(저장하지 않는다), 다른 줄을 누르면 그 줄로 옮긴다. 있으면 좋은 것은 미리 누르지 않고, 눌린 줄을 다시 누르면 거둔다. 미리 눌린 줄은 고름 면 + 고리와 숨은 글 '고를 예정', 정한 도구 줄은 ✓와 숨은 글 '정한 도구'(✓는 정한 뒤에만, D70 검토 반영). 둘째 줄은 '0원으로 시작 · 공식 · 난이도 보통', 추천 줄의 추천 이유는 둘째 줄과 겹치는 말을 빼고 적는다.
- 아래 막대의 주 버튼이 저장한다: [{도구}로 정하기] → 장바구니에 담고 다음 남은 꼭 고를 것(지금 칸 다음부터, 끝에서 처음으로)을 연다. 이미 정한 칸에서 다른 줄을 누르면 [{도구}로 바꾸기]. 고를 수 있는 꼭 고를 것을 다 고르면 [도구끼리 맞춰 보러 가기]. 눌린 줄이 없으면 주 버튼은 꺼지고(`aria-disabled`, 까닭은 칸 설명 아래 '쓸 도구를 누르면 정할 수 있어요.', 맞는 도구가 없는 칸은 알림 상자 글), 옆에 글 버튼 [이번엔 건너뛰기]. 꺼진 채 누르면 까닭을 읽고 첫 도구 줄로 초점을 옮긴다. 있으면 좋은 것에 정한 도구가 있으면 [도구 빼기]. 추천대로 가면 꼭 고를 것마다 한 번만 누른다.
- 이름은 괄호 안을 뺀 것, 빈칸을 뺀 글자가 14자를 넘으면 '고른 도구로 정하기'이고 읽는 이름(`aria-label`)은 보이는 글로 시작해 온전한 이름을 붙인다: '고른 도구로 정하기: Firebase Authentication'(WCAG 2.5.3). [도구 빼기]도 '도구 빼기: Airtable'. 조사는 `josa`(영문 끝 'ng'는 ㅇ받침, 'le'는 ㄹ받침).
- 정하면 낭독: "Supabase로 정했어요. 1개만 더 고르면 돼요. 다음은 로그인을 맡을 도구예요. 추천은 Firebase Authentication이에요."(남은 수는 상태 한 줄과 같은 말, 끝에 다음 칸에 미리 눌린 추천). [바꾸기]를 눌렀으면 "○○로 바꿨어요." 초점은 주 버튼에 남아(`preventScroll`: sticky 아래 막대로 페이지가 굴러가지 않게) 키보드로는 Enter를 누를 때마다 다음 칸으로 간다.
- '자세히'는 눌린 줄 아래에 따로 있는 글 버튼(`aria-expanded`)이다. 펼치면 바로 밑에 한눈에 보기(하는 일·다른 후보와 비교·비용·제공·무료 한도·필요한 자격·갱신·키 노출 위험·라이선스·필요한 용어·막히기 쉬운 곳·확인한 때·공식 문서).
- 바꿀 때 그 칸을 맡던 도구가 다른 칸도 혼자 맡고 있으면 장바구니에 남긴다. 잠기면(만들 앱을 정하기 전) 빈 상태 하나와 주 버튼 [만들 앱 정하러 가기] 하나.

### 3.3 도구끼리 맞춰 보기: 막힌 곳 항목과 초점

- 순서(할 일이 위, 판단 과정이 아래, D70 W4d): H1 + 한 줄 → (다 풀렸으면) 사건 메시지 → 막힌 곳 n개 → 그대로 가는 곳 → 한 번에 가기엔 길이 멀어요 → 나중에 붙일 것 → 지름길 알림 상자 → 접기 '원활 n개' → 접기 '이렇게 이해했어요'. 묶음은 상자 없이 제목과 나눔 선으로 나눈다.
- 막힌 곳 항목: 막힘 알약 + 기능 이름(지도에 없는 기능의 규칙은 '길 전체') → 설명 → '고치는 법:' → 같은 크기 중립 버튼 둘(나란히, 좁거나 글자 200%면 위아래) → 안내 한 줄 14 `--text-3`. 버튼 읽는 이름에는 기능을 붙인다('저장: 그대로 가기'). [도구 바꾸기]·[도구 고르기]는 그 기능을 펼친 도구 고르기(`?slot=`)로 간다.
  - 보통: [도구 바꾸기](빈 기능이면 [도구 고르기]) [그대로 가기] + "그대로 가면 '알아볼 것'에 적어 둘게요."
  - 미룰 수 있는 빈 기능(로그인·알림): [도구 고르기] [나중으로 미루기] + "미루면 '나중에 붙일 것'에 적어 둘게요."
  - 비워 둘 수 없는 기능(`keepable: false`): "통행 불가: 이건 비워 두고 갈 수 없어요." + [도구 고르기] 하나.
- 그대로 가는 곳: 두 줄 줄(서행 알약 + 기능 이름 + 둘째 줄 막힌 곳 설명의 첫 문장 + 글 버튼 [되돌리기], 읽는 이름 '저장: 막힌 곳으로 되돌리기'). 나중에 붙일 것: 줄 56 + 글 버튼 [되돌리기]. 한 번에 가기엔 길이 멀어요: 미룰 수 있는 기능 줄 56 + 작은 중립 버튼 [나중으로 미루기](막힌 곳의 같은 동작과 같은 이름), '더 쉬운 길' 줄 72 + 작은 중립 [바꾸기]. 미룰 것도 더 쉬운 길도 없으면 "이대로 가도 괜찮아요. 시간이 더 걸릴 뿐이에요."
- 원활: 고른 도구가 있고 막힌 곳이 붙지 않았고 미루지 않은 기능(엔진의 막힌 곳을 기능별로 묶기만 한다). '이렇게 이해했어요'에는 답(키-값 묶음), 기능마다 고른 도구, 어디에도 쓰이지 않는 도구, 난이도·예상 시간. 지름길 문장은 앱 종류 문장 틀의 `alternative`에서 온다 (R-32).
- 초점: 누른 버튼이 사라지는 동작 뒤에는 다음 막힌 곳의 첫 버튼 → 그 묶음 제목 → 아래 막대 주 버튼으로 옮긴다(WCAG 2.4.3, 아래 막대로 옮길 때는 페이지를 굴리지 않는다). 막힌 곳이 다 풀리면 사건 메시지와 다 풀린 지도가 보이게 맨 위로 올린다(동작 줄이기면 바로). 이 알림은 화면의 사건 메시지만 읽고 단계 줄의 '이제 설계도를 받을 수 있어요.'는 겹쳐 읽지 않는다. 꺼진 주 버튼(`aria-disabled`)의 까닭은 상태 한 줄이 맡고(`aria-describedby="status-line"`), 꺼진 채 누르면 상태 한 줄을 읽어 준 뒤 '막힌 곳 n개' 제목으로 초점을 옮긴다.

### 3.4 설계도 받기: 넘겨주기 세부

- 순서: (영수증 링크로 열면 꼬리표 '받은 영수증 보기') → 사건 메시지(내 영수증을 받았을 때) → H1 + 한 줄 → 건네드릴 것 카드(화면에 단 하나의 카드) → (링크로 열면 중립 버튼 [이 영수증으로 이어서 가기]) → 칸 고르개 4칸(영수증 · 설계도 · 용어 · AI에게 할 말, 처음은 영수증, `role="tablist"`, ←→↑↓·Home·End, 좁거나 글자 200%면 세로 줄 목록) → 맺음 한 줄.
- 아래 막대: 상태 한 줄 + 주 버튼 하나. 받을 수 있으면 [설계도 내려받기 (.md)](`codechauffeur-plan-YYYYMMDD-HHmm.md`). 잠김은 빈 상태 하나와, 상태 한 줄과 같은 까닭의 주 버튼: 만들 앱 전 [만들 앱 정하러 가기], 막힌 곳이 남음 [도구끼리 맞춰 보러 가기], 깨진 링크 [처음 화면으로 가기]. 셋은 `src/lib/arrival-view.ts`의 같은 값을 읽는다.
- 영수증 칸: 종이 + 같은 크기 중립 버튼 둘 [영수증 링크 복사] [PC로 보내기](Web Share, 안 되면 링크 복사) + 글 버튼 [영수증 글 복사] [메일로 보내기] + 접기 '준비물(오래 걸리는 것부터)'·'막히기 쉬운 곳'.
- 설계도 칸: 한 줄 + 고른 AI에 맞는 저장 안내(`saveAs`) + 중립 [설계도 복사] + 접기 '설계도 미리 보기'. 칸 안에 주 버튼을 두지 않는다(내려받기는 아래 막대).
- 용어 칸: '먼저 읽어 둘 용어' 줄 56(용어 카드로) + '만들면서 볼 용어'(단계 이름 아래, 먼저 읽어 둘 용어와 겹치면 다시 적지 않는다) + [용어 카드 모두 보기].
- AI에게 할 말 칸: 항목마다 제목 + '언제: …' + 붙여 넣을 말 상자([복사]). 복사하면 "복사했어요." (화면 낭독기에도 알림). 버튼 글은 2초 뒤 원래 글로 돌아간다(같은 화면의 복사 버튼들이 같은 이름으로 남지 않게).
- 출력은 한 번만: 영수증 칸으로 돌아오거나, 도착 장면을 본 뒤 다시 열면 종이와 도장을 다시 뽑지 않는다. 도착 알림은 출력이 끝난 뒤, 동작 줄이기(기기·사이트)면 바로 읽는다. 칸 고르개가 세로 목록이 되면(좁거나 글자 200%) `aria-orientation="vertical"`.
- 맺음 아래 작은 글은 설계도 끝 면책과 같은 뜻의 화면 말(해요체): "'알아볼 것'은 법률 자문이 아니에요. 도구 정보는 확인한 때 기준이라 지금과 다를 수 있어요." 설계도(.md) 안의 면책은 문서 체 그대로(DATA.md).
- 영수증 종이: 흰 감열지(낮·밤 같음), CC Receipt 14/20, 36칸(약 300px, 최대 360), 아래 톱니 8, 머리 = 단색 모자 마크 24 + '코드쇼퍼 영수증' + 받은 때 + '영수증 0427'(링크 조각 해시, 지난 영수증 줄과 같은 번호), 끝 남색 도장.
- 영수증 링크로 열었을 때: 주소의 `#r=`를 읽자마자 `history.replaceState`로 지운다 (D17). 섬이 읽기 전에는 빌드 때 그린 잠김 화면을 감춘다(`data-receipt-link`). 링크의 영수증은 읽기 전용이고, [이 영수증으로 이어서 가기]를 누르면 (지금 상태와 다를 때만 물은 뒤) 저장한다. 이어서 가면 누른 버튼(과 대화 상자)이 사라지므로 초점은 H1로 간다. 링크로 연 동안 지도 띠도 그 영수증의 도착 그림이다. 링크가 깨졌거나 출발할 수 없는 상태면 빈 상태 "영수증 링크를 열지 못했어요."와 [처음 화면으로 가기].
- 이 화면에는 Cloudflare Web Analytics 스크립트를 싣지 않는다 (주소에 영수증 상태가 잠깐이라도 있으므로, R-04).
- 영수증을 받으면 지난 영수증(`cc:receipts:v1`)에 한 장 더한다 (`docs/ARCHITECTURE.md` 4절).

### 3.5 도구 모음과 도구 상세

- 상세 페이지는 쉬운 설명이 있는 도구(`layer: shelf`)만 만든다. 원문만 있는 도구(`layer: index`)는 목록 맨 아래 접힘에서만 보이고, 원문 링크와 정해진 항목만 보여 준다.
- 검색 칸은 사전과 같은 색인을 쓴다 (`docs/ARCHITECTURE.md` 7절).

### 3.6 용어 카드: 해 보기 모형

- "내 AI에게 배우기" 문장은 복사할 수 있고, `{{project}}` 자리에 손님이 적은 한 줄이 들어간다 (없으면 "내 앱").
- 해 보기 모형 다섯 가지는 진짜 키나 서버를 쓰지 않는 연습 화면이다:
  - env-var-form: 이름 칸과 값 칸에 가짜 키를 넣으면, 코드 미리 보기에는 `env.API_KEY`처럼 이름만 남는다.
  - api-key-form: 가짜 키를 '화면 코드'와 '비밀 보관함' 중 어디에 둘지 고르고, 화면 코드를 고르면 브라우저 개발자 도구에서 키가 보이는 그림을 보여 준다.
  - json-reader: 급식 API 응답 예시에서 항목을 누르면 이름표와 값을 풀어 준다.
  - terminal-sim: 정해진 명령 몇 개(`node -v`, `npm -v`, `npm run dev`)에만 답하는 가짜 터미널.
  - deploy-sim: 파일 올리기 → 빌드 → 주소 생김을 세 걸음으로 따라가는 그림.
- 읽음과 정답 기록은 `cc:study:v1`에 둔다. 화면에는 "20장 중 n장 읽음"만 보이고 퍼센트나 순위는 두지 않는다.

### 3.7 사전

- 결과 묶음 순서: 에러가 났을 때 · 용어 · 막히기 쉬운 곳 · 도구.
- 에러 문장을 붙여 넣으면 맞는 에러 안내를 맨 위에 둔다. 없으면 질문 틀(`templates.errorFallback`)과 [복사].

### 3.8 소개, 추천 기준, 크레딧, 법, 404

- 소개 `/about`: 무엇을 하고 무엇을 하지 않는지, AI를 쓰지 않는 이유, 자료는 누구나 고칠 수 있다는 것(저장소 링크), 광고·제휴가 없다는 것. '쇼퍼'의 두 뜻(모시는 기사, 대신 골라 주는 사람)을 한 문단으로 적는다 (CONCEPT 11절).
- 추천 기준 `/about/criteria`: `data/scoring.json`의 값을 그대로 표로. 항목 설명은 `docs/ENGINE.md` 3절을 쉬운 말로.
- 크레딧 `/about/credits`: 글꼴·아이콘·그림·라이브러리의 출처와 라이선스. `THIRD_PARTY_NOTICES.md`와 같게 둔다.
- 개인정보 처리방침·이용 안내 `/legal/*`: 초안을 만들고 맨 위에 "검토 중" 표시. 최종 문구는 사람이 확인한다.
- 404: "길을 잘못 들었어요. 처음 화면으로 모실게요." (홈 버튼)

## 4. 모션

장면 S1~S9, 공통 규칙, 길이 토큰, 효과음은 CONCEPT 7절이 정본이다. 기술은 CSS 전환·키프레임·`@starting-style`, WAAPI, SVG `stroke-dashoffset`·`offset-path`, FLIP, 문서 간 View Transitions이고, 순서와 건너뛰기는 `src/lib/motion.ts`가 맡는다. **라이브러리는 없다** (색종이 `canvas-confetti`를 뺐다, D56). 길이와 곡선은 `src/styles/tokens.css`의 변수만 쓴다. 만드는 법은 `game-motion` 스킬.

지킬 선(요약): 모션 하나는 1초 안쪽, 대표 장면도 3초 이하(S5는 2.8초). 누르기·Esc·[건너뛰기]로 끝 상태로 가고, 장면 중에도 버튼이 눌린다. 움직임이 알리는 것은 `aria-live` 글로도 알린다. 번쩍임은 1초에 3번 미만. 동작 줄이기(기기·사이트)에서는 150ms 페이드만 남긴다 (D30).

## 5. 시각 요소

그림체·색·글꼴·모양·아이콘·배치는 CONCEPT 5절, 그림 자산은 9절, 피할 것은 `docs/DESIGN.md` 3절.

- 색·글꼴·크기·모서리·그림자·모션 길이는 `src/styles/tokens.css`만 쓴다. 새 색이 필요하면 토큰을 먼저 더하고 낮·밤 두 모드의 대비를 확인한다.
- 낮 지도가 기본이고, 기기가 어두운 모드면 밤 지도로 바뀐다 (`prefers-color-scheme`). 사이트 안 화면 색 설정은 `docs/BACKLOG.md`.
- 주 버튼은 파랑 `--accent` 채움에 흰 글자다. 금색은 쓰지 않는다: 남색은 내 것('요금 0원' 칩, 영수증 도장, 고른 것), 파랑은 지금·할 일, 청록은 빛(남색 위 점, 내 길의 심)이다 (CONCEPT 5.3, D61·D65).
- 기능은 색이 아니라 모양 + 그림 + 이름표로 나눈다 (CONCEPT 5.5절). 색은 교통 정보(막힘·서행·원활)와 '지금 위치'에 남겨 둔다.
- 화면 아이콘은 Phosphor Regular를 빌드 때 인라인 SVG로 넣는다 (`src/lib/icons.ts`). 기능 그림·질문 그림·지도 표지는 직접 그린 SVG(24px 격자, 선 1.5px, 둥근 끝)이고 `svg-illustrator`가 만든다.
- 사람 그림(마스코트)과 Fluent 3D 그림 문자는 쓰지 않는다. 글 속에 이모지 문자도 넣지 않는다 (D56).
- 목적지 첫 질문(앱 종류 6)의 타일은 건물 렌더 L01~L06이고, 받기 전에는 청사진 자리 표시를 쓴다. 그림은 장식(`alt=""`)이고 보기 이름이 뜻을 전한다. `questions.json`의 `alt`는 그림만 따로 보일 때 쓴다. '느낌' 보기는 내 지도를 네 팔레트로 칠한 견본이다.
- 영수증은 늘 흰 종이에 CC Receipt(D2Coding 기반), 아래쪽 톱니 가장자리, 빨간 둥근 도장 "코드쇼퍼 · 요금 0원".
- 실제 차종·건물·회사 로고, 남의 캐릭터를 닮게 그리지 않는다.

## 6. 접근성 확인표

- [ ] 모든 기능을 키보드만으로 쓸 수 있다. 초점 고리(`--focus`)가 낮·밤 모두에서 늘 보인다.
- [ ] 누르는 곳은 44×44px 이상이다 (칩·작은 버튼은 보이는 높이 36px에 누르는 곳 44px, 지도 마디 지름길 44px).
- [ ] 글자 대비 4.5:1 이상, 큰 글자·그림·입력 칸 테두리 3:1 이상. **낮 지도와 밤 지도 두 모드 모두** 맞는다 (`npm run tokens`가 두 모드를 돌고, 밤 360px 스크린샷도 직접 본다).
- [ ] 그림에는 대체 텍스트를 단다. 장식 그림은 `alt=""`.
- [ ] **지도는 `role="img"`에 요약 글**을 단다 (예: "목적지 체험학습 신청서. 꼭 고를 것 4개 중 3개 골랐어요. 막힌 곳 1개."). 요약 글은 `src/copy/ko.ts`에서 온다. 지도에서만 알 수 있는 정보는 없다. 지도 마디는 손가락용 지름길이라 탭 순서에 넣지 않고, 같은 일을 시트의 알약과 목록이 한다.
- [ ] 단계 줄은 `<nav aria-label="진행 단계">`이고 지금 단계에 `aria-current="step"`을 단다. 아직 못 가는 단계는 이유 글을 함께 보인다.
- [ ] **단계 줄이 버튼으로 접힌다**: 컨테이너가 40rem보다 좁거나 글자를 200%로 키우면 버튼 하나("2/4 · 도구 고르기" + 4칸 막대, 52px)가 된다. 보이는 '2/4'는 낭독에서 빼고 "4단계 중 2단계: 도구 고르기"가 읽힌다. 누르면 단계 시트(`<dialog>`, 제목 "진행 단계")가 열려 다섯 단계가 56px 줄로 나온다. 단계 시트도 초점 가두기·Esc·뒤 막 누르기·원래 자리로 초점을 지킨다. 시트의 못 가는 줄은 이유를 둘째 줄에 적은 누를 수 없는 줄이다 (e2e `tests/e2e/stage-rail.spec.ts`).
- [ ] **붙박이 아래 막대가 초점을 가리지 않는다**: `scroll-padding-bottom`을 막대 높이(`--bar-bottom`)로 둔다 (WCAG 2.4.11).
- [ ] 보기를 고르는 것만으로 화면이 바뀌는 곳은 버튼(`aria-pressed`)으로 만들고, 화살표 키 이동만으로는 바뀌지 않는다.
- [ ] 화면이 바뀌면 시트의 H1로 초점을 옮기고 페이지 제목(`<title>`)을 바꾼다.
- [ ] 복사, 고르기, 막힌 곳 풀기, 지도 변화 같은 결과를 `aria-live`로 알린다 (예: "Supabase로 정했어요. 1개만 더 고르면 돼요.", "지도에 저장이 생겼어요.").
- [ ] 기사 메시지는 그림 속 글이 아니라 진짜 글이다. `aria-live="polite"`로 읽히고, 닫기 버튼이 있고, 저절로 닫히지 않으며, 화면을 가리지 않는다.
- [ ] 옆 창·대화 상자·단계 시트는 열 때 안으로 초점, Esc로 닫기, 닫으면 원래 자리로 초점.
- [ ] 설계도 받기의 탭 넷은 `role="tablist"`이고 화살표 키로 옮긴다.
- [ ] 글자 크기 200%에서도 내용이 잘리지 않는다. 지도 이름표는 커지지 않으므로 같은 뜻을 시트가 가진다.
- [ ] '동작 줄이기'(기기 설정과 사이트 설정 모두)를 따른다. 줄이기에서도 정지 화면만으로 모든 정보가 보인다.
- [ ] 모든 장면을 누르기·Esc·"건너뛰기" 버튼으로 끝낼 수 있고, 장면 중에도 버튼이 눌린다. 번쩍임은 1초에 3번 미만이다.
- [ ] 효과음은 기본 꺼짐이고, 소리 없이도 모든 결과를 알 수 있다.
- [ ] 색만으로 뜻을 전하지 않는다. 교통 정보는 색 + 그림 + 글이다 (막힘 = 사고 표시 + "막힘", 서행 = 물음표 + "서행", 원활 = ✓ + "원활"). 기능 마디는 모양 + 그림 + 이름표다.
- [ ] axe 자동 검사에서 심각(serious)·치명(critical) 0개 (낮·밤).
