# 화면과 경험 설계

## 1. 이야기와 말투

손님(이용자)을 태운 차가 정류장 다섯 곳(첫 수업 · 인터뷰 · 장보기 · 재확인 · 계산대)을 돌며 장을 보고, 마지막에 영수증을 받아 내리는 여정이다. 차는 금빛 배지를 단 **기사님**(마스코트)이 몬다. 노선도 보드게임처럼 정류장을 지날 때마다 도장이 찍히고 주행 거리가 늘어난다. 세계관·색·글꼴·기사님 쓰는 법은 `docs/DESIGN.md`.

- 안내 문장은 운전기사가 손님을 모시는 존댓말(해요체)로 쓴다: "어디로 모실까요?", "다음 정류장은 장보기입니다", "영수증 챙겨 가세요".
- 버튼은 짧은 동사로 끝낸다: "담기", "빼기", "다음", "영수증 뽑기".
- 숫자는 단위와 함께: "약 2시간", "하루 10만 건".
- 쓰지 않는 말: 과장("완벽한", "혁신적인"), 겁주기("큰일 납니다"), 영어 섞어 쓰기("체크해 보세요" → "확인해 보세요"). 자세한 기준은 `.claude/rules/copy.md`.

## 2. 모든 화면에 공통

| 요소 | 내용 |
|---|---|
| 노선 띠 (상단) | 정류장 다섯 개를 잇는 굵은 길. 지금 정류장에 차가 서 있고, 지나온 구간은 금빛으로 칠해진다. 정류장 이름은 글자로도 보인다. 마친 정류장 핀 아래에 작은 도장. 첫 수업은 건너뛴 경우 흐리게. 갈 수 있는 정류장만 누를 수 있고, 아직 못 가는 곳은 자물쇠와 이유("인터뷰를 마치면 열려요"). `<nav aria-label>` + 지금 정류장 `aria-current="step"`. |
| 행선지 전광판 (노선 띠 아래) | 남색 바탕에 금색 고정폭 글자로 "이번 정류장: 장보기"처럼 지금 있는 곳을 한 줄로. 옆에 주행 거리 계기판(예: 12km, `role="progressbar"`와 글 "정류장 5곳 중 2곳 지남, 주행 거리 12km")과 기사님 작은 얼굴. |
| 기사님 | 홈(크게), 정류장에 처음 도착했을 때(작게, 말풍선 1~2문장), 재확인을 마칠 때(모두 초록), 계산대(축하)에서 왼쪽 아래에 나온다. 말풍선은 누르거나 다음 행동을 하면 접히고, 글은 `aria-live`로도 읽힌다. 화면을 가리면 접기 버튼으로 숨길 수 있다. |
| 사전 버튼 (오른쪽 아래 고정) | 누르면 사전 옆 창. 휴대폰은 아래에서 올라오는 창, 넓은 화면은 오른쪽 창. Esc로 닫고, 닫으면 초점이 버튼으로 돌아온다. |
| 아래 진행 막대 | 그 화면의 주 버튼 하나 (예: "다음 정류장으로"). 휴대폰에서 엄지로 누르기 쉬운 자리. |
| 설정 | 머리말의 작은 메뉴: 동작 줄이기 켜기·끄기 (기기 설정을 따르는 것이 기본), 효과음 켜기·끄기 (기본 꺼짐), 내 여행 기록(도장판) 보기, 저장한 기록 지우기. |
| 저장 안내 | localStorage를 쓸 수 없으면 "이 브라우저에서는 진행 상황이 저장되지 않아요" 한 줄. |

화면 폭 360px 기준, 양옆 여백 16px, 본문 폭은 720px 안쪽.

### 2.1 정류장 규칙

`evaluate()` 결과로 정한다. 조건이 안 맞는 주소로 바로 들어오면 갈 수 있는 정류장으로 보내고 이유를 한 줄 보여 준다.

| 정류장 | 열리는 조건 | 조건이 안 맞으면 |
|---|---|---|
| 첫 수업 `/lesson` | 늘 | — |
| 인터뷰 `/interview` | 늘 | — |
| 장보기 `/shop` | 인터뷰가 끝남 (`done`) | 인터뷰의 다음 질문으로 |
| 재확인 `/check` | 인터뷰가 끝남 | 인터뷰의 다음 질문으로 |
| 계산대 `/receipt` | 영수증을 뽑을 수 있음 (`canIssue`) | 재확인으로 ("고칠 곳이 남았어요") |

- 홈의 "이어서 하기": 인터뷰가 안 끝났으면 인터뷰(n번째 질문), 장바구니가 비었으면 장보기, 발행할 수 없으면 재확인, 아니면 계산대(영수증 다시 보기).
- 홈의 레시피 카드는 `recipes.json`의 앞 3개.
- 레시피로 출발하거나 공유 링크로 연 상태가 지금 저장된 상태와 다르면 덮어쓰기 전에 묻는다. 두 상태가 같은지는 `normalizeSession` 결과의 answers·cart·kept·deferred를 비교해 정한다.

## 3. 화면별

### 3.1 홈 `/`

- 장면 M8 → M2 (합쳐 3초 이하, 누르면 끝): 원근으로 기울어진 도로 위를 남색 차가 달려와 멈추고(M8), 문이 열리며 기사님이 손을 흔들고 말풍선 "어서 오세요. 어디로 모실까요?"(M2). 다시 온 사람에게는 M8을 건너뛰고 M2만.
- 큰 제목: 어디로 모실까요? / 작은 글: 코드는 몰라도 됩니다. 목적지만 말하세요. / 요금은 0원입니다.
- 두 입구 버튼: **만들러 왔어요** (→ `/interview`, 처음이면 첫 수업 권유 한 줄) / **구경하러 왔어요** (→ `/shelf`)
- "바이브코딩이 처음이세요? 10분 첫 수업부터 타 보세요" (→ `/lesson`)
- 레시피 3개 카드 (→ "이 레시피로 출발")
- 이어서 하기: 저장된 진행이 있으면 "지난번 정류장에서 이어 갈까요?" (2.1절 규칙). 그 옆에 내 여행 기록 미리 보기 (도장 몇 개, 주행 거리).

### 3.2 첫 수업 `/lesson`

10분 체험. 설치 없이 AI 채팅에서 웹페이지 한 장을 만든다. 문장마다 복사 버튼이 있다.

1. **만들기**: "버튼을 누르면 응원 문구가 하나씩 바뀌어 나오는 웹페이지를 HTML 파일 하나로 만들어 줘. 문구는 10개를 넣고, 휴대폰에서도 보기 좋게 해 줘. 코드는 한 덩어리로 보여 줘."
2. **고치기**: "배경색을 연한 노란색으로 바꾸고, 문구 아래에 몇 번째 문구인지 숫자로 보여 줘. 바뀐 코드 전체를 다시 보여 줘."
3. **저장해서 열기** (PC 권장 표시): "이 코드를 내 컴퓨터에서 열고 싶어. 메모장(맥은 텍스트 편집기)에 붙여 넣고 cheer.html로 저장한 뒤 브라우저로 여는 방법을 차례로 알려 줘."

끝: "방금 한 게 바이브코딩이에요. 코드를 직접 쓰지 않고, 말로 만들고 고쳤어요." → '첫 수업' 도장이 찍힌다 (M7, 처음 한 번만) → "이제 내 앱을 만들러 가요" (인터뷰). 각 단계에 "잘 안 돼요" 접힘 안내(복사가 안 될 때, AI가 코드를 여러 조각으로 줄 때).

### 3.3 인터뷰 `/interview`

- 한 화면에 질문 하나. 질문 글, 도움말(있으면), 보기.
- 그림 보기(앞 3문항, 분야, 느낌)는 2열 카드(넓으면 3~4열). 그림 아래 보기 이름. 그림에는 `alt`.
- 예·아니요 질문은 네 버튼: 네 / 아니요 / 아마도 / 모르겠어요.
- 보기는 하나하나가 버튼이다. 누르거나(클릭, Enter, Space) 하면 바로 다음 질문으로 간다 (0.3초 전환). 화살표 키만으로는 넘어가지 않는다 (라디오 버튼을 쓰지 않는 이유, WCAG 3.2.2). 이미 고른 보기는 `aria-pressed="true"`로 표시한다.
- "이전" 버튼으로 돌아가 답을 바꿀 수 있다.
- 진행 표시: 질문 수가 답에 따라 바뀌므로 퍼센트나 막대 대신 "n번째 질문"으로 보여 준다.
- '좁혀지는 중' 상자 (휴대폰은 접힘): 답 칩(예: 만들 것: 안내 페이지), 지금 생긴 칸 아이콘, "혹시 이걸 만드시나요?" 레시피 1~2개. 답할 때마다 바뀐 후보 카드가 뒤집히며 바뀐다 (M5).
- 답할 때마다 주행 거리가 늘고, 첫 질문에는 기사님이 "천천히 골라도 돼요. 정하지 못했으면 '아직 모르겠어요'를 누르세요."라고 한 번 말한다.
- 마지막: "만들고 싶은 걸 한 줄로 적어 주세요 (선택)". 안내: "이름, 학교 이름, 연락처는 적지 마세요. 이 글은 공유 링크에 들어가지 않아요." 80자 제한.
- 출구: "일단 구경만 할게요" (→ 진열대, 답은 저장해 둔다).
- 끝나면: '인터뷰' 도장 → "다음 정류장은 장보기입니다." → `/shop` (차가 다음 정류장으로, M1)

### 3.4 장보기 `/shop`

- 맨 위 장보기 목록: 칸 아이콘이 줄지어 있고, 채운 칸에는 확인 표시(✓) (M3).
- 칸 하나씩 펼쳐서 채운다 (한 번에 하나만 펼침).
  - 칸 제목, 필수/선택 표시, 칸 설명 한 줄(규칙의 `help`).
  - 추천 상품이 맨 위: "추천" 표시 + 이유 칩 (예: 분야 일치 · 주제 일치 · 무료) + 2위와 비교 한 줄 (예: "2위 나이스 학사일정: 주제가 달라요").
  - 그 아래 다른 진열 상품, 그 아래 "색인에서 찾은 것 n개" 접힘 (주의 배지).
  - 맞는 상품이 없으면: "이 칸에 맞는 상품이 아직 진열대에 없어요. 재확인에서 '조사할 것'으로 넘길 수 있어요."
- 상품 카드 (기본 다섯 가지): 이름·한 줄 설명 / 이럴 때 써요 / 비용 / 난이도(★) / 추천 이유. 조건 배지(무료, 초보 추천, 공식, 실시간·자주 갱신, 주의). "자세히"를 누르면: 제공, 필요한 자격, 실시간 여부, 키 노출 위험, 라이선스, 필요 개념, 프롬프트 조각, 예상 막힘, 확인한 때, 링크.
- "담기"를 누르면 M3: 상품 카드에서 작은 상자가 장바구니 칸으로 날아가고 칸에 확인 표시, 주행 거리 증가. 이미 담은 상품이 다른 칸도 맡으면 그 칸에 "이 칸도 맡아요: ○○"와 확인 표시.
- 필수 칸을 모두 채우면 '장보기' 도장.
- 아래 진행 막대: "재확인하러 가기" (필수 칸이 비어 있어도 갈 수 있다. 재확인에서 다룬다).

### 3.5 재확인 `/check`

- "이렇게 이해했어요": 답 칩 요약, 담은 상품 목록(칸별), 칸 밖 상품.
- 코딩 없이 되는 방법이 있으면 한 줄 (유형 문장 틀의 `alternative`).
- 충돌 목록: 충돌마다 신호등(M6) + 문장 + 고치는 법 + 두 버튼 **바꾸기**(장보기의 그 칸으로) / **그대로 두고 조사할 것에 추가**. 고르면 초록불. `keepable`이 false인 충돌(빈 화면 칸)은 '그대로 두기' 버튼이 없다. 충돌이 없으면 신호등 하나가 바로 초록.
- 모든 불이 초록이면 기사님이 "출발 준비 끝났어요."라고 말하고 '재확인' 도장.
- 1차/2차 나누기 (`split.needed`): "오늘 다 하기엔 길이 멀어요. 1차는 여기까지 갈까요?"
  - 미룰 수 있는 칸(`split.defer`)을 고르게 한다.
  - 더 쉬운 상품(`split.easier`)이 있으면 "○○ 대신 △△로 바꾸면 가까워져요"와 바꾸기 버튼.
  - 둘 다 없으면: "이대로 가도 괜찮아요. 시간이 더 걸릴 뿐이에요."
- 주 버튼: "영수증 뽑기" (`canIssue`일 때만 켜짐. 꺼져 있으면 이유를 글로).

### 3.6 계산대 `/receipt`

- 장면 M4: 영수증이 프린터에서 위에서 아래로 뽑혀 나오고(2.2초 이하), 끝에 "코드쇼퍼 · 요금 0원" 도장이 쾅. 처음 보는 영수증이면 색종이 한 번(1.2초), 기사님 축하 말풍선 "도착했습니다! 영수증 챙겨 가세요.", '계산대' 도장. 누르면 바로 끝까지 나온다.
- 탭 네 개: **영수증** / **설계 꾸러미** / **공부할 것** / **대화 카드**
  - 영수증: 고정폭 글꼴(D2Coding)로 그린 종이. 아래 버튼: 영수증 복사, 공유 링크 복사, **PC로 보내기**(Web Share, 안 되면 링크 복사 + 메일).
  - 설계 꾸러미: 미리 보기(접힌 마크다운) + **복사** + **.md 내려받기**(`design-pack-YYYYMMDD-HHmm.md`). 한 줄 안내: 고른 AI에 맞는 `saveAs` 문장.
  - 공부할 것: 시작 전 필수(최대 3개, "10분이면 돼요") + 단계별 개념 목록. → `/study`
  - 대화 카드: 다섯 장, 카드마다 언제 쓰는지 + 복사 버튼. 복사하면 "복사했어요" (화면 낭독기에도 알림).
- 준비물(오래 걸리는 것 먼저)과 예상 막힘 요약을 영수증 아래에 접어 둔다.
- 면책 한 줄: "'조사할 것'은 법률 자문이 아니에요. 상품 정보는 확인한 때 기준이에요."
- 맺음말: "영수증 챙겨 가세요. 막히면 언제든 사전을 여세요."
- 공유 링크로 열었을 때: 주소의 `#r=`를 읽자마자 `history.replaceState`로 주소에서 지운다. 링크의 영수증은 읽기 전용으로 보여 주고, "이 영수증으로 이어 하기"를 누르면 (지금 상태와 다를 때만 물은 뒤) 저장한다. 링크가 깨졌거나 발행할 수 없는 상태면 "링크가 깨졌어요"와 홈 버튼.
- 이 화면에는 Cloudflare Web Analytics 스크립트를 싣지 않는다 (주소에 공유 상태가 잠깐이라도 있으므로).

### 3.7 공부 `/study`, 개념 카드 `/concepts/[id]`

- 공부: 시작 전 필수 → 단계별 순서. 개념마다 읽음 표시, 확인 문제 정답 수.
- 개념 카드: 제목, 다른 이름, 3분 설명, 그림(설명 글은 alt), 해 보기 모형(있으면), 확인 문제 2~3개(고르면 바로 정답과 풀이), "내 AI에게 배우기" 문장(복사, `{{project}}` 자리에 이용자가 만들 것, 없으면 "내 앱"), 관련 상품.
- 해 보기 모형 다섯 가지는 진짜 키나 서버를 쓰지 않는 연습 화면이다:
  - env-var-form: 이름 칸과 값 칸에 가짜 키를 넣으면, 코드 미리 보기에는 `env.API_KEY`처럼 이름만 남는다.
  - api-key-form: 가짜 키를 '화면 코드'와 '비밀 보관함' 중 어디에 둘지 고르고, 화면 코드를 고르면 브라우저 개발자 도구에서 키가 보이는 그림을 보여 준다.
  - json-reader: 급식 API 응답 예시에서 항목을 누르면 이름표와 값을 풀어 준다.
  - terminal-sim: 정해진 명령 몇 개(`node -v`, `npm -v`, `npm run dev`)에만 답하는 가짜 터미널.
  - deploy-sim: 파일 올리기 → 빌드 → 주소 생김을 세 단계로 따라가는 그림.
- 확인 문제를 맞히면 작은 도장 (M7), 필수 개념을 모두 읽으면 '공부' 도장. 도장판은 설정의 '내 여행 기록'과 홈에서 본다.

### 3.8 진열대 `/shelf`, 상품 상세 `/products/[id]`

- 코너: 분야(학교·교육, 날씨…)와 기능(화면, 저장, 배포·공유…) 두 갈래 거르기. 검색창은 T15에서 사전과 같은 색인으로 붙인다.
- 상품 상세 페이지는 진열 상품만 만든다. 카드의 모든 항목 + "이 상품이 들어간 레시피".
- 색인 상품은 목록에서만 보이고, 원문 링크와 정해진 항목만 보여 준다.

### 3.9 레시피 `/recipes`

- 카드: 제목, 누구에게, 한 줄 설명, 담긴 상품, 난이도·예상 시간.
- "이 레시피로 출발": 답·장바구니·그대로 둔 충돌·한 줄 입력(`freeText`)을 채우고 `/check`로. 기존 진행이 있고 다르면 바꿀지 먼저 묻는다.

### 3.10 사전 (옆 창, `/dictionary`)

- 검색창 하나. 결과는 묶음으로: 용어(개념 카드), 에러, 예상 막힘, 상품.
- 에러 문장을 붙여 넣으면 맞는 에러 안내를 맨 위에. 없으면 질문 틀(`templates.errorFallback`)과 복사 버튼.
- 에러 안내 카드: 뜻, 흔한 원인, 먼저 해 볼 것, 내 AI에게 물어볼 말(복사), 관련 개념. "키 값은 지우고 붙여 넣으세요" 안내.

### 3.11 소개 `/about`, 추천 공식 `/about/scoring`, 법 `/legal/*`, 404

- 소개: 무엇을 하고 무엇을 하지 않는지, AI를 쓰지 않는 이유, 자료는 누구나 고칠 수 있다는 것(저장소 링크), 광고·제휴가 없다는 것.
- 추천 공식: `scoring.json`의 값을 그대로 표로. 항목 설명은 `docs/ENGINE.md` 3절을 쉬운 말로.
- 개인정보 처리방침·이용 안내: 초안을 만들고 맨 위에 "검토 중" 표시. 최종 문구는 사람이 확인한다.
- 404: "길을 잘못 들었어요. 처음 화면으로 모실게요." (홈 버튼)

## 4. 모션

기술층(무엇으로 만드나)은 `docs/DECISIONS.md` D25·D26과 `game-motion` 스킬: CSS 전환·키프레임·`@starting-style`·`offset-path`·CSS 3D·문서 간 View Transitions가 기본이고, 직접 쓴 `src/lib/motion.ts`(약 2KB)가 순서·건너뛰기를 맡는다. 라이브러리는 계산대의 색종이(`canvas-confetti`, 지연 로드) 하나뿐이다. 길이·곡선은 `src/styles/tokens.css`의 변수를 쓴다.

| 번호 | 장면 | 무엇이 움직이나 | 길이 | 동작 줄이기일 때 |
|---|---|---|---|---|
| M1 | 노선도 | 정류장이 바뀌면 차가 앞 정류장(홈에서 왔으면 출발점) 자리에서 길을 따라 이번 정류장으로 오고, 지나온 구간이 같이 금빛으로 칠해진 뒤 핀이 톡 튄다. 머리말은 페이지 전환 동안 제자리이고, 차는 전환이 끝난 새 페이지에서 달린다(전환 중에는 화면을 누를 수 없어서, D49) | 800ms(`--dur-move`), ease-in-out + 핀 300ms | 차가 바로 그 정류장에, 구간 바로 칠함 |
| M2 | 차 문·기사님 | 차 문이 열리고(CSS 3D) 기사님이 손을 흔들며 나타나 말풍선 | 800ms 이하 | 문 열린 정지 그림, 말풍선 바로 |
| M3 | 담기 | 상품 카드에서 작은 상자가 호를 그리며 장바구니 칸으로 날아가고 칸에 확인 표시, 칸이 한 번 통통 | 550ms(`--dur-fly`) + 300ms | 확인 표시만 바로 바뀐다 |
| M4 | 영수증 출력 | 종이가 위에서 아래로 뽑혀 나온 뒤 도장이 쾅, 처음이면 색종이 | 출력 2.2초 이하 + 도장 250ms + 색종이 1.2초 | 다 나온 영수증과 도장이 바로, 색종이 없음 |
| M5 | 인터뷰 카드 | 답할 때마다 바뀐 후보 카드가 뒤집힌다 (CSS 3D) | 400ms | 짧은 페이드로 바뀐 결과만 |
| M6 | 신호등 | 충돌마다 불이 켜지고, 해결하면 초록불. 충돌 항목은 한 번 살짝 흔들림 | 불 하나 350ms 이상, 흔들림 250ms | 색과 아이콘·글만 바뀐다 |
| M7 | 도장·정류장 열림·주행 거리 | 도장이 찍히고, 정류장 자물쇠가 열리며 핀이 톡 튀고, 주행 거리 숫자가 굴러간다 (모두 그 화면 안에서 바뀔 때만. 페이지를 열 때 이미 있던 값은 그대로 보인다) | 도장 250ms, 핀 300ms, 숫자 600ms | 값과 도장이 바로 |
| M8 | 홈 출발 장면 | 원근으로 기운 도로 위를 차가 달려와 멈춘다 (차선 흐름, 길가 시차) | 2~3초 (M2 포함 3초 이하) | 정지 그림 |
| — | 기사님 | 등장 때 한 번 통통, 누르면 살짝 찌그러짐, 도착 때 한 번 깡총 | 각 300ms 안쪽 | 정지 |
| — | 페이지 전환 | 문서 간 View Transitions: 머리말·노선 띠는 그대로, 무대만 바뀜 | 250ms 안쪽 | 전환 없음 |

지킬 선:
- 모션 하나는 1초 안쪽, 공들인 장면도 3초 이하. 모션 중에도 화면을 누르거나 Esc·"건너뛰기" 버튼으로 끝 상태로 건너뛴다.
- 모션이 끝나기를 기다려야 다음 행동을 할 수 있게 만들지 않는다. 5초 넘게 스스로 움직이는 것(끝없는 반복)은 두지 않는다.
- 움직임이 알려 주는 것(위치, 바뀐 것)은 글자로도 알린다 (화면 낭독기용 `aria-live`).
- 번쩍임은 초당 3번 미만.
- 동작 줄이기(기기 설정과 사이트 설정 둘 다): 이동·확대·시차·흔들림·색종이를 없애고, 바뀐 것을 보여 주는 짧은 페이드(`--dur-fade`, 150ms 이하)만 남긴다 (D30).
- 자주 하는 조작(보기 고르기, 칸 펼치기)은 300ms 안쪽의 가벼운 전환. 공들인 장면은 드문 순간(도착, 영수증, 도장)에만.

### 효과음 (기본 꺼짐)

설정에서 켜면 짧은 합성음을 낸다 (소리 파일 0KB, D28): 누르기(톡), 담기(뿅), 정류장 도착(딩동), 신호 초록(삐빅), 도장(쿵), 영수증 출력(드르륵), 축하(빰빠밤, 1초 안쪽). 소리만으로 뜻을 전하지 않는다.

## 5. 시각 요소

- 색·글꼴·크기·모서리·그림자·모션 길이는 `src/styles/tokens.css`만 쓴다. 새 색이 필요하면 토큰을 먼저 더하고 대비를 확인한다.
- 금색(`--taxi`)은 밝은 바탕에서는 채움으로만 쓰고 그 위 글자는 `--ink`. 남색(`--navy`) 바탕 위에서는 글자로도 쓴다 (전광판).
- 차와 정류장, 노선도 그림은 직접 그린 단순한 SVG로 만든다. 실제 차 브랜드, 로고, 남의 캐릭터를 닮게 그리지 않는다.
- 기사님(마스코트)은 1단계부터 쓴다. 소유자가 준 그림(`src/assets/mascot/`)만 쓰고, 새 자세는 `docs/HUMAN.md` M02로 요청한다. 쓰는 곳과 움직임은 `docs/DESIGN.md` 6절.
- 정류장·칸·보상 아이콘은 Fluent Emoji 3D 그림(128px webp), UI 아이콘은 Phosphor SVG (D27).
- 영수증은 흰 종이(`--receipt`)에 D2Coding, 아래쪽 톱니 모양 가장자리.
- 그림 보기의 그림은 Fluent 3D 그림 문자, '느낌'은 자료의 색 견본이다 (D44). 버튼 안 그림은 장식(`alt=""`)이고 보기 이름이 뜻을 전한다. `questions.json`의 `alt`는 그림만 따로 보일 때 쓴다.

## 6. 접근성 확인표

- [ ] 모든 기능을 키보드만으로 쓸 수 있다. 초점 테두리가 늘 보인다 (`--focus`, 어두운 바탕은 `--focus-on-dark`).
- [ ] 누르는 곳은 44×44px 이상.
- [ ] 글자 대비 4.5:1 이상, 큰 글자·아이콘·입력 칸 테두리 3:1 이상.
- [ ] 그림 보기와 그림에 대체 텍스트. 장식 그림은 `alt=""`.
- [ ] 보기를 고르는 것만으로 화면이 바뀌는 곳은 버튼으로 만들고, 화살표 키 이동만으로는 바뀌지 않는다.
- [ ] 화면이 바뀌면 제목으로 초점을 옮기고 페이지 제목(`<title>`)을 바꾼다.
- [ ] 복사·담기·충돌 해결 같은 결과를 `aria-live`로 알린다.
- [ ] 옆 창·대화 상자는 열 때 안으로 초점, Esc로 닫기, 닫으면 원래 자리로 초점.
- [ ] 글자 크기 200%에서도 내용이 잘리지 않는다.
- [ ] '동작 줄이기'(기기 설정과 사이트 설정 모두)를 따른다. 줄이기에서도 끝 상태가 바로 보인다.
- [ ] 모든 장면을 누르기·Esc·"건너뛰기" 버튼으로 끝낼 수 있고, 장면 중에도 버튼이 눌린다.
- [ ] 효과음은 기본 꺼짐이고, 소리 없이도 모든 결과를 알 수 있다.
- [ ] 주행 거리·도장은 글로도 읽힌다 (`role="progressbar"`의 값 글, 도장 이름).
- [ ] 기사님 말풍선은 그림 속 글이 아니라 진짜 글이고, 접을 수 있으며 화면을 가리지 않는다.
- [ ] 색만으로 뜻을 전하지 않는다 (충돌은 색 + 아이콘 + 글).
- [ ] axe 자동 검사에서 심각(serious)·치명(critical) 0개.
