# 안 B: 길 지도: 고를 때마다 자라는 내 앱 지도

## 1. 컨셉 한 줄 + 세계관

**한 줄**: 답할 때마다 내 앱의 작은 지도가 자라고, 경유지마다 도구를 고르면 길이 이어진다. 길이 다 이어지면 코드쇼퍼의 차가 그 길을 한 번 달려 목적지에 닿는다. 차는 손님에게 영수증(요금 0원)과 그 길을 글로 옮긴 설계도를 건넨다.

| 세계 안 | 실제 | 화면에서 |
|---|---|---|
| **손님** | 이용자 (교사·직장인·대학생) | 사람 그림은 그리지 않는다. 손님은 지도를 위에서 내려다보는 '나'다. 시점은 미니 모터웨이처럼 위에서 본다. |
| **코드쇼퍼 (기사)** | 이 서비스 | 남색 차 한 대가 캐릭터를 대신한다. 지붕에 금빛 표시등, 앞에 전조등 둘이 있고 표정은 불빛으로 낸다. 도착하면 전조등을 두 번 깜빡이고, 손님을 기다릴 때는 깜빡이를 두 번 켠다. 말은 화면의 안내 한 줄(모시는 해요체)로만 한다. 얼굴이 없으니 마스코트 그림이 없어도 성립한다. |
| **차고** | 처음 화면, 시운전 자리 | 지도 왼쪽 아래. 차는 여기서 출발한다. |
| **목적지** | 내가 만들 앱 | 지도 오른쪽 위의 건물과 금빛 깃발. 유형마다 모양이 다르다: 기록장=작은 서재, 신청서·설문=우체국, 안내 페이지=안내탑, 퀴즈=작은 학교, 도구=공방, 현황판·알림=시계탑. 한 줄 입력을 쓰면 깃발 이름표가 된다 (내 브라우저에만 남는다). |
| **손님 집** | 앱을 쓸 사람 | 목적지 둘레의 집. 나만=한 채, 몇 명이 같이=세 채, 아무나=골목 하나. |
| **경유지** | 앱에 필요한 기능(칸) | 길 위의 마디. 기능마다 모양과 색이 정해져 있다 (4절). |
| **도구** | 그 기능을 맡을 서비스(상품) | 경유지에 세우는 건물. 고르면 빈 마디가 도구 이름표를 단 건물로 바뀐다. |
| **길** | 기능 사이의 연결 | 도구를 고르면 앞 경유지와 길이 이어진다. 다 이어진 길이 '내 노선'이다. |
| **터널** | 키를 숨기는 중간 서버 | 외부 데이터에서 배포로 가는 길이 언덕 밑으로 들어간다. 키가 바깥에 드러나지 않는다는 뜻이다. |
| **보호 구역** | 개인정보를 받음 | 저장 경유지 둘레의 빗금 구역. 학생 정보는 빨간 빗금(어린이 보호구역처럼), 그 밖의 개인정보는 노란 빗금. |
| **신호** | 맞물림 점검(충돌) | 막힌 곳마다 갈림목에 빨간불이 켜진다. 고치거나 그대로 두기로 하면 초록불로 바뀐다. |
| **공사 예정** | 2차로 미룬 기능 | 점선 길과 고깔. |
| **답사 깃발** | 그대로 두기로 한 막힌 곳 | 물음표 깃발. 만들기 전에 내 AI와 먼저 알아볼 곳이다. |
| **표지판** | 개념 카드 | 길가에 선 표지판. 그 개념이 필요한 경유지 앞에 꽂힌다. |
| **영수증** | 텍스트 영수증 | 도착하면 뽑히는 감열지. 요금 0원. 화면에서는 맨 위에 내 노선이 검은 선으로 찍힌다. |
| **설계도** | 설계 꾸러미(.md) | 지도를 글로 옮긴 것. 내 AI가 설계도를 읽고 같은 길을 경유지 순서대로 실제로 짓는다. |

**이야기**: 코드쇼퍼는 손님을 앱까지 모시는 기사다. 코드를 대신 쓰지는 않는다 (R-01). 손님이 목적지를 말하면 함께 길을 짜고, 출발 전에 신호를 점검하고, 짠 길을 한 번 달려 보인다. 그다음 그 길을 설계도로 건넨다. 실제 공사는 손님의 AI가 설계도대로 한다. 이 이야기는 '사이트는 판단만, 구현은 내 AI'라는 제품의 사실과 그대로 맞는다.

- **이름 풀이**: 쇼퍼는 모시는 기사(chauffeur)이면서, 경유지마다 들러 도구를 고르는 사람(shopper)이기도 하다. '장보기'라는 말은 버리지만 '들러서 고른다'는 행동에 말장난이 남는다.
- **슬로건은 둘 다 그대로 둔다.** 첫 화면은 "어디로 모실까요? 요금은 0원입니다.", 소개는 "코드는 몰라도 됩니다. 목적지만 말하세요."이다. 새 슬로건은 만들지 않는다. 도착 화면에 짝 문장 하나만 더한다: **"도착했습니다. 요금은 0원입니다."** 첫 질문과 마지막 인사가 짝을 이룬다.
- **지도는 모든 화면에 나오는 같은 물건이다.**
  - 홈: 본보기 동네(다시 온 사람에게는 자기 지도)
  - 시운전: 차고 옆 연습 고리
  - 목적지: 지도가 자라기 시작한다
  - 경유지: 길이 이어진다
  - 점검: 신호가 켜진다
  - 도착: 차가 달린다
  - 본보기 지도·내 지도책·공유 링크·영수증 머리에도 같은 규칙으로 그린 같은 지도가 나온다.

## 2. 여정 단계 표

소리 내어 읽으면 이렇다. **시운전 → 목적지 → 경유지 → 점검 → 도착.**
카카오 T·내비에서 누구나 아는 순서(목적지를 먼저 넣고 경유지를 더한다)가 가운데에 있다. 그 앞에 연습 운전이, 그 뒤에 출발 전 점검과 도착이 붙는다. 다섯 개를 묶는 말은 '정류장' 대신 쉬운 말 **단계**로 쓴다.

| 지금 | 새 이름 | 주소 | 거기서 하는 일 | 지도에서 일어나는 일 | 앞뒤와 이어지는 까닭 |
|---|---|---|---|---|---|
| 첫 수업 | **시운전** | `/test-drive` | 10분 동안 AI 채팅에 문장 세 개(만들기·고치기·열기)를 붙여 넣어 웹페이지 한 장을 만든다. 건너뛸 수 있다. | 차고 옆 작은 고리 길에 점이 셋 있다. 단계를 마칠 때마다 점이 채워지고, 다 마치면 차가 고리를 한 바퀴 돈다. 단계 레일에서는 본선 밖 곁가지 고리로 그린다. 건너뛰면 고리가 점선으로 남는다. | 본 운행 전에, 앞으로 할 운전(AI에게 말로 시키기)을 한 번 해 본다. |
| 인터뷰 | **목적지** | `/destination` | 질문 17개 안팎에 답한다. 첫 질문은 "어디로 모실까요?". 마지막은 목적지 이름 한 줄(선택). | 첫 답에 목적지 건물이 선다. 누가 쓰나에 답하면 집이 생긴다. 저장·로그인·외부 데이터·알림 답에는 빈 경유지(점선 마디)가 생긴다. 개인정보 답에는 보호 구역이 생기고, 느낌을 고르면 지도 색이 바뀐다. 지금의 '좁혀지는 중' 상자를 지도가 대신한다. | "목적지만 말하세요"를 그대로 하는 단계다. 여기서 생긴 빈 마디가 다음 단계의 할 일이 된다. |
| 장보기 | **경유지** | `/waypoints` | 빈 경유지마다 도구를 하나 고른다. 추천·차선책·이유를 보고 '고르기'를 누른다. | 빈 마디가 도구 건물로 바뀌고 앞 마디와 길이 이어진다. 한 도구가 두 경유지를 맡으면 두 마디가 같은 색 띠로 묶인다. 중간 서버가 있으면 터널이 생긴다. | 목적지가 정해졌으니 가는 길에 들를 곳을 정한다. |
| 재확인 | **점검** | `/inspect` | '이렇게 이해했어요' 요약을 본다. 막힌 곳마다 '길 바꾸기'나 '그대로 두고 답사하기'를 고른다. 길이 멀면 1차·2차를 나눈다. | 막힌 길에 빗금과 빨간불이 켜진다. 고치면 초록불, 2차로 미루면 점선과 고깔이 된다. 그대로 둔 곳에는 답사 깃발이 꽂힌다. 모두 초록이면 '출발하기'가 켜진다. | 달리기 전에 신호부터 본다. 운전의 당연한 순서다. |
| 계산대 | **도착** | `/arrival` | 영수증, 설계도, 표지판, 답사할 곳, AI에게 할 말을 받는다. 공유 링크(`#r=`)도 이 주소에 붙는다. | 차가 다 이어진 길을 한 번 달린다. 지나는 마디마다 금빛 고리가 생기고, 목적지 창에 불이 켜지며 깃발이 오른다. | 말한 목적지에 닿고 요금(0원)을 낸다. 그리고 그 길을 글로 옮긴 설계도를 들고 내 AI에게 간다. |

열리는 조건은 지금 규칙(UX 2.1) 그대로이고, 말만 바뀐다.
- 경유지·점검: 목적지를 마치면 열린다 ("목적지를 정하면 길이 열려요.").
- 도착: `canIssue`일 때 열린다 ("점검에서 막힌 곳을 풀면 출발할 수 있어요.").

나머지 화면도 이름을 바꾼다. 아직 배포 전이라 옛 주소에서 옮겨 보내는 처리는 두지 않는다.

| 지금 | 새 이름 | 주소 |
|---|---|---|
| 진열대 `/shelf`, 상품 상세 `/products/[id]` | 도구 도감 | `/tools`, `/tools/[id]` |
| 공부 `/study` + 개념 카드 `/concepts/[id]` | 표지판 (내 길의 표지판이 먼저, 그 아래 20개 모두) | `/signs`, `/signs/[id]` |
| 사전 `/dictionary` | 사전 (안에 '에러 정비소' 묶음) | `/dictionary` |
| 레시피 `/recipes` | 본보기 지도 | `/examples` |
| 내 여행 기록 (설정 안 대화 상자) | 내 지도책 (화면 하나) | `/atlas` |
| 소개·추천 공식·크레딧·법·404 | 그대로 | 그대로 |

## 3. 용어 사전

'쉬운 말'에 ●가 있으면 세계관보다 뜻이 분명한 쪽이 이겨서 평범한 말로 남긴 것이다.

| 지금 | 새 말 | 이유 한 줄 | 쉬운 말 |
|---|---|---|---|
| 정류장 (다섯 곳 묶음) | **단계** | 묶음 이름은 뜻이 분명해야 한다. 장소의 느낌은 다섯 이름이 맡는다. | ● |
| 첫 수업 · 인터뷰 · 장보기 · 재확인 · 계산대 | **시운전 · 목적지 · 경유지 · 점검 · 도착** | 한 번의 운행을 이루는 말들이라 차례가 저절로 읽힌다. | |
| 노선 띠 / 행선지 전광판 "이번 정류장: ○○" | **단계 레일** (낭독 이름 "진행 단계"). 전광판은 없앤다. | 지금 위치는 레일이, 상황은 지도가 보인다. 같은 말을 세 번 보이던 머리말(약 190px)을 100px로 줄인다. | |
| 주행 거리 km · 계기판 | 없앤다 → **"경유지 4곳 중 3곳 연결"** | km는 아무것도 재지 않는 숫자였다. 이어진 경유지 수는 남은 일을 그대로 알려 준다. | |
| 도장 (단계 도장) | **단계 완료 표시**(레일의 ✓)와 **지도에 생긴 변화** | 도장은 길 세계와 따로 놀았다. 보상은 자라는 지도 자체다. | |
| 공부 도장 · 확인 문제 도장 | **표지판 익힘**. 읽으면 색이 채워지고, 문제를 맞히면 테두리가 금색이 된다. | 모으는 재미를 개념 카드의 모양 안에 넣는다. | |
| 내 여행 기록 | **내 지도책** | 영수증을 뽑은 지도가 한 장씩 쌓이는 진짜 기록이다. | |
| 잠김 · 자물쇠 | **아직 길이 없어요** (점선 길 + 이유 글 "목적지를 정하면 열려요.") | 자물쇠 대신 아직 나지 않은 길로 보인다. 이유는 늘 글로 쓴다. | |
| 장바구니 · 담은 상품 | **고른 도구** (지도에 선 건물) | 지도 자체가 장바구니다. 목록 이름은 하는 일 그대로 쓴다. | ● |
| 칸 (slot) | **경유지** (예: 저장 경유지) | 기능이 '들러야 할 곳'이 되어 지도 위 마디와 같은 말이 된다. | |
| 필수 칸 / 선택 칸 | **필수 / 선택** (경유지 이름 옆) | 꾸밀 필요가 없는 구분이다. | ● |
| 상품 · 진열 상품 · 색인 상품 | **도구 · 도감에 실린 도구 · 색인 도구** | '상품'은 돈 주고 사는 느낌이라 0원 서비스와 맞지 않는다. 앱 재료로는 '도구'가 바로 알아듣힌다. '색인'은 그대로 둔다. | ● |
| 담기 / 빼기 | **고르기 / 빼기** | 지도 위에 세우는 동작을 가장 쉬운 동사로 쓴다. | ● |
| 추천 | **추천** | 지도 앱의 '추천 경로'와 같은 말이다. | ● |
| 2위 | **차선책** | 흔히 쓰는 말이고, '차선(찻길)'과 겹치는 말맛이 길 세계와 맞는다. | |
| 난이도 ★ | **난이도: 쉬움·보통·어려움** + 언덕 그림(평지·언덕·고개) | 낱말은 그대로 두고 그림만 지형으로 바꾼다. | ● |
| 무료 / 유료, 비용 합계 0원 | **무료 / 유료** (유료에는 요금소 그림), 합계는 **요금 0원** | 비용 낱말은 분명하게 둔다. 합계만 "요금은 0원입니다"와 맞춘다. | ● |
| 충돌 | **막힌 곳** | 지도에서 실제로 길이 막혀 보인다. '충돌'보다 덜 겁난다. | |
| 신호등 | **신호** (빨간불·초록불) | 이미 쉬운 말이고 세계에도 맞는다. | ● |
| 바꾸기 / 그대로 두고 조사할 것에 추가 | **길 바꾸기 / 그대로 두고 답사하기** | 버튼 글자만 보고도 결과(경유지로 돌아감, 답사 깃발)를 알 수 있다. | |
| 예상 막힘 (stuck) | **주의 구간** | 도로의 '사고 잦은 곳' 표지처럼, 처음 하는 사람이 자주 걸리는 곳이다. '막힌 곳'과 헷갈리지 않는다. | |

### 색

### 글꼴

- 쓰는 글꼴은 Pretendard Variable과 CC Receipt 둘뿐이다.
  - **Pretendard Variable**: 모든 화면 글자와 지도 이름표.
  - **CC Receipt**(D2Coding 조각): 영수증과 '요금 0원' 칩에만. 전광판이 없어지니 고정폭 글꼴은 '돈과 종이'에만 남는다.
- 크기와 굵기
  - 큰 제목 32px/800, 자간 -0.02em
  - 화면 제목 24px/800
  - 본문 17px, 줄 간격 1.6, `keep-all`
  - 보조 글 14px
  - 숫자는 `tabular-nums`
- **지도 이름표**: 14px/700. 땅색 3px 테두리(`paint-order: stroke`)로 길 위에서도 읽힌다. 8자를 넘으면 지도에서는 줄이고, 온전한 이름은 시트에 쓴다. 이를 위해 상품 자료에 선택 칸 `shortName`(8자 이하)을 더한다.
- **글자 상표**: '코드쇼퍼' Pretendard 800에, '쇼' 위에 금빛 점(지붕등) 하나를 붙인다.

### 모양 말

- **지도**
  - 24px 격자 위에 그린다.
  - 길은 45°·90°만 쓴다. 굽는 곳 반지름 12, 이음과 끝은 둥글게.
  - 빈 길 10px, 내 노선 6px + 2px.
  - 건물은 모서리 4px의 둥근 덩어리이고, 남동쪽으로 2·3px 비스듬한 그림자를 둔다 (흐림 없음, 빛은 늘 왼쪽 위에서).
  - 땅·물·공원에는 테두리가 없다.
- **화면 틀**
  - 모서리: 카드 12, 시트 20, 칩은 알약 모양.
  - 테두리는 1px 선. 그림자는 시트 하나에만 위쪽으로 둔다.
  - 그라데이션·유리 흐림·카드마다 깐 그림자는 쓰지 않는다.
  - 주 버튼은 높이 56px, 금색 채움.

### 깊이와 3D

- **지도는 위에서 내려다본 평면에 짧은 비스듬 그림자를 더한 방식(2.5D)으로 정한다.** 아이소메트릭은 360px에서 이름표가 겹치고 길이 읽히지 않아 쓰지 않는다.
- 카메라 기울기는 두 순간에만 쓴다: 홈 첫 운행의 끝, 도착 운행. CSS `perspective` + `rotateX(24deg)`, 400ms.
- 3D 렌더는 지도 밖의 '가까이 보기' 자리에만 둔다: 목적지 그림 보기 카드, 본보기 지도 표지, 도착 화면 머리.
  - 소유자가 준 Tripo3D 모델을 우리 렌더 틀로 같은 빛, 같은 각도, 같은 팔레트로 굽는다 (7절).
  - 받기 전에는 지도와 같은 SVG 건물을 크게 쓴다.

### 아이콘 체계

- 아이콘은 세 갈래로 나눈다.
  1. **지도 그림 문자**(직접 그림): 24px 격자, 같은 그림자 규칙. 경유지 6, 목적지 6, 집 3, 차, 신호, 터널, 요금소, 보호 구역, 고깔, 답사 깃발, 차고, 다리.
  2. **표지판**(직접 그림): 20개 개념을 세 종류로 나눈다.
     - 주의 표지(빨간 테두리 세모): API 키, 환경 변수, CORS, 무료 한도, HTTPS
     - 지시 표지(파란 동그라미): 배포, 터미널, 커밋, npm 패키지, 개발자 도구, 로그
     - 안내 표지(초록 네모): API, JSON, 데이터베이스, 서버, 프런트엔드·백엔드, 저장소, 도메인, localhost, 로그인
     - 모양은 일반 도로 표지판의 틀만 빌리고, 안의 그림은 우리가 새로 그린다.
  3. **화면 아이콘**: Phosphor Regular 24px(닫기·복사·뒤로·설정·소리). duotone을 버리고 선 하나로 통일한다.
- **Fluent 3D 그림 문자는 모두 뺀다.** 평면 지도와 그림체가 부딪히고, 흔한 그림 문자로 보여 싸 보인다.

### 배치와 플랫폼 패턴

- **맨 위 막대** 56px: 흰 바탕, 붙박이 아님(D41 유지). 왼쪽에 글자 상표, 오른쪽에 '사전'(아이콘+글)과 설정. 사전 버튼을 위로 올려 아래 막대를 주 버튼에 다 준다.
- **단계 레일** 44px, 작업 화면만:
  - 다섯 이름을 가는 선으로 잇는다.
  - 지금 단계는 남색 알약에 흰 글자.
  - 마친 단계에는 작은 ✓, 아직 못 가는 단계는 회색 글자와 점선.
  - 시운전은 본선 왼쪽의 작은 고리로 그린다.
- **지도 캔버스 + 시트** (카카오맵 방식)
  - 360px: 지도는 위에서 가장자리까지 꽉 차게 둔다. 높이는 화면마다 다르다: 목적지 168, 경유지·점검 232, 도착 280.
  - 시트는 지도 아래 24px을 덮고 올라온다(윗모서리 20px). 끌어 올리는 패널이 아니라 문서 흐름이다. 접근성과 단순함 때문이다.
  - 768px: 지도 320px.
  - 1024px 이상: 왼쪽 시트 440px만 스크롤되고, 오른쪽 지도는 화면 높이만큼 붙박이로 둔다.
- **아래 막대**(붙박이, 작업 화면만): 위 20px에 미니 노선(경유지 모양이 채워짐 + "경유지 4곳 중 3곳 연결"), 아래에 주 버튼 52px. 시트를 내려 지도가 안 보여도 고른 결과가 여기서 보인다.
- **출발·경유·목적지 카드**: 경유지와 점검 시트 머리에 둔다. 경유는 가로 칩 줄이고, 칩을 누르면 그 경유지가 펼쳐진다.
- **도구 고르기 = 경로 고르기 카드**
  - 맨 위 카드는 '추천' 칩과 금빛 옅은 바탕.
  - 칩: [무료] [쉬움] [공식] [자주 갱신]
  - 이유 한 줄, 차선책 비교 한 줄.
  - 버튼: '자세히' / '고르기'.
- **지도 접근성**
  - 지도는 `role="img"`에 요약 글을 단다. 예: "목적지 체험학습 신청서. 경유지 4곳 중 3곳 연결. 막힌 곳 1곳."
  - 실제 조작은 시트의 HTML 목록이 맡는다.
  - 지도 마디를 누르는 것은 손가락용 지름길(44px)이다. 같은 일을 칩이 하므로 탭 순서에는 넣지 않는다.

## 5. 대표 장면

새 길이 토큰을 더한다:
- `--dur-draw` 400ms: 길 그리기
- `--dur-pop` 300ms: 건물 솟기
- `--dur-run` 1800ms: 도착 운행
- `--dur-tilt` 400ms: 카메라 기울기
- `--dur-palette` 300ms: 지도 색 바꾸기
- `--dur-print` 2200 → 900ms로 줄인다

모든 장면은 화면 어디든 누르거나 Esc를 누르면 끝 상태로 간다(D49 그대로). 장면 중에도 버튼은 눌린다. 움직임이 알리는 것은 `aria-live`로도 읽힌다. 장면은 그 지도에서 처음 일어날 때만 다 보이고, 다시 열면 끝 상태로 보인다.

## 6. 게임 층

**진행**: 진행은 숫자가 아니라 **지도**로 보인다.
- 빈 마디 수가 남은 일이고, 이어진 길이 한 일이다.
- 레일은 지금 단계를 보이고, 아래 막대는 "경유지 4곳 중 3곳 연결"을 보인다.
- 모두 저장된 상태에서 계산한다 (D32 원칙 유지). `progress.ts`의 km는 연결 수와 단계 완료로 바꾼다.

**보상**
1. **완성된 지도**: 도착 장면에서 목적지에 불이 켜진다. 내가 고른 것들이 한 장의 그림이 된다.
2. **내 지도책** (`/atlas`)
   - 영수증을 뽑은 지도가 썸네일로 쌓인다.
   - 한 장에는 공유 링크 문자열, 목적지 유형, 날짜만 담는다 (`cc:atlas:v1`, `store.ts` 안). 최대 30장이고, 넘치면 가장 오래된 것을 빼면서 그렇다고 알린다.
   - 누르면 그 영수증이 다시 열린다. 지금은 한 브라우저에 하나만 남던 결과를 다시 찾을 수 있게 되는, 쓸모 있는 보상이다.
3. **표지판 모음**: 20개 표지판이 세 종류 모양으로 한 판에 놓인다. 읽은 것은 색이 채워지고, 맞힌 것은 금 테두리. "20개 중 6개 익힘"으로만 보이고, 퍼센트·순위는 두지 않는다.
4. **도구 도감**: 내 지도에 세운 적 있는 도구에 '내 지도에 있음' 표시가 붙는다.

**손맛과 알림**
- 손님이 한 일마다 지도 변화 하나, 낭독 한 줄, (켰다면) 소리 하나가 짝지어 나온다.
- 자주 하는 조작(보기 고르기, 경유지 펼치기)은 300ms 안의 조용한 전환이다. 큰 장면은 드문 순간 다섯 곳(홈 첫 운행, 경유지 연결, 모두 초록, 도착, 시운전 끝)에만 둔다.

**하지 않는 것** (다크 패턴 없음)
- 연속 출석, 매일 보상, 시간 제한, 정체로 지는 판, 순위표, 다른 사람과 비교를 두지 않는다.
- 뽑기식 보상, 잃는 것, "거의 다 왔어요!" 같은 재촉도 없다.
- 미니 모터웨이에서 압박만 빼고 가져온다. 우리 판은 늘 풀리는 퍼즐이다. '모르겠어요'를 고르면 안전한 쪽으로 간다.

**기다리게 하지 않는 장치**
- 모든 장면은 누르면 끝난다.
- 장면 중에도 버튼이 눌린다.
- 다시 오면 장면이 짧아진다.
- 본보기 지도로 출발하면 목적지·경유지를 건너뛰고 점검에 바로 내린다.
- 동작 줄이기에서는 150ms 넘는 움직임이 하나도 없다.

### (c) 소유자 요청

**흐름**은 한 가지로 정한다.
1. 소유자가 **이미지 생성**으로 기준 그림을 만든다.
2. 그 그림을 **Tripo3D 이미지→3D**에 넣어 GLB로 내보낸다.
3. 우리가 렌더 틀로 굽는다.
   - 정사영 카메라, 고도 35°, 왼쪽 앞 45°.
   - 빛은 왼쪽 위 하나. 그림자는 남동쪽으로 지도와 같게.
   - 투명 PNG로 뽑은 뒤 sharp로 팔레트 색에 맞춰 줄이고, webp 320×320(18KB 이하)·160×160(7KB 이하) 두 벌을 만든다.

같은 틀로 구우니 열 개가 같은 세계에 있는 물건처럼 보인다. 받기 전 자리 표시는 모두 우리 SVG 건물을 크게 쓴 것이다. 그 자체로 완성 품질이라 늦어도 막히는 화면이 없다. 렌더가 '빛 방향 같음, 160px에서 실루엣 구분, 팔레트에서 크게 벗어나지 않음'을 넘지 못하면 SVG를 그대로 둔다.

### 깨질 수 있는 것과 막는 법

- **배치 조합**: 경유지 있고 없음, 2차, 터널, 여러 경유지를 맡는 도구가 겹치면 조합이 많다.
  - 배치는 경유지 수로만 고르고 상태는 그림으로만 바꾼다.
  - 단위 시험으로 모든 조합(화면 칸은 늘 있으니 2⁵=32)을 그려 겹침과 화면 밖 넘침을 본다.
- **글자 크기 200%**: SVG 이름표는 글자만 키우는 설정을 따라 커지지 않는다. 뜻은 시트의 HTML 목록이 다 가지고 있으므로 지도는 보조 그림이다 (요약 `aria-label`).
- **브라우저 차이**
  - 차 이동은 CSS `offset-path` 대신 `getPointAtLength` 표본 + WAAPI라 브라우저 차이가 적다.
  - View Transitions는 지원하지 않으면 그냥 넘어간다.
  - `@property` 색 전환이 없으면 바로 바뀐다.
- **저사양 휴대폰**: 흐림 필터는 쓰지 않는다. `transform`·`opacity`·`stroke-dashoffset`만 움직인다. 한 번에 움직이는 길은 두 개까지다.
- **밤 지도**: 토큰이 두 벌이 되니 대비 검사(`check-tokens.ts`)를 두 벌 모두 돌린다. 화면 점검 스크린샷에 밤 360px을 더한다.
- **붙박이 아래 막대가 초점을 가림** (WCAG 2.4.11): `scroll-padding-bottom`을 막대 높이로 둔다. 지금 `--bar-bottom` 시험을 그대로 쓴다.
