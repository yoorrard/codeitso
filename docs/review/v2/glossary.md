# v2 어려운 말 풀이: 고르면 쉬운 풀이가 뜨는 기능 설계와 용어 목록

작성 2026-10-13. 소유자 요청("어려운 표현을 드래그하면 쉬운 설명이 나오게")에 대한 설계 몫이다. D60에서 1판(`src/lib/glossary.ts`, `src/components/TermPopover.tsx`, `data/glossary.json` 64개, `tests/lib/glossary.test.ts`, `tests/e2e/glossary.spec.ts`)을 이미 만들었다. 이 문서는 1판을 조사 결과에 비춰 검토하고, **무엇을 어떻게 바꿀지**와 **새로 넣을 용어 148개**를 정한다.

함께 읽을 것: `docs/review/v2/game.md` 3.5절(겹 풀이·밑줄 5개·처음 한 번 알림), `docs/review/v2/systems.md`(토큰·모션 길이). 이 문서는 game.md 3.5절과 같은 방향이고, 조사로 숫자를 정하거나 고친 곳은 그때마다 적었다.

## 0. 결론

1. **들어오는 길을 둘로 한다.** (가) 지금처럼 글을 끌어 고르기, (나) 사전에 있는 말에 **점선 밑줄을 긋고 누르면 풀이**. 본문 글을 키보드로 고르려면 캐럿 브라우징(F7)을 켜야 하고 Safari에는 그 기능이 없다. 1판만으로는 키보드·화면 읽개 이용자가 이 기능을 쓸 수 없다(WCAG 2.1.1). 밑줄 말은 버튼이라 Tab으로 닿는다.
2. **1판에서 실제로 확인한 문제 9개** (4절). 가장 큰 것: 모달 시트 안에서 고르면 풀이가 시트 **아래에 깔리고 누를 수 없다**(inert). 낱말을 두 번 눌러 고르면 '키를', '환경', '변수에'만 골라져서 'API 키'·'환경 변수'를 **놓친다**. '포트폴리오'를 포트로, '블로그'를 로그로, '시크릿 창'을 환경 변수로, '본인인증'을 로그인으로, 'Firebase 콘솔'을 개발자 도구로 **잘못 푼다**. 스크롤하면 풀이가 닫히는데 고른 글은 남는다. 홈 제목 '어디로 모실까요?'를 고르면 "'어디로 모실까요?' 사전에서 찾기"가 뜬다. '사전에서 더 보기'는 사전 색인에 용어집이 없어 '프레임워크'·'캐시' 같은 말에서 **빈 결과**로 끝난다.
3. **찾는 법을 '어절 경계 + 꼬리 검사 + 문맥 넓히기'로 바꾼다** (5.2절). 고른 글 앞뒤 48자를 함께 보고, 용어가 어절 첫머리(또는 한글↔영문 바뀌는 곳)에서 시작하고 뒤에 조사·하다 활용·복수 '들'만 붙을 때만 맞다고 본다. 시제품으로 57개 사례를 돌려 문서에 적은 기대값이 모두 나왔고, 한 번 찾는 데 0.13ms(열쇠 668개)였다.
4. **자리.** 마우스는 고른 글 마지막 줄 **아래 8px**, 모자라면 위로 뒤집는다(Wikipedia·Material과 같은 값). 손가락은 휴대폰 손잡이·메뉴를 피해야 한다: 고른 글이 화면 **위쪽 55%면 아래 40px**(안드로이드 손잡이 누름 상자 40dp), **아래쪽이면 화면 위쪽에 붙인다**. 폭은 `min(320px, 화면 폭 − 32px)`.
5. **닫기.** Esc, 닫기 버튼, 고른 글이 풀림, 바깥 누르기. 스크롤·화면 크기 바뀜은 닫지 않고 **따라간다**. 시간이 지났다고 닫지 않는다(1.4.13 '머무름').
6. **기술.** Popover API(Baseline 2025-01-27)로 맨 위 층에 띄우고, 위치는 지금처럼 JS로 잡는다. CSS 앵커 위치는 선택 영역(Range)에 붙일 수 없고 아직 Baseline이 아니다. `interestfor`는 Chrome만 된다. 모달 안에서는 풀이를 그 `<dialog>` 안으로 옮겨 그린다.
7. **화면 읽개.** 밑줄 말은 `popovertarget` 버튼이라 '접힘·펼침'이 저절로 읽히고(HTML-AAM), Tab을 누르면 풀이 안으로 바로 들어간다(HTML 표준의 popover 초점 범위). 풀이 문장은 지금처럼 정중한 알림 영역으로 읽어 준다.
8. **집계는 하지 않는다.** PRD R-60이 셀 이벤트를 다섯 개로 묶어 두었다. 고른 글은 어디에도 보내거나 저장하지 않는다. 연 용어의 id만 이 브라우저에 남겨 밑줄을 거둔다(`store.ts`).
9. **성능.** 풀이 자료 212개(기존 64 + 새 148)는 줄여 쓰면 49.1KB, **gzip 14.8KB**(지금 64개 4.5KB). 처음 고르기 시작할 때(`selectstart`, iOS는 첫 `selectionchange`) 또는 밑줄 말을 처음 누를 때 불러온다. 풀이 섬은 지금 2.2KB gz, 고친 뒤 5KB gz 안쪽.
10. **용어.** 새로 148개(키·로그인 24, 돈 17, 자료 38, 코드 50, AI 3, 권리 8, 코드쇼퍼 말 8)와 기존 64개 중 24개 고침. 모두 '70자 이하·요.로 끝·한 문장·열쇠 겹침 없음' 검사를 통과했다(가장 긴 풀이 54자, 212개 중 186개가 40자 이하).

**휴대폰 기본 선택 화면과의 충돌** (고르기 풀이를 손가락으로 쓸 때 가장 중요한 숫자):

- 결론: 손가락 고르기의 풀이는 **고른 글 위에 두지 않는다**(기본 메뉴 자리). 아래에 둘 때는 **40px** 띄워 손잡이를 남긴다. 고른 글이 화면 아래쪽이면 화면 **위쪽에 붙인다**.

## 3. 접근성 기준과 플랫폼 지원

**WCAG 1.4.13 (내용이 올림·초점으로 나타날 때, AA).** 세 조건: 초점·포인터를 옮기지 않고 **닫을 수 있다**(예: Esc), 포인터를 **풀이 위로 옮겨도** 사라지지 않는다, 이용자가 치우거나 내용이 쓸모없어질 때까지 **머문다**. 고르기·누르기로 여는 풀이는 엄밀히 이 기준의 대상(올림·초점)이 아니지만, 같은 문제(가림, 확대해서 보는 사람이 놓침)가 생기므로 셋을 다 지킨다. 그래서 **시간으로 닫지 않는다**.

**ARIA APG 툴팁.** 툴팁은 초점을 받지 않고, 초점 가능한 것이 든 풀이는 **비모달 대화 상자**로 만든다(APG 스스로 '작업 중, 합의 전'이라고 적어 둠). 코드쇼퍼 풀이에는 링크·버튼이 있으므로 툴팁이 아니라 비모달 대화 상자다. 1판의 `role="dialog"`가 맞다. 밑줄 말은 **토글팁**(누르면 켜고 끄는 풀이, TPG 2016)이다.

**HTML 표준(1차).**
- popover가 **트리거**(`popovertarget`의 버튼, 또는 `showPopover({ source })`)를 가지면 그 트리거가 '초점 범위 주인'이 된다. 그래서 트리거 다음 Tab이 **풀이 안으로** 들어간다. 따로 초점 옮김 코드를 쓰지 않아도 된다.
- 모달 `<dialog>`가 열리면 그 대화 상자와 그 안의 것만 빼고 **문서 전체가 inert**가 된다. 1판의 풀이는 대화 상자 밖(Base 레이아웃)에 그려지므로 모달 시트 안에서 고르면 누를 수 없다(4절 P1의 원인).
- HTML-AAM: `popovertarget` 버튼은 풀이가 열리면 `aria-expanded=true`, 닫히면 `false`로 저절로 읽힌다.

**WCAG 2.5.8 (누르는 곳 크기 최소, AA).** 문장 속 링크·버튼은 **인라인 예외**라 24px 규칙을 받지 않는다. 그래도 밑줄 말 위아래에 0.15em 정도 누름 여백을 준다(줄 간격을 바꾸지 않는 범위).

**WCAG 2.1.1 (키보드).** 본문 글을 키보드로 고르려면 캐럿 브라우징(Chrome·Edge·Firefox의 F7)을 켜야 하고 Safari에는 없다(2차). 고르기는 마우스·손가락 이용자의 지름길로 두고, **모든 이용자의 길은 밑줄 말 + 사전**이다.

### 5.2 찾는 법 (한국어)

`src/lib/glossary.ts`에 순수 함수로 둔다. 시제품(`lookup`)을 만들어 아래 기대값을 확인했다.

1. **정규화.** `NFKC`(전각 → 반각), 영문 소문자, 폭 없는 글자(U+200B~U+200D, U+2060, U+FEFF)와 소프트 하이픈(U+00AD) 지우기. 공백·따옴표·괄호·`. , ! ? : ; · … ~ - _ / |`는 **어절 경계**로 바꾼다(지우되 경계 표시는 남긴다). `+`·`#`은 남긴다. 원문 위치 표를 함께 만들어 맞은 자리를 원문으로 되돌린다.
2. **열쇠.** 이름과 다른 이름을 같은 방식으로 정규화한 것. 공백을 뺀 모양이라 'API 키'·'API키'·'api key'가 같다. 읽는 법(`say`)은 열쇠로 쓰지 않는다('코스'처럼 흔한 말과 겹친다).
3. **시작 자리.** 용어는 어절 첫머리, 또는 한글↔영문·숫자가 바뀌는 자리에서만 시작한다('급식API를' → API). 그래서 '블로그' 속 '로그', '리포트' 속 '포트'는 맞지 않는다.
4. **꼬리 검사.** 용어 뒤에 같은 어절로 붙은 글(꼬리)이 다음 중 하나일 때만 맞다.
   - 없음.
   - 조사 0~2개(긴 것부터 떼기). 목록: 으로부터, 에서부터, 이라는, 이라고, 이라도, 이란, 에게서, 한테서, 에서는, 에서도, 에서, 으로는, 으로도, 으로서, 으로써, 으로, 에게, 한테, 께서, 까지, 부터, 처럼, 보다, 하고, 이랑, 라는, 라고, 라도, 이나, 이고, 이며, 이든, 마다, 마저, 조차, 밖에, 대로, 입니다, 이에요, 예요, 이다, 에는, 에도, 로는, 로도, 로서, 로써, 와는, 과는, 은, 는, 을, 를, 이, 가, 의, 에, 로, 와, 과, 도, 만, 란, 나, 랑, 야 (open-korean-text의 506개 조합 목록에서 이 사이트 글에 나오는 것만 골랐다).
   - 앞에 복수 '들'이 하나 붙은 위 꼴('패키지들을').
   - 끝의 '요'('데이터베이스는요').
   - 하다·되다 활용: `^(하|되|해|돼|했|됐|한|할|된|될|함|됨)[가-힣]{0,5}$` ('배포하려면', '커밋했어요').
   - 영문 용어 뒤의 `s`·`es`('APIs', 'tokens'). 단 용어 + s가 따로 열쇠면 쓰지 않는다('https'를 http + s로 보지 않게).
5. **문맥 넓히기.** 고른 글이 든 글 덩어리(가장 가까운 `p, li, dd, dt, td, th, figcaption, blockquote, h1~h6` 또는 글 마디)에서 고른 범위 앞뒤 **48자**를 문맥으로 잡고 문맥 전체에서 맞는 용어를 모두 찾는다(꼬리까지 포함한 범위를 함께 적는다).
6. **고르기.** 
   - 첫째 용어 = 고른 범위와 **꼭 맞거나 감싸는** 것 중 가장 긴 것. 없으면 고른 범위 **안에** 든 것 중 앞의 것.
   - 같이 보여 줄 말(칩) = 고른 글과 꼭 맞는 더 짧은 용어가 따로 있으면 먼저('API'를 골랐는데 'API 키'가 첫째일 때 'API'), 그다음 고른 범위 안에서 첫째·이미 고른 칩과 **겹치지 않는** 용어를 긴 것부터. 칩은 **2개까지**.
   - 아무것도 없으면 5.9절.

위에서 아래로 (360px 기준 높이 약 170~230px):

1. **머리 줄**: 용어 이름(17px, 굵기 600) + 읽는 법(`say`가 있으면 13px `--text-2`, "CORS · 코스"). 오른쪽 위 닫기 버튼 44×44px. 겹 풀이 안이면 이름 위에 길잡이 "API › API 키"와 [뒤로](44px).
2. **풀이 한 문장**(`plain`, 16px/24px). 문장 속에 상위 용어(`see`)가 있으면 그 말에 점선 밑줄 → 누르면 같은 상자에서 그 풀이로 바뀐다. **2겹까지**(game.md 3.5와 같음). 3겹부터는 밑줄을 긋지 않고 카드 링크만.
3. **예**(`example`, 있으면, 14px/21px `--text-2`). 문구 틀 `ko.glossary.example` = "예: {{example}}".
4. **칩 줄**(있으면): '같이 고른 말' 칩 2개까지, 높이 44px. 누르면 그 풀이로 바뀐다(겹 풀이와 같은 길잡이).
5. **이어 가기**(버튼 두 개까지, 높이 44px): 첫째는 `concept`가 있으면 [용어 카드 보기], 없고 `tool`이 있으면 [도구 카드 보기], 없고 `error`가 있으면 [에러 안내 보기]. 둘째는 늘 [사전에서 더 보기].

보이지 않는 것: 광고성 링크, 복사 버튼, '도움이 됐나요' 같은 평가(집계가 없으므로), 그림.

밑줄 말·고르기 모두 같은 상자를 쓴다. **쉬운 말이 위험을 가리지 않게**, 위험이 있는 용어(관리자 키, 테스트 모드, 강제 푸시, 공개 환경 변수 등)는 풀이 문장 안에 '넣으면 안 돼요'·'지워질 수 있어요'를 꼭 넣었다(7절).

### 5.4 자리 (360px 기준)

공통: 폭 `min(320px, visualViewport.width − 32px)`, 최대 높이 `min(60% × visualViewport.height, 360px)`(넘으면 안에서 스크롤), 좌우는 화면 끝에서 **16px** 안쪽으로 붙잡는다. 위쪽 고정 머리줄과 아래 행동 막대(`.action-bar`)·안전 영역(`env(safe-area-inset-*)`)을 피한다. 모든 계산은 `visualViewport`의 `offsetTop`·`offsetLeft`·`height`로 한다(핀치 확대·화면 키보드).

| 길 | 붙일 곳 | 세로 | 가로 | 뒤집기 |
|---|---|---|---|---|
| 마우스·펜 | 손을 뗀 점에 가장 가까운 줄 상자(`range.getClientRects()`) | 그 줄 아래 **8px** | 고른 폭이 28px보다 넓으면 손을 뗀 x, 좁으면 줄 상자 가운데 (Wikipedia 규칙) | 아래 남은 높이 < 상자 높이 + 16px이고 위가 더 넓으면 줄 **위 8px** |
| 손가락 | 고른 글의 마지막 줄(`Selection.direction`이 있으면 손을 뗀 쪽 끝) | 마지막 줄 바닥이 보이는 높이의 **위 55%** 안이면 그 아래 **40px**. 아니면 **화면 위쪽에 붙임**(머리줄 아래 8px, 좌우 16px) | 맞은 용어 자리 가운데(5.2의 범위를 원문 Range로 되돌림), 없으면 줄 가운데 | 위에 붙인 상자는 꼬리(화살표)를 그리지 않는다 |
| 키보드 고르기 | 고른 글 끝(focus) 줄 | 아래 8px | 줄 가운데 | 마우스와 같음 |
| 밑줄 말 | 그 버튼 | 아래 8px (손가락이어도 고른 글이 없어 손잡이·메뉴가 없다) | 버튼 가운데 | 마우스와 같음 |

꼬리(화살표)는 12×6px, 상자 끝에서 **16px** 안쪽에서만 움직인다(토스 TDS 규칙). 손가락 아래 40px 간격은 안드로이드 손잡이 누름 상자 40dp에서 왔다. 이 값을 둔 까닭은 풀이 상자가 손잡이를 덮으면 고르기를 넓힐 수 없기 때문이다.

### 5.5 닫기

- 닫힘: Esc, 닫기 버튼, 고른 글이 풀림(`selectionchange`에서 `isCollapsed`, 늦춤 없이), 풀이 밖을 누름(밑줄 말 길은 `popover="auto"`의 바깥 누르기 닫힘을 그대로, 고르기 길은 `popover="manual"` + 직접: 고른 글 안을 다시 누르는 건 손잡이 조정일 수 있으니 닫지 않는다), 페이지 이동.
- 닫히지 않음: 스크롤, 크기 바뀜, 시간. 스크롤·크기 바뀜은 `requestAnimationFrame`으로 자리를 다시 잡는다. 붙인 줄이 화면 밖으로 나가면 숨기고 돌아오면 다시 보인다.
- Esc로 닫은 고르기는 고른 글이 바뀔 때까지 다시 띄우지 않는다(같은 글로 또 뜨지 않게).
- 모달 안: 풀이가 열려 있으면 Esc는 풀이만 닫는다(대화 상자의 `cancel` 이벤트를 막는다).
- 풀이 안의 버튼은 마우스 `pointerdown`에서 `preventDefault()`해 고른 글이 풀리지 않게 한다(Medium식). 손가락은 `click`에서 처리하고, 고른 글이 풀려 닫히는 것은 400ms 늦춤 뒤라 누르기가 먼저 닿는다.

모션: 열림 160ms(투명도 0→1, 위로 4px → 0, `--ease-out`), 닫힘 120ms(열림의 약 70%, systems.md 규칙). 동작 줄이기(기기·사이트)에서는 이동 없이 투명도만. 숫자는 토큰으로(`--dur-…`).

### 5.6 초점·키보드·화면 읽개

| 길 | 초점 | 읽는 것 |
|---|---|---|
| 고르기 | 옮기지 않는다(고른 글과 휴대폰 메뉴를 지키려고). `showPopover({ source: 고른 글을 감싼 요소 })`가 되는 브라우저(Chrome 137·Firefox 144·Safari 26)에서는 그 요소 다음 Tab이 풀이로 간다 | 맞으면 정중한 알림 "{용어}: {풀이}"(1판과 같음). 못 찾으면 읽지 않는다 |
| 밑줄 말 | 버튼에 남는다. Tab 한 번이면 풀이 안 첫 버튼(HTML 표준). Esc로 닫으면 초점은 버튼 | 버튼 이름 = 화면 글 그대로("환경 변수, 버튼, 접힘"). 열면 '펼침' + 알림 "{용어}: {풀이}" (토글팁 방식) |
| 겹 풀이·칩 | 바뀐 풀이의 제목(`tabindex="-1"`)으로 옮긴다 | 제목이 읽힌다. [뒤로]는 이전 풀이 제목으로 |

풀이 상자: `role="dialog"`, `aria-labelledby`=용어 이름 칸, 비모달(초점 가두지 않음). 영문 용어 이름에는 `lang="en"`을 달고 읽는 법을 화면 글로 함께 둬서 한국어 음성이 'CORS'를 '씨오알에스'로 읽어도 '코스'를 듣게 한다.

### 5.7 점선 밑줄 말

- **그리는 곳**: 설명 글 칸만. 질문 도움말(`q-help`), 도구 카드의 하는 일·이럴 때 써요·무료 한도·비용·막히기 쉬운 곳·준비, 점검의 막힌 곳 설명·고치는 법, 도착의 알아볼 것·나중에 붙일 것·막히기 쉬운 곳, 용어 카드 본문(그 카드의 용어는 빼고), 사전 결과 본문.
- **그리지 않는 곳**: 제목(h1~h3), 버튼·링크·라벨·`summary` 안(버튼 안에 버튼을 못 둔다), `code`·`pre`·`kbd`, AI에게 할 말 상자(`.prompt-box`, 복사할 글), 설계도 미리 보기, 영수증, 법 문서, 홈 첫 화면.
- **양**: 한 화면에서 용어마다 **처음 한 번**, 단계 화면은 **5개까지**(game.md와 같음), 참고 쪽(`/tools/*`, `/terms/*`, 사전)은 구역마다 처음 한 번씩 **8개까지**. 한 문단에 2개를 넘기지 않는다. `noMark: true`인 말(요청·응답·명령어·변수, 코드쇼퍼 말)은 긋지 않는다(고르기로는 풀린다).
- **읽은 말**: 풀이를 한 번 연 용어는 다음부터 긋지 않는다(옅은 밑줄은 3:1 대비를 못 지켜 '누를 수 있음'을 알리지 못하므로 아예 거둔다). `store.ts`에 `termsSeen`(id 목록, 300개까지)을 둔다.
- **모양**: `text-decoration: underline dotted 1.5px var(--link)`, `text-underline-offset: 0.2em`(16px에서 약 3px), 글자색은 본문 그대로. 누를 때 배경 `--fill`. 초점 테두리는 사이트 공통. 버튼 안쪽 여백 0·테두리 0·`font: inherit`라 줄이 밀리지 않는다(CLS 0).
- **만드는 법**: `src/lib/glossary.ts`에 `segmentTerms(text, index, seen, limit) → (string | { id, text })[]`(5.2와 같은 매처). Astro 쪽(도구·용어 카드 등)은 빌드 때 나눠 그리므로 실행 JS가 0이다. 섬(목적지·경유지·점검·도착)은 처음엔 밑줄 없이 그리고, 쉬는 시간(`requestIdleCallback`, 늦어도 2초)에 풀이 자료를 불러와 밑줄을 더한다. 열쇠만 떼어도 5.4KB gz(전체 14.8KB gz의 37%)이고, 밑줄을 누르면 결국 전체를 받아야 하므로 나누지 않는다.
- **연결**: 버튼은 `<button type="button" class="term-mark" data-term="env-var" popovertarget="term-pop">`. 풀이 상자 하나(`#term-pop`)를 모두 같이 쓰고, `beforetoggle`에서 내용을 바꾼다. 풀이 섬(`client:idle`)이 깨어나기 전에 누른 것은 Base의 아주 작은 인라인 스크립트(약 0.3KB)가 받아 두었다가 섬이 깨어나면 연다. 모달 `<dialog>` 안의 밑줄 말은 대화 상자 밖 풀이 상자를 열 수 없으므로(inert) 그 대화 상자 안에 둔 풀이 상자를 쓴다(P1과 같은 까닭).

### 5.8 설정과 처음 안내

- 설정 메뉴에 두 줄: **'어려운 말 풀이'**(켜짐·꺼짐: 고르기 풀이), **'점선 밑줄'**(켜짐·꺼짐). 기본은 둘 다 켜짐. Wikipedia Page Previews가 풀이마다 끄는 길을 둔 것처럼, 글을 자주 복사하는 사람이 끌 수 있어야 한다. 저장은 `setPrefs`.
- 처음 한 번: 밑줄이 처음 보이는 화면의 기사 메시지 한 번(`markSceneSeen('glossary-hint')`). 문장: "점선 밑줄 말을 누르면 쉬운 풀이가 떠요." / "다른 말도 골라 보면 풀어 드려요." (두 문장, 각 40자 안쪽, 해요체. 손가락·마우스 어느 쪽에도 맞게 '끌어'·'길게 눌러'를 쓰지 않았다.)
- `/about`의 '이 사이트 쓰는 법'에 한 줄.

### 5.9 모르는 말과 에러 문장

| 고른 글 | 보여 줄 것 |
|---|---|
| 용어가 있음 | 5.3의 풀이 |
| 용어 없음, 영문·숫자가 섞이고 40자 이하 | 작은 칩 하나 "'{고른 글}' 사전에서 찾기" (44px). 알림으로 읽지 않는다 |
| 용어 없음, 에러 문장처럼 보이고 200자 이하 (`Dictionary.tsx`의 `ERRORISH`와 같은 판단, `errors.json`의 `patterns`) | 칩 "에러 안내 찾기" → 사전을 그 글로 연다(사전이 이미 `matchErrors`로 에러 카드를 맨 위에 보인다) |
| 용어 없음, 한글만 | 아무것도 띄우지 않는다. 대부분 복사하려고 고른 보통 말이다(P7) |
| 사전 창 안에서 고름 | 용어가 있을 때만 풀이. 모르는 말 칩은 띄우지 않는다(이미 사전 안) |

빠진 말은 집계로 모으지 않는다. 관찰 시험(`docs/OBSERVATION.md`)에서 "고르고 아무것도 안 뜬 말"을 적어 다음 용어 추가에 쓴다.

### 5.10 집계와 개인정보

- 집계 이벤트를 더하지 않는다. PRD R-60이 다섯 개(목적지 시작, 영수증 받음, AI에게 할 말 복사, 먼저 읽어 둘 용어 완료, 확인 문제 응답)로 묶어 두었다. 바꾸려면 PRD부터 고쳐야 하고, 고른 글은 내용이라 구간 값으로 줄일 수도 없다.
- 고른 글은 보내지도 저장하지도 않는다. 이 브라우저에 남는 것은 연 용어의 id(`termsSeen`)와 두 설정뿐이다. 개인정보 쪽(`/legal/privacy`) 문구에 한 줄: "고른 글은 어디에도 보내거나 저장하지 않아요. 열어 본 용어 이름만 이 브라우저에 남겨 밑줄을 거둬요."

### 5.11 성능

| 묶음 | 지금 | 목표 | 언제 |
|---|---|---|---|
| 풀이 섬 (`TermPopover`) | 2.2KB gz | **5KB gz 이하** (선택 감지, 자리 계산, 칩, 겹 풀이) | `client:idle` |
| 풀이 자료 + 매처 | 64개 4.3KB gz | 212개 **14.8KB gz** + 매처 약 1.5KB → **17KB gz 이하** | 처음 `selectstart`(iOS는 첫 고르기), 처음 밑줄 말 누름, 섬 화면의 쉬는 시간(밑줄 그릴 때) |

### 5.12 자료 모양 (`data/glossary.json`, `schemas/`)

```ts
interface GlossaryEntry {
  id: string;
  term: string;            // 보이는 이름
  aliases?: string[];      // 다른 이름 (정규화 뒤 2자 이상, 용어끼리 겹치지 않음)
  say?: string;            // 새: 읽는 법 (영문 용어). 열쇠로 쓰지 않음
  plain: string;           // 한 문장 해요체, '요.'로 끝, 70자 이하 (목표 45자 이하)
  example?: string;        // 한 문장, 60자 이하
  concept?: string;        // 용어 카드 id (concepts.json)
  tool?: string;           // 새: 도구 카드 id (products.json)
  error?: string;          // 새: 에러 안내 id (errors.json)
  see?: string;            // 새: 풀이 문장 속 상위 용어 id (겹 풀이 1겹)
  kind: 'key' | 'money' | 'data' | 'code' | 'ai' | 'law' | 'site' | 'tool';  // 새 ('tool'은 빌드 때 products.json에서 만드는 항목)
  noMark?: boolean;        // 새: 점선 밑줄을 긋지 않음
}
```

문장 규칙(자료 시험으로 막는 것):
- 한 문장(가운데 `. `·`? `·`! ` 없음), '요.'로 끝, 70자 이하. 예는 60자 이하.
- 풀이에 쓰는 말은 **기본 낱말**(앱·화면·코드·파일·폴더·주소·브라우저·키·API·서버·데이터·요청·프로그램·인터넷·사이트·계정·컴퓨터·저장소·명령·기록), 서비스 이름, 그리고 **상위 용어 하나**(`see`)까지만. 이 문서 초안은 매처로 검사해 상위 용어가 둘 이상인 풀이가 없다. 상위 용어 하나를 품은 22개(예: Node.js → 자바스크립트, Vite → React, 학교 코드 → 나이스, 유효 기간 → 토큰)는 `see`로 잇는다.
- 위험이 있는 것은 쉬운 말로 숨기지 않는다: '넣으면 안 돼요', '지워질 수 있어요', '꺼야 해요'를 풀이 안에 둔다.
- `say`는 한글만. `tool`·`concept`·`error`는 있는 id만(`npm run validate`).
- 도구 이름은 손으로 넣지 않는다: 빌드 때 `products.json`의 `name`(괄호 안 이름도 따로)을 `kind: 'tool'` 항목으로 더하고 풀이 대신 `summary`를 보인다(명사구라 '요.' 규칙 밖). 손으로 넣은 항목과 열쇠가 겹치면 손으로 넣은 쪽이 이긴다(예: '브라우저 저장 공간').

- **코드쇼퍼 말 8개**는 단계 이름 결정(game.md 3절, mobility.md)에 따라 바뀐다. 이름이 정해지면 `kind: 'site'` 항목을 다시 쓴다.
- '웹훅'과 '웹후크' 중 사이트 표기를 무엇으로 할지(6절). 이 문서는 둘 다 찾게만 했다.
- iOS 편집 메뉴가 풀이 상자 위치에 따라 아래로 내려오는 조건(WebKit의 '위에 누를 수 있는 요소') 때문에 손가락 아래 40px 자리에서도 메뉴가 풀이와 겹칠 수 있다. 실제 iPhone(iOS 26)에서 관찰 시험 때 확인한다(`docs/OBSERVATION.md`에 한 줄).
- Chrome Android의 Touch to Search가 지금도 켜져 있는지는 확인하지 못했다(2차 자료는 2015~2023). 켜져 있으면 화면 아래를 차지하므로, 이 설계는 고르기 풀이를 아래에 붙이지 않는다.
- 풀이에 든 사실(부가세 10%, UTC+9, 종목 코드 6자리, 요금제 이름)은 사람 확인 대상은 아니지만 `products.json`이 바뀌면 같이 본다. 요금제 금액은 풀이에 넣지 않고 도구 카드로 잇는다(Eco 플랜 '한 달 5달러'를 일부러 뺐다).
