## 0. 결론 여덟 줄

1. 호출 앱의 공통 뼈대는 **목적지 → 고르기(차종·예상 요금) → 호출 전 확인 → 진행 상태 → 도착·영수증**이다. 코드쇼퍼의 다섯 단계와 거의 1:1로 맞는다. 고칠 것은 구조가 아니라 **이름**이다.
2. 호출 앱은 **버튼은 동사**("호출하기", "Confirm UberX"), **상태는 명사**("배차 완료", "운행 중")로 쓴다. 지금의 '시운전·목적지·경유지·점검·도착'은 활동·장소·장소·활동·사건이 섞여 한 계열로 읽히지 않는다.
3. 권장 단계 이름: **AI 써 보기(선택) → 목적지 정하기 → 도구 고르기 → 길 확인하기 → 설계도 받기.** 모두 '[손에 쥐는 것] + 하기'라서 무엇을 하는 단계인지 이름에 들어 있다. 탈것 느낌은 지도·차·교통 정보·"도착했습니다"·영수증이 맡는다.
4. 비유 가운데 **목적지·예상 비용·차종 목록 모양·출발 전 확인·교통 정보(원활·서행)·영수증**은 초심자에게 도움이 된다. **호출·배차·시운전·경유지(단계 이름)·점검·하차·결제·별점**은 헷갈리게 하거나 거짓 기다림을 만든다.
5. 지도는 Uber처럼 **채도 낮은 바탕 + 대비가 큰 경로선 하나**로 간다. 로고 색으로 옮기면 **남색 #001E5A 바깥선 8px + 청록 #00B4FA 심 4px**이다. 청록은 흰 바탕에서 2.36:1밖에 안 되니 낮 지도에서는 혼자 쓰지 않는다.
6. 로고의 밝은 파랑 #0082FA는 흰색과 3.77:1이다. **글자나 흰 글자를 얹는 버튼 채움에는 못 쓴다.** 주 버튼은 남색 채움(흰 글자 15.75:1)으로 하고, 파랑은 그림 요소(고리, 진행 막대)에만 쓴다. 파랑 글자가 필요하면 #0068CC(5.45:1)를 쓴다. TMAP도 로고 색은 브랜드 장면에만 쓰고 화면에는 단색 파랑 하나만 쓴다 [2차].
7. 상태 한 줄은 Uber Live Activity와 카카오 T의 '도착 예정 시각' 순서를 따른다: **지금 단계 · 남은 일 개수 · 약 n분.** 시간은 남은 질문·고를 것 개수로 계산한 정직한 추정이어야 한다. 실시간으로 줄어드는 초읽기는 하지 않는다.
8. 고급스러움은 Blacklane·Uber Black처럼 **절제와 미리 밝히기**에서 나온다. 색은 하나만 강조하고, 값은 먼저 보여 준다(숨은 비용 없음). 기다려도 돈을 받지 않고(이어서 가기), 손님 취향 설정을 둔다("조용히 모시기"). 반짝이는 장식으로는 고급스러워지지 않는다.

### 1.6 길 안내의 공통 약속 (한국 내비 · 공공 · 지도 SDK)

| 항목 | 관찰 | 확신도 |

## 2. 공통 패턴 정리

### 2.1 흐름의 뼈대

| 호출 앱 | 내비 | 코드쇼퍼 (지금) | 하는 일 |
|---|---|---|---|
| (없음) | 모의 주행 | 시운전 | 내 AI를 10분 써 보기 |
| 출발지·도착지 / "Where to?" | 목적지 검색 | 목적지 | 만들 앱과 조건에 답하기 |
| 차종 선택 + 예상 요금 | 경로 옵션(최적·무료…) | 경유지 | 기능마다 도구 하나 고르기 |
| 픽업·목적지 확인 → "Confirm UberX" / "호출하기" | 경로 미리보기 → 안내 시작 | 점검 | 고른 도구끼리 부딪치는 곳 보기 |
| 배차 → 운행 중 → 하차 → 결제·영수증 | 목적지 부근 → 안내 종료 | 도착 | 설계도·영수증 받기 |

- 호출 앱에는 '연습'이 없다. 손님이 처음 겪는 것은 기다림뿐이라서다. 코드쇼퍼의 연습 단계는 탈것 비유에 억지로 넣지 말고, 하는 일 그대로 부르는 편이 낫다.
- '배차·운행 중'은 **실제로 기다리는 시간**이 있어서 생긴 상태다. 코드쇼퍼의 엔진은 바로 계산한다. 여기에 '배차 중…' 같은 연출을 넣으면 **가짜 기다림**이 된다. Fleet Engine처럼 상태는 앞으로만 가게 하고, 가짜 지연은 넣지 않는다.

### 2.2 이름 짓는 문법

- 버튼: 동사형(호출하기, Confirm UberX, Start Ride). **고른 것의 이름을 버튼에 넣는다.** "Confirm UberX"는 무엇을 확정하는지 버튼만 봐도 안다.
- 상태: 명사형(배차 완료, 운행 중, 운행 완료). 짧고, 숫자와 함께 쓴다(도착 예정 시각, n분).
- 차종 이름: 기능을 드러낸다(블루 = 빠른 배차, 벤티 = 대형, 모범 = 고급 / 타다 넥스트 = 대형). 브랜드 말장난은 적다.

### 2.3 지도

- 바탕은 채도를 빼고, **경로선 하나만 대비를 크게** 준다(Uber 검정선, 대비 +123%).
- 출발과 도착은 **모양**으로 나눈다(둥근 표시 / 네모 표시). 색으로만 나누지 않는다.
- 남은 길은 숨기거나 흐리게 한다(Google: remaining은 기본으로 숨김).
- 밤 지도는 낮 지도를 반전한 것이 아니다. 따로 정한 낮은 채도 팔레트다.
- 내 위치나 지금 단계에는 강조색 하나를 쓴다(Waymo의 파란 음영, Apple의 파란 점).

### 2.4 아래 시트

- 지도는 위쪽 약 40~50%이고 시트가 나머지를 덮는다. 시트 맨 위에는 **지금 상태 한 줄**, 그다음에 고를 것이나 사람·차 카드가 오고, 맨 아래에 세부가 온다.
- 주 버튼 하나를 시트 아래에 붙여 둔다(Lyft 2018: 조작을 아래로 내림).
- 끄는 시트는 손잡이로 그 사실을 알린다. **끌 수 없으면 손잡이를 그리지 않는다.**

### 2.5 상태 줄

- 순서: **ETA(시간) → 누구·무엇(차, 번호판) → 세부.** 카카오 T도 같다: 도착 예정 시각 → 차량 번호 → 탑승 확인번호.
- 진행은 막대 하나로 보인다(Uber Live Activity, 시계의 둥근 막대).
- 낱말보다 숫자다. 3피트·1초 기준으로 한눈에 읽혀야 한다.

### 2.6 고급스러움의 신호

| 신호 | 어디서 | 실제로 하는 일 |

## 3. 코드쇼퍼에 주는 권고

### 3.1 흐름과 단계 이름

**지금 이름의 문제.** 시운전(활동, 그것도 '내가 운전해 본다'는 뜻) · 목적지(장소) · 경유지(장소. 그런데 실제로 하는 일은 '도구 고르기') · 점검(활동. 정비소가 떠오름) · 도착(사건). 품사와 시점이 섞여 있다. 게다가 '경유지 → 도구 고르기', '점검 → 충돌 확인'으로 **한 번 더 바꿔 읽어야** 뜻이 나온다.

**권장안: '[손에 쥐는 것] + 하기' 한 계열**

| 순서 | 단계 이름 (화면 제목) | 단계 줄 짧은 이름 | 풀이 한 줄 (제목 아래) | 호출 앱에서 짝 | 다음으로 가는 버튼 |
|---|---|---|---|---|---|
| 0 (선택) | **AI 써 보기** | 연습 | 10분 동안 내 AI로 웹페이지 한 장을 만들어 봐요. | (없음, 내비 모의 주행) | 목적지 정하러 가기 |
| 1 | **목적지 정하기** | 목적지 | 만들고 싶은 앱을 고르고 몇 가지에 답해요. | "Where to?" / 도착지 입력 | 도구 고르러 가기 |
| 2 | **도구 고르기** | 도구 | 필요한 기능마다 맡길 도구를 하나씩 골라요. | 차종 선택 + 예상 요금 | 길 확인하기 |
| 3 | **길 확인하기** | 길 확인 | 고른 도구끼리 부딪치는 곳이 없는지 봐요. | 픽업·목적지 확인, 경로 미리보기 | **출발하기** |
| 4 | **설계도 받기** | 설계도 | 내 AI에게 줄 설계도와 영수증을 받아요. | 하차·영수증 | 설계도 내려받기 (.md) |

- 소리 내어 읽으면 "AI 써 보기, 목적지 정하기, 도구 고르기, 길 확인하기, 설계도 받기"다. 이름마다 **무엇을** 하는지가 들어 있다.
- 탈것 세계는 이름 대신 **장면**이 맡는다. 3단계의 [출발하기] → 차가 달림(S5) → "도착했습니다. 요금은 0원입니다." → 4단계 화면. 그래서 '출발'과 '도착'은 단계 이름이 아니라 **사건**이 된다. 호출 앱에서도 '운행 중'과 '하차'는 손님이 고르는 단계가 아니라 상태다.
- '경유지'는 지도 그림에만 남긴다. 지도의 마디 = 기능 = 들르는 곳이다(Uber 다중 경유와 Fleet Engine의 intermediate destination과 같은 모양). 단계 이름으로는 쓰지 않는다.
- 360px 단계 줄에는 다섯 이름이 다 들어가지 않는다. '목적지 정하기'는 14px로 약 84px이고, 다섯이면 420px이 넘어 쓸 수 있는 폭 328px을 넘는다. 그래서 360px에서는 **"2/5 도구 고르기" + 다섯 칸 막대**로 접고, 768px 이상에서만 짧은 이름 다섯을 다 보인다.
- 버려 본 안: (B) '연습 운행 · 목적지 · 경로 고르기 · 출발 전 확인 · 도착'. 탈것 말은 살지만 '경로 고르기'가 도구를 고른다는 뜻으로 읽히지 않고, '도착'은 하는 일이 아니다. (C) '어디로? · 무엇으로? · 괜찮을까? · 받기' 같은 질문형은 단계 줄에서 귀엽게만 보이고, 화면 낭독기로 들으면 단계 이름으로 들리지 않는다.

**흐름에 더할 것 (호출 앱에서 배운 것)**

1. **추천을 미리 골라 두기 (선택 사항).** Uber는 차종 목록을 열면 하나가 이미 골라져 있고 손님은 확정만 한다. 코드쇼퍼도 도구 고르기에서 추천을 '고를 예정'으로 표시해 두고, [추천대로 정하기] 한 번으로 꼭 고를 것을 다 채울 수 있게 할 수 있다. 기능마다 한 번씩 누르는 것보다 탭이 크게 준다. 이건 제품 결정(추천 강요로 보일 위험)이라 DECISIONS에 적고 정한다.
2. **확인 단계를 건너뛰지 않기.** Lyft Silver는 초심자에게 출발·도착 확인을 의무로 만들었다. 3단계는 막힌 곳이 없어도 한 화면으로 지나간다("모두 원활해요" + [출발하기]).
3. **쉬운 모드.** Uber Simple mode와 Lyft Silver는 글자 1.4배, 버튼 줄이기, 상담 버튼을 넣었다. 코드쇼퍼 설정에 '글자 크게'(1.25~1.4배)를 두고, 사전 버튼은 늘 머리줄에 둔다(이미 있음). 드래그로 낱말 풀이를 보는 새 기능은 이 '도움이 늘 가까이' 원칙의 연장이다.

- 첫 화면에 지도(200)와 도구 두 줄이 함께 보인다. Uber의 차종 고르기 화면처럼 '지도 위 결과 + 아래 고를 것'이 한 화면에 들어간다.
- 끄는 시트는 넣지 않는다. 문서 흐름 안에 두고 손잡이도 그리지 않는다. 끌기 대신 쓸 방법(WCAG 2.5.7)을 따로 만들지 않아도 되고, 모바일 웹에서 스크롤과 끌기가 부딪치지 않는다.
- 768px 이상에서는 시트 내용 최대 폭을 640으로 둔다(Material 3의 시트 최대 폭과 같다). 1024px 이상은 지금처럼 왼쪽 패널 + 오른쪽 지도로 나눈다.
- 도착 화면(설계도 받기)의 위계는 Uber 진행 화면 순서를 따른다: **상태(도착했습니다 · 요금 0원) → 무엇을 받았나(설계도 1부 · 영수증 1장…) → 세부 탭.**

### 3.4 지도 스타일 명세 (로고 색으로)

대비는 직접 계산했다(WCAG 2.x 상대 휘도).

| 요소 | 낮 지도 | 밤 지도 | 근거 |
|---|---|---|---|
| 땅 | #EEF2F7 | #0A1328 (로고 남색 쪽으로 기운 어둠) | Uber처럼 회색조 바탕, 경로가 주인공 |
| 블록 / 길 / 길 테두리 | #E3E9F1 / #FFFFFF / #CDD5E1 | #101B35 / #1A2747 / #233257 | 장식이라 대비 기준 없음 |
| 물 / 공원 | #D3E3F5 / #DDE9DF (채도 낮게) | #0E1E3D / #0F2229 | 원색 바다·형광 잔디 금지 유지 |
| **내 길 (이어진 길)** | 바깥 **8px #001E5A** + 심 **4px #00B4FA**, 끝·이음 둥글게 | 심 **4px #00B4FA** + 둘레 **14px #00B4FA 25%** (흐림 필터 없이 넓은 선 하나) | Google 테두리 경로 9/5 비율. 남색 대 땅 14.0:1. 청록은 흰 바탕에 2.36:1이라 낮에는 혼자 못 씀. 밤 청록 대 땅 7.8:1, 로고 전조등과 같은 빛 |
| 아직 나지 않은 길 | 3px #7D879A 점선 (둥근 끝, 대시 0·간격 7 → 점) | 3px #8994AA 점선 | Google: 남은 구간은 흐리게·숨김. 땅 대비 낮 3.2:1 · 밤 6.1:1 |
| 지금 여는 마디 | 마디 둘레 3px #0082FA 고리 | 3px #4DA8FF 고리 | 그림 요소 3:1 기준: 낮 땅 3.35:1, 밤 7.4:1 |
| 고른 마디 | #001E5A 채움 + 흰 그림 | #E6ECF7 채움 + #0A1328 그림 | 모양으로 기능 구분(지금 CONCEPT 유지) |
| 출발 | 지름 16 남색 원 + 흰 가운데 6 | 밝은 원 + 어두운 가운데 | Uber 픽업 = 원 |
| 목적지(빈 터) | 둥근 네모 터 + 남색 네모 표시 + 깃발 | 같음, 청사진 선은 #7FA7FF | Uber 하차 = 네모. 모양으로 출발과 나눔 |
| 차 | 위에서 본 렌더 길이 44px, 남색 몸체 + 청록 전조등 띠(로고와 같은 차), 그림자는 오른쪽 아래 2·3px | 같음 + 전조등 앞 부채꼴 빛 12% | Uber·Tesla 모두 위에서 본 차. 로고의 정면 차는 지도 밖(홈 머리, 도착 카드)에만 |
| 교통 색 | 원활 #15803D · 서행 #B45309 · 막힘 #C8372D | #34D399 · #FBBF24 · #F87171 | TOPIS 낱말. 늘 그림 + 글과 함께 |
| 이름표 | 14px/700 #0B1530, 땅색 3px 테두리(`paint-order: stroke`) | #E6ECF7 + 땅색 테두리 | 길 위에서도 읽힘 |

- **금색은 로고에 없다.** 지금 CONCEPT의 '남색 + 금색 심' 경로, 금색 칩·꼬리표·도장은 로고 색 체계와 부딪친다. 경로 심은 청록으로, '추천' 꼬리표는 남색 테두리 알약으로, 요금 0원 칩은 청록 점 + 남색 글자로 바꾸는 쪽을 권한다. 따뜻한 색이 꼭 필요하면 영수증 도장 하나(빨강 #C8372D)에만 남긴다.
- 밤 지도 장면(S5 출발 → 도착)은 로고 그림과 같은 분위기를 내기에 가장 좋은 자리다. 남색 밤 + 청록 전조등 + 빛나는 경로. Uber의 밤 지도처럼 따로 정한 팔레트로 만들고, 낮 색을 반전하지 않는다.
- 모션 곡선은 Base Web 값을 빌린다: 들어오기 `cubic-bezier(0.22,1,0.36,1)`, 나가기 `(0.64,0,0.78,0)`, 카메라 이동 `(0.4,0,0.2,1)`. 길이는 지금 토큰(120~700ms) 그대로 둔다.

### 3.5 상태 한 줄 문장 틀

틀: **[단계 짧은 이름] · [남은 일 개수] · [약 n분]**. 처음 보는 단계에서만 한 문장짜리 기사 메시지를 함께 보인다. 쓰는 곳은 아래 막대 위 줄, 낭독은 바뀔 때만.

| 단계 | 상태 한 줄 (보통) | 다 됐을 때 | 막혔을 때 |
|---|---|---|---|
| AI 써 보기 | 연습 · 3개 중 1개 했어요 | 연습 · 다 했어요 | — |
| 목적지 정하기 | 목적지 · 질문 6개 남음 · 약 2분 | 목적지 · 정했어요 | — |
| 도구 고르기 | 도구 · 꼭 고를 것 1개 남음 · 약 1분 | 도구 · 꼭 고를 것을 다 골랐어요 | 도구 · 맞는 도구가 없는 기능 1개 |
| 길 확인하기 | 길 확인 · 막힌 곳 1개 | 길 확인 · 모두 원활해요 | 길 확인 · 막힌 곳 2개 (출발하기 꺼짐 + 이유) |
| 설계도 받기 | 도착 · 설계도와 영수증을 받았어요 | — | — |

- '약 n분'은 남은 질문 × 15초, 남은 고를 것 × 30초로 계산하고 1분 단위로 올린다. 답할 때만 다시 계산한다. 1초마다 줄어드는 초읽기와 "서두르세요"류 말은 쓰지 않는다(CONCEPT 5.9의 '남은 시간 세기' 금지와 같은 뜻).
- 카카오 T의 "도착 예정 시각 + 차량 번호" 순서처럼 **시간·개수를 먼저, 이름을 뒤에** 둔다. 360px에서 한 줄 24자 안쪽이다.
- 기사 메시지는 "기사님이 n분 뒤 도착해요" 같은 호출 앱 말투를 흉내 내지 않는다. 대신 다음 행동을 말한다: "들르는 곳마다 도구를 하나씩 골라요. 맨 위가 추천이에요."

### 3.6 고급스러움을 코드쇼퍼에 옮기기

| 호출 앱의 신호 | 코드쇼퍼에서 |
|---|---|
| 색 하나만 강조(Uber, TMAP) | 화면의 강조는 파랑 계열 하나. 로고의 세 색(남색·파랑·청록)은 지도·차·로고 장면에서만 함께 쓴다 |
| 값 미리 밝히기(카카오 T 예상 요금, Blacklane 정액) | 믿음 줄 "요금 0원 · 회원가입 없음 · 광고·제휴 없음"을 홈과 도착에 둔다. 도구 비용은 고르기 전에 보인다 |
| 무료로 기다림(Blacklane 15·60분) | "천천히 하셔도 돼요. 진행은 이 브라우저에 남아요." → [이어서 가기] |
| 취향 설정(Uber Black 조용히 가기) | 설정에 **조용히 모시기**: 기사 메시지 숨기기 + 효과음 끄기 + 장면 짧게. '동작 줄이기'와 따로 둔다 |
| 신원 확인(차량 번호, 탑승 확인번호) | 영수증 번호(예: "영수증 0427")를 영수증 머리와 영수증 링크 미리 보기에 같게 찍는다. 같은 영수증인지 한눈에 확인한다 |
| 의도 보이기(Waymo) | '이렇게 이해했어요'(답 요약)와 추천 이유를 늘 펼칠 수 있게 둔다. 지도는 엔진 상태를 그대로 그리는 그림이다 |
| 큰 숫자, 짧은 말 | 비용·개수·시간은 숫자 같은 폭 600 굵기, 제목은 22~24/700 |

### 3.7 하지 말 것

- 가짜 기다림: '배차 중…', '길 찾는 중' 스피너를 일부러 늘리는 것. 엔진은 바로 계산한다.
- 노랑이 주인공인 화면(카카오 T처럼 보임), 흑백만 쓰는 화면(Uber 복제처럼 보임). 로고의 남색·파랑으로 우리 것을 만든다.
- 끌 수 없는 시트에 손잡이 그리기.
- 별점·'이 기사 또 만나기'·평가 요청. 추적하지 않는다는 원칙과 어긋난다.
- 실제 회사의 차종 이름(블루, 블랙, UberX)이나 실제 지도 자료 흉내.
- 청록을 흰 바탕의 글자나 가는 선으로 혼자 쓰기(2.36:1). 흰 글자를 파랑 #0082FA 위에 얹기(3.77:1).
