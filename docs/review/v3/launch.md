### 0.2 이미 출시 수준인 것 (지키기만 하면 된다)

- **접근성 자동 점검 만점:** Lighthouse 13.5.0 모바일 접근성 100점(5개 화면), 기존 e2e의 axe 검사, 320px 다시 흐르기에서 가로 스크롤 0(14개 화면), 글자 200%에서 가로 스크롤 0(5개 화면) [잼].
- **권장 사항 100점, 콘솔 오류 0:** 19개 라우트 360px에서 페이지 오류·콘솔 오류 없음(없는 주소의 404 응답 한 줄만) [잼]. 외부 요청 0 [잼].
- **오류·빈 상태가 다 있다:** 깨진 영수증 링크 → "영수증 링크를 열지 못했어요." + 처음 화면 버튼, 저장이 막힌 브라우저 → "이 브라우저에서는 진행 상황이 저장되지 않아요." 안내와 오류 0, 지난 영수증 0장 → 안내 + [만들 앱 정하기], 잠긴 단계 → 까닭 한 줄 + 갈 곳 버튼 [잼].
- **망가진 저장 값에 강하다:** 깨진 JSON·엉뚱한 모양·지워진 도구 id를 넣고 7개 화면을 열어도 오류 0, 화면은 처음 온 사람처럼 열린다 [잼].
- **보안 머리글:** CSP(해시), `frame-ancestors 'none'`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP이 이미 있다 [확인 `public/_headers`, `astro.config.mjs`]. 빠진 것은 HSTS 하나(L-26).
- **제목이 모두 다르다:** 85쪽 `<title>` 중복 0 [잼].

### 0.3 GitHub Pages 404에 대해 (소유자 요청 1과 이어짐)

GitHub Pages는 이 사이트의 배포 대상이 아니다(D72). 무료 요금제에서는 비공개 저장소에 Pages를 쓸 수 없고, Astro 원본을 그대로 올리면 빌드 결과(`dist/`)가 없어 어차피 404가 난다. 배포는 Cloudflare Workers Builds가 `npm run build:cf`로 한다(`docs/DEPLOY.md`). 저장소 폴더 정리는 v3-0 작업에서 따로 다룬다. 이 문서의 모든 명세는 Cloudflare 배포를 전제로 한다.

### 1.2 한계

- **실제 기기와 실제 브라우저로 보지 못했다.** 소유자는 Claude in Chrome·컴퓨터 사용·내부 브라우저로 실측하라고 했지만, 이 세션에는 그 도구가 없어 헤드리스 Chromium만 썼다. 카카오톡·네이버 앱 안 브라우저, 아이폰 Safari, 삼성 인터넷, 화면 낭독기(VoiceOver·TalkBack·NVDA)는 L-12의 표로 넘긴다.
- **로컬 서버는 압축을 하지 않는다**(`scripts/qa/serve.ts`). Lighthouse의 LCP·문서 지연 값은 실제 Cloudflare(압축함)보다 나쁘게 나온다. 미리 보기 배포 뒤 PageSpeed Insights로 다시 잰다(L-28).
- 미리 보기 단계(`PUBLIC_STAGE` 없음)로 빌드했다. 그래서 `noindex`와 `Disallow: /`가 붙어 있고, Lighthouse 검색 점수 66은 그 때문이다(예상한 값).

### 1.3 조사 방법과 믿을 수 있는 정도

- 이 환경의 네트워크 정책이 대부분의 참고 사이트(webkit.org, design-system.service.gov.uk 등)를 막아 원문을 열지 못했다(`connect_rejected`). 그래서 대부분 **[검색 요약]**이다. 사실을 화면 문구에 옮길 때는 원문을 다시 확인한다.
- **[확인]**으로 읽은 것: Front-End Checklist 저장소(thedaviddias/Front-End-Checklist, 커밋 e8d14d0, 2026-10-06, 규칙 391개)를 받아 규칙 파일을 직접 읽었다. npm 등록 정보로 `lighthouse` 13.5.0, `@astrojs/sitemap` 3.7.4, `@vite-pwa/astro` 1.2.0의 판을 확인했다.
- 카카오 관련 사실은 공식 문서가 아니라 카카오 개발자 포럼(devtalk) 답변과 개인 블로그다. 기기에서 확인하기 전에는 화면에 단정하는 문장으로 쓰지 않는다.

### 3.3 한국에서 쓰는 환경

**L-05 카카오톡 등 앱 안 브라우저에서 설계도 받기 (P0, 에이전트 M + 기기 확인)**
- 빠진 것: [설계도 내려받기 (.md)]는 `new Blob` → `URL.createObjectURL` → `a.download`로 받는다 [확인 `src/components/ArrivalAction.tsx`]. 공유 단추는 이미 인앱 브라우저를 가려 링크 복사로 돌린다(`Receipt.tsx`의 `canWebShare`). 내려받기는 가리지 않는다.
- 근거: 카카오 개발자 포럼 답변 — 카카오톡 인앱 브라우저는 OS 웹뷰 위에 있고 웹뷰는 내려받기를 기본으로 주지 않는다. blob·dataURL 방식은 안드로이드 웹뷰에서 동작하지 않고, `<a download>`는 안드로이드만, dataURL은 iOS만, 서버 응답 머리글(`Content-Disposition: attachment`) 방식은 둘 다 된다 [검색 요약]. 우리는 서버로 영수증 상태를 보내지 않으므로(R-04) 머리글 방식을 쓸 수 없다. 교사가 학생·동료와 링크를 나누는 길은 대부분 카카오톡이다.
- 명세:
  - `src/lib/inapp.ts`(순수 함수, 시험): `inAppBrowser(ua): 'kakao' | 'naver' | 'instagram' | 'facebook' | 'line' | null`. `Receipt.tsx`의 정규식을 이리로 옮긴다.
  - 설계도 받기 아래 막대: 인앱이면 주 버튼을 [설계도 복사]로 바꾸고(복사는 인앱에서도 된다), 그 위 한 줄 "{앱 이름} 안에서는 파일 저장이 안 될 수 있어요." + 글 버튼 [다른 브라우저로 열기]. 
  - [다른 브라우저로 열기]: 카카오톡·안드로이드면 `kakaotalk://web/openExternal?url=` + `encodeURIComponent(영수증 링크)`로 이동한다(누르는 동작 안에서만. 페이지가 열리자마자 부르면 막힌 사례가 보고됐다) [검색 요약: 개인 Gist·데브톡, 공식 문서 아님]. 그 밖(아이폰 카카오톡, 네이버·인스타그램 앱)은 시트로 안내한다: "오른쪽 아래(또는 위) 메뉴에서 '다른 브라우저로 열기'나 'Safari로 열기'를 골라 주세요. 영수증 링크가 함께 넘어가요." 영수증 링크를 먼저 복사해 둔다(넘어가지 않을 때 붙여 넣게).
  - 홈 첫 방문이 인앱이면 홈 시트 맨 위 한 줄(기사 메시지 아님, 닫기 가능): "{앱 이름} 안에서 열었어요. 기록은 이 창에만 남아요." + [다른 브라우저로 열기].
  - 시험: e2e에서 사용자 에이전트에 `KAKAOTALK`를 넣고 주 버튼이 [설계도 복사]인지, 복사 알림이 나오는지.
  - 기기 확인(H-R1): 안드로이드·아이폰 카카오톡에서 ① 지금 내려받기가 실제로 실패하는지 ② `openExternal`이 되는지 ③ 넘어간 브라우저에 `#r=`가 살아 있는지.

**L-24 기록이 사라질 수 있는 환경 알리기 (P1, 에이전트, S)**
- 빠진 것: 진행과 영수증은 localStorage에만 있다. 인앱 브라우저의 저장소는 기본 브라우저와 따로이고, 아이폰 Safari는 지능형 추적 방지가 켜져 있으면 '7일 동안 그 사이트와 상호작용이 없으면 스크립트가 쓴 저장소(localStorage 포함)를 지운다'는 정책을 2020년(Safari 13.1)에 발표했다. 홈 화면에 추가한 웹 앱은 따로 센다 [검색 요약: WebKit 블로그 원문은 열지 못함, 2020~2022 자료라 지금 동작은 미확인].
- 근거: Ink & Switch '로컬 우선 소프트웨어'의 일곱째 이상 "최종 소유와 통제는 이용자에게" [검색 요약]. Front-End Checklist `web-storage` [확인].
- 명세: ① 지난 영수증 화면 머리 아래 꼬리 글 "브라우저가 오래 쓰지 않은 사이트의 기록을 지울 수 있어요. 중요한 영수증은 링크를 메모에 남기거나 '내 기록 내려받기'로 저장해 두세요." ② L-18의 내려받기를 같은 자리에 둔다. ③ (P2) 영수증을 처음 받을 때(누르기 동작 안) `navigator.storage.persist()`를 한 번 부른다. Safari 15.2부터 지원하고, 브라우저에 따라 묻는 창이 뜰 수 있다 [검색 요약: web.dev]. 묻는 창이 초심자를 놀라게 할 수 있으니 관찰 시험에서 본 뒤 켠다.

### 3.4 내 기록

**L-18 내 기록 내려받기·불러오기 (P1, 에이전트, M)**
- 빠진 것: 다른 브라우저·기기로 옮기는 길이 영수증 링크 한 장씩뿐이다. 진행 중인 답, 읽은 용어, 지난 영수증 30장을 한 번에 옮길 수 없다 [잼: 저장 키 4~6개].
- 근거: 로컬 우선 소프트웨어(위), Nielsen 원칙 3 '이용자 통제와 자유'(비상구) [검색 요약].
- 명세:
  - 설정 시트 '내 기록' 묶음에 [내 기록 내려받기], [내 기록 불러오기].
  - 파일: `codechauffeur-records-YYYYMMDD.json`, 모양 `{ "app": "codechauffeur", "v": 1, "savedAt": "ISO", "keys": { "cc:session:v1": …, "cc:study:v1": …, "cc:meta:v1": …, "cc:seen:v1": …, "cc:receipts:v1": …, "cc:terms:v1": …, "cc:drafts:v1": …, "cc:prefs:v1": … } }`. 읽기·쓰기는 `src/lib/store.ts`에만(CLAUDE.md 꼭 지킬 것 2). 모양 고르기는 `saved.ts`의 기존 함수를 그대로 써서 모르는 키·틀린 값은 버린다.
  - 불러오기: `<input type="file" accept=".json,application/json">`, 200KB 넘으면 거절, 확인 대화 상자 "지금 기록을 이 파일 내용으로 바꿀까요? 지금 기록은 '만들다 만 것'에 남겨 둘게요." → 바꾼 뒤 L-19의 [되돌리기] 띠.
  - 인앱 브라우저에서는 내려받기 대신 "다른 브라우저에서 내려받아 주세요" 안내(L-05와 같은 까닭).
  - 문구 견본: "내 기록 내려받기" · "내 기록 불러오기" · "기록을 파일로 저장했어요." · "이 파일은 코드쇼퍼 기록이 아니에요." · "기록을 불러왔어요."
  - 개인정보: 파일은 이용자 기기에서만 오간다. 처리방침 '내 브라우저에 저장되는 것'에 한 줄 더한다.

**L-19 만들다 만 것(여러 앱)과 되돌리기 (P1, 에이전트, M)**
- 빠진 것: 다시 온 손님이 [새로 만들 앱 정하기]·[이 코스로 출발]·[이 영수증으로 이어서 가기]를 누르면 확인 대화 상자가 "되돌릴 수 없어요"라고 말하고 지금 답과 고른 도구를 지운다(`ko.home.freshBody`, `overwriteBody`, `receipt.continueBody`) [확인]. 영수증을 받기 전의 앱은 하나만 둘 수 있다.
- 근거: Nielsen 원칙 3(되돌리기·다시 하기) [검색 요약]. 교사는 한 학기에 앱을 여럿 구상한다(PRD 대상).
- 명세:
  - 새 키 `cc:drafts:v1`: `{ id, savedAt, title, session }[]`, 최대 5개(넘치면 가장 오래된 것을 빼고 알린다). `title`은 앱 종류 이름 + 한 줄 입력 앞 20자. 지우거나 바꾸는 세 동작 직전에, 답이 하나라도 있으면 지금 세션을 여기에 넣는다.
  - 확인 대화 상자 본문을 "지금 고른 것은 '만들다 만 것'에 남겨 둘게요."로 바꾼다.
  - 바꾼 직후 화면 맨 위에 닫을 수 있는 띠: "비우고 새로 시작했어요. [되돌리기]". 저절로 사라지지 않는다(시간 제한 없는 알림. 토스트처럼 사라지면 화면 낭독기·느린 이용자가 놓친다). 다음 화면으로 가면 걷힌다.
  - 지난 영수증 화면 맨 위에 '만들다 만 것' 묶음(0개면 그리지 않음). 줄: 미니 지도 + 이름 + "2026-10-14 · 2/4 도구 고르기". 누르면 확인 뒤 지금 것과 맞바꾼다.
  - '저장한 기록 지우기'도 같은 띠로 되돌릴 수 있게 한다(메모리에만 사본, 페이지를 떠나면 버림).
  - ARCHITECTURE 4절 키 표, 설정의 지우기 대상(일곱 키), 시험을 함께 고친다.

### 3.5 도움·의견·정보

**L-06 의견 보내기와 문의 (P0, 에이전트 S + 사람 주소)**

  - 빌드 변수 `PUBLIC_CONTACT_EMAIL`(비밀 아님). 정식 빌드에서 비어 있으면 실패(L-04와 같은 검사).

**L-16 화면 색: 기기 따라 · 낮 지도 · 밤 지도 (P1, 에이전트, M)**
- 빠진 것: 밤 지도는 기기 설정으로만 켜진다(UX.md, CONCEPT 5.3, BACKLOG '화면'). 
- 근거: 카카오톡 설정 → 테마의 세 갈래(시스템 설정 모드가 기본, 라이트, 다크) [검색 요약: 블로그]. Front-End Checklist `dark-mode-css` [확인]. CSS `light-dark()`는 2024년 기준선(Chrome 123, Firefox 120, Safari 17.5)이고, `color-scheme`을 `light dark`로 두면 기기를 따르고 `light`·`dark`로 고정하면 그 값을 따른다 [검색 요약: MDN].
- 명세:
  - `cc:prefs:v1`에 `scheme: 'system' | 'light' | 'dark'`(기본 `system`)를 더한다(빠진 값은 기본, 키 판은 그대로).
  - 기본 틀 머리 스크립트(첫 그림 전)가 `html[data-scheme]`과 `style.colorScheme`을 붙인다. `<meta name="theme-color">` 두 줄도 고른 값에 맞게 하나로 바꾼다.
  - 토큰: 두 길 중 하나를 D73에서 정한다. (가) 색 토큰을 `light-dark(낮, 밤)`으로 옮기고 `:root { color-scheme: light dark }`, 그림자 같은 색이 아닌 값만 `[data-scheme]`·미디어 쿼리 짝으로. Safari 17.5 미만(아이폰 iOS 17.4 이하)은 낮 지도로만 보인다. (나) 지금의 미디어 쿼리 다섯 곳(`tokens.css` 셋, `frame.css`, `parts.css`)을 `:root:not([data-scheme='light'])`로 감싸고 같은 값을 `:root[data-scheme='dark']`에 한 번 더 둔다. 압축 후 약 1.1KB가 늘어 설계도 받기 CSS가 29.5/30KB가 된다 [잼: 밤 블록 3,392바이트, gzip 1,098바이트]. **(가)를 권한다**: 값이 한 곳이라 어긋나지 않고 CSS가 늘지 않는다. 대비 검사(`npm run tokens`)가 `light-dark()` 짝을 읽게 고친다.
  - 조작: `<fieldset>` + 진짜 라디오 셋을 칩 모양으로(인터뷰 보기의 D19 '라디오 금지'는 질문 보기에만 해당). 이름 "화면 색", 보기 "기기 따라" · "낮 지도" · "밤 지도".

**L-17 글자 크기 (P1, 에이전트, S)**
- 빠진 것: 사이트 안 글자 크기 설정 없음. 토큰이 rem이라 브라우저 설정은 따른다(200% 통과) [잼].
- 근거: 카카오톡도 글자 크기를 따로 고르게 한다(기본 15pt) [검색 요약: 블로그]. 대상이 교사·직장인이고, 휴대폰 브라우저의 글자 크기 설정은 찾기 어렵다. Front-End Checklist `text-resizing`(높음) [확인].
- 명세: `cc:prefs:v1.text: 'base' | 'large' | 'larger'`(기본 `base`), 머리 스크립트가 `html[data-text]`를 붙이고 `tokens.css`에 `:root[data-text='large'] { font-size: 112.5% }`, `'larger'`는 125%. 보기 "보통" · "크게" · "아주 크게". 지도 이름표는 커지지 않으므로(UX.md 접근성 확인표) 같은 뜻을 시트 글이 가진다. 시험: 세 값 × 단계 화면 다섯에서 가로 스크롤 0, 주 버튼이 아래 막대 안에 보임.

### 3.8 인쇄

**L-20 설계도 받기와 용어 카드 인쇄 (P1, 에이전트, M)**
- 빠진 것: `@media print` 규칙 0 [확인 `src/styles`]. A4로 찍으면 화면 그대로 찍히고 아래 막대가 영수증 위에 겹치며 설계도는 안 나온다 [잼 `flow-arrival-print.png`, `arrival-print.pdf`].
- 근거: Front-End Checklist `css-print`(중간) [확인]. 교사는 연수·수업 자료로 종이에 뽑는다(BACKLOG '연수 키트').
- 명세:
  - `src/styles/print.css`를 설계도 받기·용어 카드·도구 상세에서만 불러온다. 전부 `@media print { … }` 안(압축 후 1KB 이하, CSS 예산 안).
  - 숨김: `.topbar`, `.rail-wrap`, `.action-bar`, `.site-footer`, 지도 띠, 기사 메시지 닫기, 모든 `button`, 어려운 말 풀이 시트, 장면 [건너뛰기].
  - 설계도 받기: 칸 고르개 네 칸의 내용을 모두 차례로 찍는다(`.ar-panel[hidden] { display: block }` — 패널은 이미 DOM에 `hidden`으로 있다 [확인 `Receipt.tsx` 196줄]). 설계도 미리 보기 `<details>`는 닫힌 채면 찍히지 않으므로 `beforeprint`에서 열고 `afterprint`에서 되돌린다. 영수증 종이 `break-inside: avoid`, 칸마다 `break-before: page`.
  - 글자 검정, 바탕 흰색, 링크는 바깥 링크만 뒤에 주소를 붙인다(`a[href^="http"]::after { content: " (" attr(href) ")" }`).
  - 마지막 쪽 아래에 사이트 주소 한 줄(`@page` 여백 글은 지원이 고르지 않아 본문 끝에 둔다).
  - (P2, L-38) 설계도 받기 '더 보기'에 글 버튼 [인쇄하기] → `window.print()`.
  - 시험: e2e에서 `emulateMedia({ media: 'print' })` 뒤 아래 막대가 안 보이고 설계도 제목이 보이는지.

### 3.13 고르는 곳마다 직접 쓰기 (소유자 요청 5)

**L-07 (P0, 에이전트, L)** — 지금 직접 쓰는 칸은 만들 앱 정하기 마지막의 한 줄(80자, R-18)뿐이다 [확인]. `design.md`(느낌·색·글꼴·바라는 점·닮고 싶은 앱)와 `aitools.md` 9.2절(AI 종류·도구 이름)이 각자의 자리를 설계했다. 남은 자리와 공통 규칙만 여기에 둔다.

| 고르는 곳 | 직접 쓰면 | 엔진에 들어가는 것 | 설계도 |
|---|---|---|---|
| 어떤 앱을 만들까요? (`q.type`) | 보기 일곱 아래 타일 "직접 쓸게요" → 한 줄(40자). 이 글이 지금의 마지막 한 줄 입력(`freeText`)을 채우고, 마지막 질문에서는 고쳐 쓸 수 있게 미리 채운다 | 낱말표(`data/free-words.json`, AI 없음)로 가장 가까운 종류를 미리 누르고 "'독서 기록장' → 기록장으로 골랐어요. 다르면 바꿔 주세요."라고 말한다. 못 찾으면 고르게 한다 | 1번 '만들 것'에 "내 말 그대로" 줄 |
| 누가 쓰나요? (`q.audience`) | "직접 쓸게요" → "예: 학부모 30명" | 가까운 칸을 고르게 한다(숫자가 있으면 '몇 명이 같이'를 미리 누름) | '쓰는 사람' 줄에 원문 |
| 밖에서 가져올 정보 (`q.domain`)와 주제 질문 넷 | "직접 쓸게요" → "예: 우리 지역 도서관 휴관일" | 낱말표로 분야·주제를 미리 누름. 못 찾으면 '그 밖의 공공 정보' + 알아볼 것에 "이 정보를 주는 공식 API가 있는지" 한 줄 | 9번 '알아볼 것'에 원문 |
| 도구 고르기 (기능마다) | 칸 맨 아래 "목록에 없는 도구 쓰기" → 이름(30자) | 세션에 `custom: { [칸]: 이름 }`. 점수·추천 없음, 꼬리표 "주의: 직접 확인 필요", 막힌 곳 검사는 '모름'으로 다루고 알아볼 것에 "{이름}이 이 기능을 맡을 수 있는지" | 5번 '쓸 도구'에 이름 + "(직접 고름)" |
| 막힌 곳 '그대로 가기' | (선택) "까닭 한 줄" | 없음 | 9번에 원문 |
| 예·아니요 질문 (`q.save` 등) | 직접 쓰기를 두지 않는다 | — | 네 보기에 '모르겠어요'가 있어 빈 곳이 없다. 모든 질문 아래 "질문이 맞지 않으면 마지막에 한 줄로 적어 주세요" 안내로 대신한다 |

공통 규칙: ① 화면은 AI를 부르지 않는다. 직접 쓴 말은 낱말표로만 읽고, 무엇으로 읽었는지 글로 말한다(R-01). ② 원문은 설계도에 "내 말 그대로"로 넣어 사용자의 AI가 해석한다. ③ **영수증 링크(`#r=`)에는 원문을 넣지 않는다**(R-18 개인정보 원칙). 단 직접 쓴 **도구 이름**은 영수증을 다시 만들려면 필요하므로 넣을지 D73에서 정한다(권장: 넣되 30자·3개 제한). ④ `<label>` + 도움말 `aria-describedby`, 글자 수 표시, 이름·학교 이름을 쓰지 말라는 한 줄(R-18과 같은 문장). ⑤ 엔진 동작이 바뀌므로 ENGINE.md·골든·`npm run examples`를 함께 고친다(CLAUDE.md 꼭 지킬 것 4). GOV.UK 라디오는 '그 밖'을 고르면 관련 질문을 바로 아래에 펼치고, 펼친 질문이 복잡하면 다음 화면으로 보내라고 한다 [검색 요약] — 우리 '직접 쓸게요' 타일도 같은 화면 안에서 한 줄만 펼친다.

### 3.14 작은 것 (P2)

- **L-37** 영어 낱말(도구 이름)에 `lang="en"`을 붙일지: 한국어 낭독기는 대부분 잘 읽는다. 관찰 시험에서 어색하면 넣는다(WCAG 3.1.2).

- **L-40** 홈 시트의 "시험판이에요" 줄이 바닥글과 겹친다(미리 보기에서만). 홈 시트 쪽을 뺀다.
