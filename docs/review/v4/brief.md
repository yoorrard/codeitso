# v4 개편 설계서 (2026-10-14)

소유자 요청(2026-10-14)을 한 문서로 정리한다. 이 문서가 v2 컨셉(`docs/CONCEPT.md`의 게임 세계)과 v3 설계서의 **화면 표현**보다 앞선다. v3의 기능(직접 쓰기, 디자인 정하기 엔진, 만들기 안내, 다음 할 일, AI 설정 파일, 출시 준비)은 그대로 살리고, 보여 주는 방식만 바꾼다.

## 0. 소유자 요청 (요지)

1. PC 넓은 화면에서 여백이 많고 비율이 이상하다. 큰 플랫폼처럼 유연한 반응형으로.
2. 문체는 요체가 아니라 **다체('~다.')**. 쉽게 쓰되, 일상 외래어와 업계 용어는 풀어 쓰지 않는다.
3. 스크롤이 너무 많다. 특히 PC에서 첫 화면에 다 보여야 한다.
4. 초보자에 맞춘 풀어 쓰기가 오히려 어렵다(무료 채팅·앱에서 개발·유료 구독·코딩 에이전트 등). **표준 용어 + 예시 플랫폼 이름**, 어려운 말은 드래그 풀이.
5. **게임 요소를 모두 걷어 낸다.** 그래픽은 하나만: 답할 때마다 바뀌는 **실시간 설계도**.
6. 되는 조합이 '막힘'으로 나온다. 사전 버튼이 밀리고 시트가 안 닫힌다. 오류가 많다. 디자인 고르기가 허술하다.
7. 디자인은 최대한 단순하게. 그래픽은 부품이 선으로 이어져 **연결망처럼 조립되는 느낌**.

## 1. 결정 (DECISIONS D96~D101로 옮긴다)

- **D96 게임 요소 제거.** 지도·차·장면 S1~S9·효과음·교통 비유·영수증 출력/도장 연출·연습 고리·구운 3D 렌더·지도 토큰을 지운다. 남기는 것: 이름 '코드쇼퍼', 로고(브랜드 표시로만, 머리줄), 단계 흐름과 주소(`/destination` `/waypoints` `/check` `/arrival` 등 그대로), 엔진, 저장·공유 링크, 직접 쓰기, 디자인 정하기 엔진(`look*.ts`), 풀이 팝오버, 도구·용어 페이지.
- **D97 실시간 연결망 설계도**(2절)가 유일한 그래픽이다.
- **D98 레이아웃과 스크롤 예산**(3절).
- **D99 문체 다체 + 표준 용어**(4절).
- **D100 디자인 고르기 v2**(5절).
- **D101 막힘 규칙 정정**(6절): 공식 문서로 확인한 규칙만 '충돌'로 막고, 고르는 방법으로 풀 수 있는 것은 '주의'로 낮춘다.

## 2. 실시간 연결망 설계도

- **모델:** `src/lib/graph/model.ts`의 순수 함수 `blueprintGraph(result, opts)`가 `evaluate()` 결과를 노드·선으로 바꾼다. 추천·점수 계산은 하지 않는다(엔진 결과만 읽음). 같은 입력이면 같은 배치(난수·시각 없음). 단위 시험.
- **노드 셋 층:** ① 앱(가운데 하나: 앱 이름 또는 종류) ② 기능(화면·저장·로그인·외부 데이터·알림·배포, 엔진의 칸 순서 그대로; 필요 없는 기능은 그리지 않음) ③ 도구(고른 도구 이름 + 비용 배지 '0원'/'유료'/'확인 필요').
- **선:** 앱–기능(필수는 실선, 선택은 점선), 기능–도구(정함은 실선, 아직은 점선 + '도구 고르기'), 도구–도구(엔진의 충돌·주의가 걸린 짝을 잇는 선: 충돌은 굵은 선 + ✕, 주의는 점선 + !).
- **상태 표시는 색만으로 하지 않는다:** 아이콘(✓ ! ✕ 빈 원) + 짧은 글 + 선 모양.
- **배치:** 층별 고정 열(왼→오: 앱 · 기능 · 도구). 휴대폰(<600px)은 위→아래 나무 꼴(앱 → 기능 줄마다 도구가 오른쪽). 노드 크기 고정, 글자는 한 줄 말줄임 + `title`.
- **움직임:** 새 노드는 150ms 나타남, 새 선은 200ms 그려짐. 동작 줄이기면 없음. 장면·카메라·효과음 없음.
- **접근성:** SVG는 `role="img"` + 요약 `aria-label`. 바로 아래(또는 '목록으로 보기' 토글)에 같은 내용의 목록(기능 → 도구 → 상태). 2·3단계에서 기능 노드를 누르면 그 칸이 열린다(진짜 `<button>`/링크, 키보드 가능).
- **놓는 곳:** 1~4단계 모두. ≥1024px: 오른쪽 고정 창(sticky). 600~1023px: 위쪽 카드(높이 220, 펼치기). <600px: 위쪽 작은 카드(높이 140, 눌러 전체 보기 시트). 홈: 미리 짠 코스 하나의 완성 그래프를 소개 그림으로.
- **4단계:** 그래프 전체 + 칸(영수증→'비용 요약', 설계도, 다음 할 일, 프롬프트).

## 3. 레이아웃과 스크롤 예산

- **구간:** compact <600 · medium 600~1023 · expanded 1024~1439 · large ≥1440. 토큰: `--bp-*`(문서용), `--container-max: 1360px`, `--pane-left: minmax(420px, 560px)`, 글자 크기는 `clamp()` 유동 척도(본문 16~17px, 제목 22~32px).
- **단계 화면(≥1024):** 두 칸 격자. 왼쪽 = 단계 표시줄 + 질문/도구 목록 + 주 버튼(아래 막대가 아니라 왼쪽 칸 안 고정 하단). 오른쪽 = 연결망 설계도(sticky, 높이 = 화면 − 머리줄). 가운데 정렬 640 단일 열과 큰 띠 그림은 없앤다.
- **보기(옵션) 배치:** 타일은 ≥600에서 2열, ≥1024 왼쪽 칸 안에서 2열; 목록 줄은 1열. 도움말·부가 설명은 접기.
- **둘러보는 곳(/tools /terms /receipts /dictionary 등):** 카드 격자 `repeat(auto-fill, minmax(280px, 1fr))`, 최대 1360. 읽는 글은 한 줄 최대 72ch.
- **스크롤 예산(e2e로 잰다):** 1440×900에서 각 단계의 현재 질문(또는 칸 제목)·보기 전부(최대 8개)·주 버튼이 스크롤 없이 보인다. 390×844에서 질문 + 보기 첫 4개 + 주 버튼(하단 고정)이 보인다. 홈은 1440×900 첫 화면에 소개·주 버튼·미리 짠 코스 셋이 보인다.
- **머리줄:** 로고 · 단계 표시줄(단계 화면) · 사전 · 설정. 사전 버튼 위치가 바뀌거나 밀리지 않는다(고정 폭).

## 4. 문체와 용어

- **문체:** 설명·도움말·상태·알림·오류·빈 상태 = '~다.' 질문 제목 = '~까?'(예: "어떤 앱을 만들까?"). 버튼 = 짧은 동사형/명사형(그대로). 법 문서(처리방침·이용 안내)는 '~다.'로 맞춘다. 프롬프트(사용자가 AI에게 하는 말)는 반말 '~해 줘' 그대로. 설계도 목록은 이미 '-ㄴ다'체.
- **외래어·업계 용어는 그대로 쓴다:** 테마, 폰트, 가이드, 체크리스트, 프리뷰, 다크 모드, 템플릿, 프롬프트, 배포, API, 깃허브, 클릭 등. `scripts/lib/words.ts`의 외래어 금지를 푼다. 옛 비유 금지(정류장 등)는 v4 비유(아래 '버림')로 바꿔 계속 막는다.

## 6. 막힘 규칙 정정

- 6개 충돌 규칙(`conflict.paid-on-free` · `realtime-mismatch` · `personal-server` · `key-in-static-page` · `key-on-public-host` · `shared-without-login`)과 칸 규칙을 공식 문서로 다시 확인한다. 확인 못 한 규칙, 또는 설정·선택으로 풀 수 있는 경우(예: 지역을 고를 수 있는 저장 서비스는 서울 지역을 고르면 됨, 유료 도구에 무료 등급이 있음)는 '충돌'이 아니라 '주의'로 낮추고 할 일을 적는다.
- 미리 짠 코스 다섯 + 무작위 답 300개 × 칸별 도구 조합을 돌려, 끝까지 '진행 불가'가 되는 조합 목록을 만든다. 실제로 되는 조합이 막히면 규칙을 고친다.
- 골든 기대값이 바뀌면 사례마다 이유 한 줄(커밋 메시지 `골든: case-NN 이유`).
